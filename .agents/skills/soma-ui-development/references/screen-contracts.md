# 页面契约

## 四个根页面

- 教练：对话和审查是主任务；历史可从左上角、左边缘手势和 VoiceOver 打开；输入框附近只放三个紧凑 Skill、加号、文本、麦克风和发送。
- 训练：进行中 Session → 我的计划 → 最近训练；没有进行中 Session 时不显示占位卡；计划与训练记录图标使用训练语义色，不使用无差别黑色。
- 进展：单张训练概览卡分段切换近 7 天、连续性与容量 → 一条可理解结论 → 最近六项混合活动（更多记录在卡内滚动） →
  体重趋势 → 数据与全部记录。最近活动标题旁用语义图标和短下划线直接进入训练记录、饮食记录。训练柱和连续性使用频率青，
  训练容量使用负荷橙，体重曲线使用身体蓝。每个指标显示专属 SF Symbol。
- 设置：个人与训练 → 服务 → 平铺低频入口（任务、后台、数据、隐私、高级）→ 显示 → 关于 → 反馈。不得用“更多”标题重复包裹这些入口；反馈直接嵌入最后。根设置项保留现有文字和 SF Symbol 形状，只按功能映射身体蓝、训练橙、智能紫、数据青、通知琥珀和后台绿；不统一染成黑白，也不增加彩色底块。「个人与训练」提供 Apple 健康只读连接（日活动三项与体重）；不提供写回或其他厂商直连。

四个 Tab 各自保留导航栈；换 Tab 不 pop。再点教练始终 no-op；训练、进展、设置只有当前处于详情页时再点才回根，已经在根页时 no-op。根标题全部使用 inline 模式。未选中图标使用 outline，选中项可使用 fill 和中性选中底。

## 高频与低频

- 一次点击可继续训练、进入当前计划、打开最新记录或发送反馈。
- 新建、开始、继续、编辑参数和保存是明确主操作；分享、AI 复盘、归档和调试下沉到上下文菜单或后部区块。业务版本历史不进入产品界面。
- 外观切换频率低，因此位于设置底部；反馈虽频率低但需要易发现，不进入关于或二级页。
- 浅色设置的每个 section 使用浅灰卡和明确组间距，根分区标题对齐卡片外沿；反馈输入使用 inset 表面和 1 pt 边界，不能只靠模糊阴影让页面融成一片。

## 聊天内容

- AI 回复使用开放阅读版式和 Subheadline Light，直接对齐消息区左边界，不设置重复头像或装饰列；用户消息使用紧凑的主题灰色气泡。
- 每条用户和 AI 消息都显示日期与时间；位置存在时与时间合并为一行。
- 处理中提示与完成时间共用消息左边界；AI 时间、执行日志与反馈图标的可见间隔相等，按钮触达仍不少于 44 pt。
- 逐回复反馈在当前消息下方原位展开；展开布局完成后自动平滑滚到该编辑器底部，投递成功后自动收起，失败保持展开并保留草稿；手动收起保持当前阅读位置。
- AI 只通过受控 Markdown 映射标题、段落、分隔线和列表；模型不能注入按钮、卡片或任意图标。

## 列表和详情

- 体重记录列表：导航标题「体重记录」使用 inline 小标题（非 large），避免大标题占位；返回按钮保留。导入/手动行共用统一图标容器尺寸与圆角；来源靠官方发行页图标或通用字形区分。Keep 使用 App Store 官方图标原色（不自绘仿制）；主行用简洁来源名，品牌归属见 `Soma/Resources/Brand/README.md`。页内一张合并趋势图：一周／一个月／三个月／一年选择（默认一个月，锚定真实现在）；共享所选时间域；图上体重与体脂各自按自然日取当天最后一次有效样本（不平均、不抹掉另一指标）；左轴 kg、右轴 %，单位各在轴顶端横向；体重身体蓝细实线、体脂对比色细虚线（低噪声小点，密集可减常驻点）；附图例（超大动态字号改为上下排布，不靠强行缩字）；网格用 separator；无指标切换；默认无选中浮层，点选用 SpatialTap（不拦截 List 纵向滚动；禁止用 minimumDistance 0 的 DragGesture 盖住图表）；点选后图内 inset 浮层（controlRadius）显示该代表样本真实单位与采样时间；无图下常驻读数；下方列表按自然日卡分组（与训练/饮食历史同层级）。健康导入的体重与体脂仅在同源（非空 bundle 相同，否则非空来源名相同）且采样时间同一秒时展示为一条同次测量，明细同时给出体重与体脂；不可仅因同日或同来源合并，不同秒、不同源保持单指标。健康导入（含组合行）只读，禁止编辑覆盖原始样本；删除或同步更新其中一个样本后，余下指标单独正确展示。持久化仍保留各 HealthKit UUID。超大字号行列改为上下布局：采样时间整行、来源整行、体重「N kg」足宽整行不拆小数；体脂率标签与「N%」可上下排但百分比本身不拆、不截断；禁止图标/体脂/体重/chevron 挤横排，不靠缩小字体；且须能滚到最后一条记录、末行完整高于浮动 Tab（可点开返回）；身体记录用户路径（列表、详情、新增/编辑、教练可见描述、进展身体指标切换）不展示也不再输入腰围；已存腰围字段保留但不进入界面；缺测不编造不插值；列表底部滚动边距对齐历史页并保证末行完整位于浮动 Tab 之上。
- 历史列表按业务需要提供月份或类型筛选，筛选 chip 不形成厚重实心栏。
- 删除使用系统 trailing swipe destructive action；训练页最近训练与计划详情最近执行记录同样左滑删除，不用长按菜单。主页最近六项与卡内滚动只承担快速回看，不承担完整管理功能。
- 详情进入即编辑，只有脏状态显示保存。聊天和详情必须共用同一记录草稿、缺失值和验证规则。
- 空态要给出下一步；加载失败保留已有内容并给重试；权限拒绝说明恢复路径。
- 计划动作行使用紧凑缩略图、Medium 动作名和最多两行处方；次数/时长混合时显式提示“混合次数与时长”，不自动改写计划。
- 计划动作的组间歇与换侧间歇在“动作设定”中各编辑一次；换侧间歇只对左右分开显示，独立组不重复间歇字段。
- 从计划进入动作详情时，首个业务区块为“本计划目标”；通用动作库入口不显示无来源的计划目标。
- 主要肌群、辅助肌群、动作提示、双面受力图和简短图例放在“标准动作”的同一个列表行；不得让
  `Form` 把 Divider、受力图或图例拆成空白行，也不得为受力图另开小节。
- 动作训练历史分成“训练概览”和“训练记录”：最近一次左对齐展示日期与压缩处方，容量卡只强调最近容量与较上次变化，图表使用负荷橙和真实记录日期，记录数量放在列表标题处。
- 计划训练效果总览分别列出主要与辅助肌群；主要/辅助身份来自动作库事实，目标组数只缩放受力图强度。

## 文案

- 结论先行，一句依据足够。避免内部置信度、Agent 实现细节和诊断式健康结论。
- 不显示“已保存”“仅最新回复可编辑”等可由勾选或锁图标表达的冗余状态文字。
- 使用用户术语，不暴露枚举原值、UUID、Tool 名称或原始 JSON。
