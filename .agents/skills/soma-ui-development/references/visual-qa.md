# Soma 视觉 QA

## 证据矩阵

每个受影响主流程至少检查：

- 标准 iPhone 的浅色和深色。
- 小屏 iPhone 的标题、长中文、键盘、滚动与底部安全区。
- iPad portrait 的内容宽度和留白。
- 带练额外检查 landscape、相机画面、暂停、休息和失败恢复。
- 默认字号和一个 Accessibility Dynamic Type；VoiceOver 标签、顺序和自定义操作。

测试和截图只使用虚构数据及 `Soma/Resources/DemoMedia`。

## 与设计稿比较

1. 使用相同主题、视口、数据和交互状态分别打开设计稿与实现截图。
2. 把两者组合在同一比较图或同一次视觉输入中，不凭代码或记忆判断。
3. 明确检查 Subheadline Light 是否真实生效、用户气泡是否保持主题灰、未选中 Tab 是否线框、Composer 是否只有四项、设置分组是否与页面分离，以及间距、语义色、图标质量、文案和状态。
4. P0/P1/P2 必须修复并重新截图；P3 可留下明确的后续打磨记录。

产品级重构在根目录维护 `design-qa.md`，记录：来源路径、实施截图路径、像素和视口、状态、完整与局部比较、每轮问题/修复、交互与控制台检查、最终 `passed` 或 `blocked`。

## 交互检查

- 四 Tab 切换保留各自导航；教练和任一根页再选 no-op，训练、进展、设置详情页再选回根。
- 未选中 Tab 为线框；选中 Tab 为中性强调，不依赖彩色品牌 tint。
- 主题切换不丢当前导航、草稿或训练进度。
- 每条消息显示日期时间；加号、文本、麦克风和发送均可访问，三个 Skill 的触达不小于 44 pt。
- 聊天卡保存、锁定、删除、添加/复制/删除逻辑组。
- 历史左滑删除、详情脏状态保存、空态和可恢复错误。
- 带练开始、说明、倒计时、左右换侧、组间休息、暂停、完成与相机异常。

## 工程门禁

视觉通过不替代构建和测试。完成前运行 `make format`、`make check`、`make verify`，并把真机才能确认的相机、签名或权限场景单独列为待验收，而不是把模拟器结果当成真机证据。
