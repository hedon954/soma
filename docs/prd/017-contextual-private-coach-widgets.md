# PRD 017：情境化私人教练主屏组件

- 状态：已实现，待真机验收
- 日期：2026-08-04
- 修订自：[PRD 004](004-soma-current-product.md) 的“主屏幕、锁屏组件与系统快捷入口”范围
- 后续修订：暂无
- 上游依据：[私人健身教练的情境化主屏组件调研](../research/2026-08-04-contextual-private-coach-widgets.md)、[ADR 0042](../adr/0042-contextual-widget-snapshot-and-privacy.md)
- 关联决策：[ADR 0013](../adr/0013-widget-and-app-intent-capture-routing.md)、[ADR 0042](../adr/0042-contextual-widget-snapshot-and-privacy.md)

## 背景

当前 Soma 主屏 Widget 是一个中尺寸的“快速记录”面板，只提供文字、拍照、照片/视频三个按钮。
它不读取任何用户状态，因而无法告诉用户是否有未结束带练、应该恢复哪一个计划，或最近训练是否已
中断。作为私人健身教练，这使组件只减少了录入摩擦，没有减少“从想训练到开始训练”的摩擦。

训练计划和带练已经是一级“训练”Tab，正在训练的逐组状态也已经有专属 Live Activity。新的主屏
组件应补足两者之间的空白：在不打开 App 的瞬间展示最相关的下一步，并把用户一次点击带到正确位置。

## 用户结果

- 正在带练时，用户在主屏一眼看到“继续带练”，点击即回到同一 Session，而不是从首页重新找计划。
- 未在带练但已选择常用计划时，用户能从组件进入该计划的开始前确认，避免层层进入计划库。
- 没有计划或不想按计划训练时，用户仍可从组件进入训练页或快速记录，不被强制创建计划。
- 用户可决定组件显示的训练详情程度；锁屏和其他高暴露系统表面不泄露动作、重量、身体、饮食或媒体。
- Widget 未拿到新数据、应用空间切换、设备锁定或刷新延迟时，组件清楚说明可做的下一步，不展示陈旧
  或伪实时的训练状态。

## 产品规则

### 组件组合

1. 新增小尺寸「训练节奏」：展示一个用户可理解的连续性摘要（例如“本周 2 次”或“距上次训练 3 天”）
   和一个进入训练 Tab 的点击目标。
2. 将现有中尺寸入口升级为「Soma 今日训练」：以“当前情境 + 下一步”为单一任务；最多一个主操作、
   两个辅助入口。原文字、拍照、照片/视频入口保留为“快速记录”显示模式，不能消失。
3. 新增大尺寸「本周训练」：展示本周概览、固定计划入口与最近训练；不展示完整趋势、媒体墙或多个
   可并列执行的计划。
4. 锁屏继续提供无训练事实的文字、拍照、照片/视频入口；可新增通用“打开训练”入口，但不显示
   计划、动作、重量、体重、饮食、视频或 AI 建议。
5. 训练正在进行时，Live Activity 仍负责活动中的状态；主屏 Widget 只展示可恢复的摘要，不能显示
   秒级休息倒计时、相机画面或录像状态。

### 自动显示优先级

组件默认使用“自动”模式，按以下顺序决定内容：

1. 有未结束的带练 Session：显示“继续带练”，进入该 Session；若用户已开启训练详情，可补充计划名和
   已完成组数。
2. 无 Session 但组件配置了固定计划：显示“准备开始”，点击进入该计划详情的就绪确认；仅在训练详情
   下显示计划名。
3. 无 Session 且无固定计划、但有训练历史：显示本周次数或距上次训练天数，主操作为“打开训练”，
   辅助操作可为“记录训练”。
4. 无可用训练历史：显示“开始你的第一条训练记录”，进入教练文字输入或训练 Tab；不推断目标、动作或
   容量。

用户可在 App 的“主屏组件”设置中选择“自动、固定计划、训练节奏、快速记录”之一。即使选择非自动模式，进行中的
Session 仍可以覆盖为“继续带练”，防止用户中断后失去恢复入口。

### 隐私配置

组件提供三个显示级别，默认“私密”：

| 级别 | 允许内容 |
| --- | --- |
| 私密（默认） | 通用训练状态、进入训练/记录入口；不显示任何训练事实 |
| 概览 | 本周训练次数、已完成组数、距上次训练的相对天数 |
| 训练详情 | 仅主屏显示计划名、动作名和处方摘要；仍不显示体重、饮食、健康备注、媒体、相机画面或 AI 分析 |

- 用户在 App 的“主屏组件”设置中选择显示模式、隐私级别和固定计划。关闭训练详情即刻降级所有主屏
  组件到私密模式。
- 锁屏、StandBy、CarPlay、Dynamic Island 和 Live Activity 固定为私密模式。设备未解锁、快照不可读或
  个人数据空间不可用时，也使用私密占位态。
- 演示/个人空间切换、清除个人数据、计划/Session 删除后不得残留前一空间的组件内容。

### 路由与行为边界

- 可见的主操作必须深链接到其语义对应的页面：继续带练到 Session、固定计划到该计划的就绪确认、
  训练节奏到训练 Tab、快速记录到现有 `soma://capture/*` 路由。
- Widget 不直接创建/完成训练、修改计划、调用 Agent、录制媒体或写入 SwiftData；所有会改变训练事实
  的操作仍在 App 内经用户确认和既有确定性状态机执行。
- 组件不承诺秒级更新。App 在相关事实变化与日期边界时请求 WidgetKit 刷新；未刷新时必须以最后更新时间
  或通用“打开 Soma 更新”处理，不能把旧状态描述为当前状态。

## 数据与隐私

ADR 0042 已部分替代 ADR 0013 中“不引入 App Group”的限制，并明确最小共享投影：

- 主 App 唯一负责从 SwiftData 读取并生成按数据空间隔离的 `WidgetSnapshot`；Widget Extension 只读。
- Snapshot 只包含渲染当前组件和路由所需的派生字段、版本、生成时间、隐私配置和内部路由标识；不包含
  原始聊天、完整训练史、照片/视频、健康样本、位置、API Key 或 AI Trace。
- 写入必须原子化；删除、空间切换和隐私降级先写入空/降级 Snapshot，再请求对应组件刷新。
- Snapshot 保存在本机 App Group 容器，不上传 Soma Server、模型 Provider 或第三方；删除 App 或清除个人
  数据时随本地数据一并移除。
- 为支持可配置 Widget，配置参数仅用于本机显示和路由；固定计划失效、归档或被删除时回退到自动模式，
  不保留已删除计划文字。

## 明确不在范围

- Widget 内实时相机预览、动作识别、动作计数、录像和视频复盘。
- Widget 内启动后自动创建 Session、直接“完成本组”或写入训练记录。
- 每日由 AI 生成训练建议、推送到 Widget，或为此消耗模型 Token。
- 根据自然语言排期猜测“今天练什么”；在未新增结构化排期模型前，只支持用户明确固定的计划。
- 锁屏、StandBy、CarPlay、Live Activity 上展示私人训练详情。
- 账户、云端同步、远程业务数据投影或服务端刷新依赖。

## 验收

- 小/中/大组件各自只有一个明确主要目的，且小组件不只是中组件的缩放版。
- 自动模式按“进行中 Session → 固定计划 → 训练历史 → 首次使用”稳定选择内容；所有空态、失效固定计划
  与数据空间切换都有可理解的回退。
- 主屏每个主点击目标直达正确 Session、计划就绪确认、训练 Tab 或现有记录入口；不落到无关首页。
- 关闭组件详情或进入锁屏/StandBy/CarPlay/Live Activity 后，动作、重量、次数、计划名、体重、饮食、
  媒体和 AI 内容均不可见。
- App 不在运行时，Widget 仍能读取最后一份有效快照并诚实呈现更新时间；快照不可读或设备尚未解锁时
  显示私密占位态，不崩溃、不展示旧空间内容。
- 计划、Session、训练记录、隐私设置、数据空间与日期周界变化后，WidgetKit 刷新请求被合并；组件不依赖
  高频刷新实现计时或实时录像状态。
- VoiceOver 可读出当前情境和主要操作；Dynamic Type、浅深色、组件着色、StandBy 和无数据态均通过
  模拟器检查，主屏/锁屏隐私与深链接在真机手工验收。
