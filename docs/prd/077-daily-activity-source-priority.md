# PRD 077：日常活动多来源优先级与独立列表

- 状态：提议
- 日期：2026-11-05
- 修订自：[PRD 075](075-healthkit-daily-activity.md)（单通道 Apple 健康日汇总混入训练列表）、[工程契约](../../CLAUDE.md)（外部导入与可替换边界）
- 上游依据：[多来源调研](../research/2026-11-05-daily-activity-source-priority.md)
- 下游落地：[ADR 0146](../adr/0146-daily-activity-source-priority.md)
- 后续修订：暂无

## 背景

连接 Apple 健康后，每日步数、步跑距离与活动消耗已形成「日常活动」记录，但事实通道只有 HealthKit 系统合并值。COROS 写入健康库后可按来源单独摘出，但系统「今日汇总」不一定优先 COROS；日常活动还出现在训练记录列表，并会进入按日分享海报，用户并不想分享步数项。

## 用户结果

- 用户只连接并授权 **Apple 健康**一次；不出现 COROS OAuth、MCP、Client ID 或任何厂商开发者配置。
- 在设置「日活动数据源」中选择来源（每项前带对应 logo / icon，见下）：**Apple** 始终可选；**COROS** 仅当 Apple 健康库中已存在 COROS 来源的日活动样本时才显示；**步数更大**始终可选（有 COROS 样本时可与 COROS/Apple 整包比较）。**默认 = Apple**（跟系统汇总）；用户有 COROS 数据时可改选 COROS 或步数更大。
- 每个自然日仍只有一条日常活动事实；展示的步数、距离、卡路里始终来自同一获胜来源，并带来源图标。
- 训练记录列表不再出现日常活动；进展「日」用独立「日常活动」区块展示当日步数等；另有单独入口查看每日步数历史（行内带来源图标）。
- 按日或训练分享海报自动排除日常活动，只聚合真实训练记录。

空态：未连接 Apple 健康时不生成记录。失败态：某一候选快照失败不清除已成功落盘的整包；部分指标失败不向其他来源借数填齐。

产品预期：今日数据可能略旧（表 → COROS App → 健康库的链路不在 Soma 控制内）。多数时候不必为查看 Soma 专门打开 COROS；不承诺打开 Soma 即实时到这一分钟。

## 产品规则

- 继续只关心三项日汇总：步数、步行与跑步距离、活动消耗；不读静息能量。
- 一天一条记录；覆盖规则沿用 PRD 075（较小值、0、空结果可覆盖；失败项不覆盖；三项皆空删除）。
- **数据通道仅 HealthKit**。COROS 选项 = 读取健康库中 `source` / bundle 属于 COROS 的样本并组成整包；**不是** COROS MCP / 云端 API。本需求不做 COROS MCP（含「可选连接」），也不做 Partner API。
- 设置项文案：**日活动数据源**。概念上仍是三选一，但 **COROS 行按有无数据动态出现**：

  | 选项 | 何时显示 | 含义 | 选项前 icon |
  | --- | --- | --- | --- |
  | Apple | 已授权 Apple 健康后始终显示 | 跟 Apple 健康系统汇总 / 内部择优走；Soma 不再重选来源 | Apple 健康（或 Apple）logo |
  | COROS | **仅当**健康库中已能识别到来源为 COROS 的日活动样本（步数/距离/卡路里任一相关窗口内有 COROS `HKSource`，判定细节见 ADR）时显示；否则整行隐藏，避免「没有 COROS 还摆 COROS」 | 只取 HealthKit 中来源为 COROS 的样本，组成当日整包（步数+距离+卡路里） | COROS 官方 logo |
  | 步数更大 | 已授权后始终显示 | 在可用整包（有 COROS 时含 COROS 整包 vs Apple 汇总等，见 ADR）之间比较步数，取步数更大的整包；无 COROS 时等价于仅 Apple 汇总 | 明确表示「更大 / 择优」的图标（如 gauge 或向上箭头），勿与 COROS/Apple 品牌混淆 |

- **默认策略 = `apple`**（Hedon 锁定）。不因后来出现 COROS 样本而自动改默认；用户若曾选 `coros`，之后 COROS 样本消失导致选项隐藏时，按 ADR 回退到 `apple` 并持久化（或等价：隐藏后读取时按 `apple` 行为，见 ADR）。
- **整包一致性**：一旦选定来源/策略，距离与卡路里必须同包，禁止跨来源混拼。
- **COROS 缺包回退**：选 COROS 但当日 COROS 整包不完整（缺步数，或三项中无法形成可用快照）时，按 ADR 回退到 Apple 健康汇总（或策略规定的下一候选），不跨源拼数；UI 用来源图标如实反映最终采用的来源。
- **步数更大**：只比较完整（或按 ADR 定义的可用）整包的步数；平手时用稳定次序打破平局；仍整包采用，不混拼。
- 仅连接 Apple 健康、健康库内尚无 COROS 样本时：设置页不出现 COROS 选项；默认与可选均为 Apple / 步数更大。
- 演示空间只用虚构数据与演示来源名，不访问真实 HealthKit。
- 断开 Apple 健康：停止读取；已落盘日常活动保留，直至被新同步覆盖或用户清空个人数据。

## 数据与隐私

- 日常活动仍落在个人库 `WorkoutEntry`（或等价本地模型），不进应用备份/导出、模型上下文、Server、Widget、日志与反馈自动上下文。
- 不新增 COROS 令牌、OAuth 或远程轮询；不增加健康写回、后台 Delivery、账户系统。

## 明确不在范围

- COROS MCP、COROS OAuth、「连接 COROS」设置入口、Partner API、webhook、GPX、向 COROS 写回。
- 心率、睡眠、压力等扩展健康指标。
- 把日常活动重新做成进展首页大卡片仪表盘（独立列表即可）。
- 为「可能的未来厂商」预建可插拔插件市场；只保留读取协议与来源枚举扩展点。
- 远程叫醒 COROS App / 手表蓝牙同步（第三方做不到）。

## 验收

- 设置「日活动数据源」：有 COROS 样本时最多三选项，无 COROS 样本时仅 Apple / 步数更大；每个可见选项前有对应 logo/icon；固定夹具下整包结果可预测，混拼用例失败。
- 默认策略为 Apple；切到 COROS（选项可见时）则用 COROS 整包；步数更大在夹具下可预测。
- 无 COROS 样本时设置页不出现 COROS 行；曾选 COROS 后样本消失时行为符合 ADR（回退 Apple）。
- COROS 整包缺项当日回退行为符合 ADR，且不出现跨源拼数。
- 训练历史与按日分享不含日常活动；独立列表含三项与来源图标。
- 用户路径仅 Apple 健康授权；无 COROS 登录/OAuth UI。
- 旧 `appleHealth` + `daily:` 记录仍可识别为日常活动并迁移到新识别规则。
- 隐私过滤与空间隔离保持；`make verify` 通过；真机分来源对照另记，不入库真实截图数值。
