# PRD 077：日常活动多来源优先级与独立列表

- 状态：提议
- 日期：2026-11-05
- 修订自：[PRD 075](075-healthkit-daily-activity.md)（单通道 Apple 健康日汇总混入训练列表）、[工程契约](../../CLAUDE.md)（外部导入与可替换边界）
- 上游依据：[多来源调研](../research/2026-11-05-daily-activity-source-priority.md)
- 关联决策：[ADR 0146](../adr/0146-daily-activity-source-priority.md)
- 后续修订：暂无

## 背景

连接 Apple 健康后，每日步数、步跑距离与活动消耗已形成「日常活动」记录，但事实通道只有 HealthKit 系统合并值。COROS 需先写入健康库，存在同步延迟，且系统不一定优先 COROS 的步数与卡路里。日常活动还出现在训练记录列表，并会进入按日分享海报，用户并不想分享步数项。

## 用户结果

- 在设置里连接 Apple 健康，并可选择连接 COROS（直连）；可设置第三方日常活动优先级：优先 COROS、优先 Apple 健康，或「步数更大者」。
- 每个自然日仍只有一条日常活动事实；展示的步数、距离、卡路里始终来自同一获胜来源，并带来源图标。
- 训练记录列表不再出现日常活动；单独入口查看每日步数历史。
- 按日或训练分享海报自动排除日常活动，只聚合真实训练记录。

空态：未连接任何来源时不生成记录。失败态：某一来源失败不清除另一来源已成功的整包快照；部分指标失败不向其他来源借数填齐。

## 产品规则

- 继续只关心三项日汇总：步数、步行与跑步距离、活动消耗；不读静息能量。
- 一天一条记录；覆盖规则沿用 PRD 075（较小值、0、空结果可覆盖；失败项不覆盖；三项皆空删除）。
- **整包一致性**：择优比较以步数为键（「优先某来源」则先看该来源是否有可用快照）；一旦选定来源，距离与卡路里必须同包，禁止跨来源混拼。
- 来源图标：至少区分 COROS、Apple 健康；未知来源用中性标识，不猜测厂商。
- 默认优先级提议为「步数更大者」；用户可改。仅连接单一来源时该来源即结果。
- COROS 直连采用用户授权的自助 MCP OAuth；不在本需求申请 Partner API。未直连时仍可从 HealthKit 分来源统计中识别 COROS 写入样本。
- 演示空间只用虚构数据与演示来源名，不访问真实 HealthKit / COROS。
- 断开某一来源：停止该来源读取；已落盘日常活动保留，直至被新同步覆盖或用户清空个人数据。

## 数据与隐私

- 日常活动仍落在个人库 `WorkoutEntry`（或等价本地模型），不进应用备份/导出、模型上下文、Server、Widget、日志与反馈自动上下文。
- COROS 刷新令牌存 Keychain（ThisDeviceOnly）；授权与轮询是明确远程数据流，须在实现 PR 写明触发、载荷最小化、失败与撤销。
- 不增加健康写回、后台 Delivery、账户系统。

## 明确不在范围

- Partner API、webhook、GPX、向 COROS 写回训练计划。
- 心率、睡眠、压力等扩展健康指标。
- 把日常活动重新做成进展首页大卡片仪表盘（独立列表即可）。
- 为「可能的未来厂商」预建可插拔插件市场；只保留读取协议与来源枚举扩展点。

## 验收

- 设置可切换三种优先级；固定夹具下整包结果可预测，混拼用例失败。
- 训练历史与按日分享不含日常活动；独立列表含三项与来源图标。
- 旧 `appleHealth` + `daily:` 记录仍可识别为日常活动并迁移到新识别规则。
- 隐私过滤与空间隔离保持；`make verify` 通过；真机 COROS / 健康延迟对照另记，不入库真实截图数值。
