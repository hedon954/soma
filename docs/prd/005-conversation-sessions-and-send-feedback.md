# PRD 005：对话 Session 与发送反馈

- 状态：已采纳
- 日期：2026-07-30
- 关联基线：[PRD 004](004-soma-current-product.md)
- 关联决策：[ADR 0015](../adr/0015-daily-conversation-session-lifecycle.md)

## 背景

当前教练页把所有历史消息放在同一条无限对话里。跨天重新进入 App 时，旧上下文仍直接
延续，既不符合用户对一次谈话边界的理解，也会让 Agent 的最近对话摘要混入上一天内容。

发送文字、图片或视频后，输入焦点和页面位置也需要立即进入“消息已发出、等待回复”的
状态。开发者设置已有提示词和 Skills，但执行日志入口位于旧的信息架构残留中，用户进入
开发者设置后反而找不到诊断入口；只读的内置工具协议同时占据了一行不可操作的界面。

## 用户结果

1. 每次重新进入前台时，Soma 检查最新一条消息：
   - 最新消息发生在今天：继续使用这条消息所属的当天 Session；
   - 最新消息早于今天，或尚无消息：自动进入今天的新 Session；
   - 今天已经创建了尚未发送消息的空 Session 时复用它，不重复制造空会话。
2. 教练主页面只展示当前 Session，最近对话上下文也只从当前 Session 提取。
3. 历史 Session 保留在本机，并可从教练页进入只读会话记录查看。
4. 发送文字、图片或视频被接受后：
   - 停止语音输入；
   - 清空草稿与待发送附件；
   - 收起键盘；
   - IM 页面滚到稳定的底部锚点；
   - 保持在底部展示用户消息、Agent 执行卡和等待状态，直到回复完成或失败。
5. 开发者设置直接提供“执行日志”入口和当前数据空间内的日志数量。
6. “内置工具协议”及其只读说明不再出现在开发者设置中。工具名称、描述和参数 Schema
   仍然由 Runtime 固定，不因此变成可配置项。

## Session 规则

- Session 是当前数据空间内的本地持久化对象，演示与个人空间继续完全隔离。
- 日期边界使用设备当前日历与时区的自然日，不使用固定 24 小时窗口。
- Session 的标题取第一条用户消息的简短单行摘要；只有媒体时使用媒体摘要。
- 每条用户消息及其 Agent 回复共享同一个 `sessionID`；一条用户消息仍只对应一条 Trace。
- 旧版本没有 `sessionID` 的消息首次加载时按自然日归档，不能删除或隐藏。
- App 一直停留在前台跨过午夜时不强制中断正在进行的谈话；下一次进入前台再执行分流。

## 状态与失败

- 空 Session 展示现有对话引导，不伪造欢迎消息。
- 媒体保存或 Agent 失败时，已接受的本地消息、附件和成功 Tool 写入继续保留。
- App 被系统终止时仍不承诺后台继续运行 Agent；该边界沿用 ADR 0008。
- Session 分流失败不得阻止用户进入教练页；发送前再次确保存在当前 Session。

## 隐私与数据

- Session、消息和 Trace 只保存在当前 SwiftData 数据空间。
- Session 标题只来自用户已发送的本地消息，不额外调用远程模型生成。
- 历史列表不展示媒体原图、API Key、Authorization 头或完整 Trace 参数。
- 本需求不引入账户、云同步、后台服务或新的远程数据流。

## 验收

- 构造昨天的最后消息，重新进入前台后看到空的新 Session；再次进入前台不会再新增空
  Session。
- 构造今天的最后消息，重新进入前台后继续显示同一 Session。
- 旧消息没有 `sessionID` 时按自然日归档，历史会话仍可查看。
- 连续发送文字、图片和视频时，键盘收起、输入区清空、页面保持在底部，Agent 回复流式
  追加。
- 开发者设置内可以进入执行日志；页面不再出现“内置工具协议”及其说明。
- `make verify` 通过，并在 iPhone 尺寸模拟器检查浅色、深色、键盘、滚动和安全区。
