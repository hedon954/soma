## 背景

七项要求来自维护者连续使用后的真实反馈，可以归成三类：

1. **聊天信息层级**：消息看不出什么时候发的，位置占一个独立胶囊；当前 Session 的记录日期入口
   压在输入框上方，抢走本来就紧张的输入区。
2. **能力配置**：输入框上方有六个内置快捷按钮，设置页却只能排序，不能新增、改名、删除或换绑；
   工具权限挂在 Skill 上，用户想让某个场景多用或少用一个工具时无处可改。
3. **可靠性与可解释性**：流式回复期间频繁闪退，事后没有任何可读证据；带练录像仍然失败并且只
   说「系统提前结束了录像」；模型在聊天里声称自己没有饮食写入工具，日志里查不到那一轮到底
   注册了哪些工具。

饮食分析的呈现也不符合要求：现在只有一张汇总卡，用户要改一道菜必须跳进详情页。

## 用户结果

1. 每条用户消息和教练回复底部有一行时间；开启位置且该消息带位置时，同一行显示「时间 · 位置」，
   长 POI 名中间截断，不再出现独立的绿色位置胶囊。当天只显示时刻，跨天补日期，跨年补年份。
2. 当前 Session 的记录日期入口移到导航栏「Soma」下方居中；点开仍是同一个日历选择器，输入区
   完全归还给输入和快捷按钮。
3. 用户可以在设置里新增、改名、换图标、换绑 Skill、删除、拖动排序快捷按钮，并单独控制每个按钮
   是否出现在聊天输入区；先配置好、暂时不显示是允许的。
4. 每个快捷按钮持有自己的工具白名单，默认全选，用户可按分组删减。用户也可以让 AI 读这个按钮
   绑定的 Skill 内容推荐一份工具清单并给出理由，一键采纳。
5. 默认只内置「饮食分析」、「训练记录」、「近期分析」三个可见按钮；其余内置 Skill 仍在设置页里，
   只是默认不占用聊天输入区。
6. 流式回复不再闪退。若上次运行确实崩溃过，下次启动会静默整理一份诊断报告发送到内置反馈邮箱；
   高级设置提供总开关和「查看上次报告」。
7. 带练录像失败时给出具体原因，而不是一句「系统提前结束了录像」。原因区分存储不足、被其它 App
   占用、来电或系统压力中断、录像期间配置被改动等，并带可检索的技术标识。
8. 饮食结果在聊天里是两张卡：第一张「记饮食」是一份可直接改的菜品清单，每行是图标、菜名、热量、
   份量与三大宏量，支持增删行与改餐次；第二张「饮食评价」只读，随第一张卡实时重算，缺项显示未估算
   而不是 0。
9. 记录卡跟在产生它的那一步后面，写入前后的文字保持原顺序，聊天读起来是「一句说明 → 卡片 →
   一段评价」，而不是文字读完才在末尾看到一堆卡片。
10. 饮食记录的时间是钟点而不是当天零点；餐次按这条记录真正发生的时刻推断，夜里补记昨天午餐不会
    被标成夜宵。

## 产品规则

### 快捷按钮与工具

- 快捷按钮是可完整增删改的实体：名称、图标、绑定 Skill（可为空）、工具白名单、是否显示、排序。
- 工具曝光边界由快捷按钮持有。Skill 只提供专业方法，不再声明工具权限。
- 未选任何快捷按钮时本轮全量曝光当前协议工具；选中某个按钮时只曝光该按钮勾选的工具。
- 快捷按钮不能扩权到当前协议之外；未知工具名在保存与运行时都被丢弃。
- AI 推荐只在用户点按时触发一次，优先小模型档，只发送按钮名称、Skill 正文与工具目录，不含健康数据。
- 聊天输入区最多显示六个按钮；隐藏的按钮不参与曝光判断。

### 诊断与崩溃上报

- 崩溃诊断默认自动发送，可在高级设置一键关闭，并可丢弃排队中的报告。当前只有维护者本人使用，
  报告尽可能完整；对外分发前必须先补一次性明确授权。
- 只有真实运行才产生崩溃证据：跑单测（宿主 App 被测试进程杀掉）和 Xcode 附着调试器结束进程都
  不算崩溃，不置位哨兵也不发信。
- 报告包含设备与版本、崩溃类型与堆栈、最近诊断日志尾部、崩溃时所在 Session 的消息与最后一次
  Agent Job/Trace 摘要（含该轮工具清单）。
- 诊断日志与报告都不写 API Key、Authorization 头或媒体 Base64。
- 发送失败留盘并在下次启动重试，最多保留 5 份。
- 每次模型调用都记录本轮注册的工具名和数量，落到 Trace metadata 与诊断日志，并在执行日志可见。

### 饮食呈现与时间

- 记录卡按 `record_refs` 插在产生它的那一步之后；同一条记录一个 Turn 内只出一张卡，无法归位的
  引用兜底放在末尾。
- 饮食 Skill 在写入前先用一句话说明识别结果且不复述数字，让卡片承担数据、文字承担解释。
- 菜品拆解是事实来源，汇总是纯派生；两处共用同一条求和规则。
- 任一菜品缺某个字段时该项汇总保持为空，不补零。
- 用户没有明确说时间时省略 `occurred_at`，由 App 使用发送时刻的钟点；显式改期只改日期部分，
  钟点跟随发送时刻。

## 数据与隐私

- 快捷按钮存 UserDefaults JSON，不进入 SwiftData schema，也不离开设备。
- `AgentJob` 新增可选 `selectedShortcutID`，让排队与恢复沿用同一曝光边界。
- 崩溃诊断是新增的自动出网数据流：触发条件是「上次运行异常结束且开关打开」，内容是上面列出的
  报告，投递复用现有反馈 SMTP 链路，失败留盘重试，报告发送后删除。
- 业务记录仍只在设备上；诊断日志滚动覆盖，不做长期归档。

## 明确不在范围

- 不给 Skill 恢复工具绑定，也不允许 Skill Markdown 声明任意工具。
- 不为快捷按钮增加自动触发、定时或后台执行能力；仍由用户点按并发送。
- 不把崩溃诊断变成第三方 SDK 或远程日志服务。
- 不新增饮食识别模型能力，双卡片只改呈现与编辑边界。

## 验收

- 消息元信息行的当天、跨天、跨年与带位置格式由单测覆盖，助手消息不显示位置。
- 导航栏日期入口在浅色/深色、Dynamic Type 与长日期下不挤压标题。
- 快捷按钮增删改排序与显示开关落盘可复现；默认三个可见按钮为饮食分析、训练记录、近期分析。
- 选中按钮时曝光集合等于该按钮工具白名单；未选时等于当前协议全量。
- 每次模型调用的工具清单出现在执行日志与诊断日志。
- 录像失败提示包含具体原因与技术标识，且录像进行中不再改写视频连接。
- 饮食双卡片编辑后保存，汇总与本机记录数值一致；缺项显示未估算。
- 记录卡出现在产生它的步骤之后，重复引用只渲染一张卡，由确定性单测覆盖顺序与去重。
- `make check`、`make verify` 通过；带练录像与崩溃上报补真机手工验收。
