## 背景

训练记录、饮食和体态是一次发生的自然事实，聊天可以显著降低录入摩擦。训练计划不同：它是
用户主动编排的结构化处方，需要反复比较动作、调整顺序并配置组数、次数、重量、间歇和热身组。
只允许聊天创建会让用户无法直接看见整体结构，也会把本可确定完成的选择交给模型解释。

现有 GUI 已能审查和创建计划的新模板版本，但无法从计划列表直接创建第一版计划。用户必须先
经聊天生成计划，才能使用更适合编排的 GUI。

## 用户结果

1. 用户可以继续在教练中自然描述目标，由 Agent 创建或调整计划。
2. 用户也可以从“进展 → 训练计划”主动新建计划，从个人动作库选择动作并组合。
3. 用户可以调整动作顺序、移除动作，并为每个动作填写可选处方和首组热身标记。
4. 保存后立即得到可审查、可编辑、可启动的版本化训练计划，不需要调用模型或联网。
5. 动作库为空时展示原因和返回教练形成动作的引导，不暴露包内尚未激活的动作目录。

## 产品规则

- 训练计划列表提供系统风格的“新建训练计划”入口，不新增顶层 Tab。
- GUI 只选择当前数据空间中未归档的 `ExerciseDefinition`；稳定 ID 是保存引用，名称只用于展示。
- 未被用户实际形成的包内动作仍保持静默，不能因打开计划创建器而进入动作库。
- 计划名称必填，目标与安排提示可选；计划至少包含一个动作。
- 动作可重复添加、排序和删除；每一行可配置组数、次数、重量、间歇和“第 1 组是热身组”。
- 用户没有填写的处方值保持 `nil`，GUI 不预填所谓常见值，也不自动请求 AI 建议。
- 首次保存调用共享 `TrainingPlanStore.createProgram` 创建 Program 与模板版本 1；后续编辑继续
  通过 `createNextVersion` 生成不可变新版本。
- GUI 与 Agent 创建的计划使用同一数据模型、验证规则、就绪检查、备份、导出和删除边界。
- 保存失败留在编辑页并显示可恢复原因；不得产生没有当前版本的半成品 Program。

## 数据与隐私

- 新建计划、动作引用和处方全部保存在当前本地 SwiftData 空间。
- 打开、编辑和保存 GUI 计划不调用模型，不上传动作名称、训练历史或处方。
- 演示与个人空间继续隔离；切换空间后只显示该空间的动作和计划。
- 计划仍进入现有开放导出、加密备份、恢复和个人数据清除范围，无新增迁移模型。

## 明确不在范围

- 在计划创建器内新建、搜索包内未激活动作或合并动作；
- 为处方自动补齐推荐重量、次数、组数或间歇；
- 改变 Session 快照、带练状态机或自动录像规则；
- 新增课程商城、日历排期、顶层训练 Tab 或服务器计划数据库。

## 验收

- 计划列表和空态都能进入新建页；取消不会产生 Program 或模板版本。
- 从当前动作库选择至少两个动作后，可以排序、删除并保存。
- 保存后 Program 指向版本 1，处方顺序连续且使用对应动作稳定 ID。
- 空白组数、次数、重量和间歇保存为 `nil`；无效范围显示现有确定性错误。
- 动作库为空或全部归档时无法保存，并明确引导先形成动作。
- 保存不触发 Agent Job、网络请求或 AI 消耗。
- 新计划可继续编辑产生版本 2；已开始 Session 的版本 1 快照保持不变。
- VoiceOver、Dynamic Type、键盘遮挡、长动作名称、浅色和深色模式通过模拟器验收。
