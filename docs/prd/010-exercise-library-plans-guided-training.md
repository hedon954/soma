## 背景

训练、饮食、身体和健身房都可以由聊天持续产生新记录，但动作会在一个有限集合中反复出现。
当前 `WorkoutEntry.exercise` 只有名称字符串，同一动作可能因错别字、简称和不同表达割裂历史；
用户也需要反复输入动作、组数、次数、重量和间歇。

稳定动作身份可以同时支撑单动作历史、聊天快捷输入、训练计划、程序化带练和视频复盘。该能力
必须继续遵守聊天优先：用户不需要先维护动作数据库，Agent 在自然交互中逐步形成个人动作库。

## 用户结果

1. 用户继续直接描述训练，Agent 自动复用已有动作或创建新的标准动作。
2. 每个动作按稳定 ID 汇聚训练历史、最近一次训练值、媒体和反馈。
3. 用户在输入框输入部分动作名称时，可以选择已有动作并一键补入最近一条训练记录。
4. 用户可以通过聊天创建和调整训练计划，在 GUI 中审查、排序、替换动作和启动训练。
5. 带练流程根据固定计划快照完成动作、组间休息、暂停、跳过和实际值记录，不依赖在线模型。
6. 用户为本次训练开启自动录像后，每个动作自动录制一组；用户可以暂停、取消、重录或删除。
7. 训练完成后先生成本地确定性总结，只有用户主动请求时才进行 AI 建议或视频复盘。

## 产品规则

### 动作身份

- 每个动作是当前数据空间中的 `ExerciseDefinition`，拥有稳定 `id` 和可编辑标准名称。
- Agent 在 `record_workout` 前调用固定 Tool `list_exercise_names`。
- `list_exercise_names` 返回当前数据空间全部已有动作的 `{ id, name }`；名称只是展示和语义
  选择依据，写入引用必须使用 ID。
- 语义归一由大模型完成，不再建立本地字符串规则与大模型投票机制。
- 错别字、漏字、简称或真正同义时复用已有 ID；器械、角度、单双侧或动作模式存在实质差异时
  使用不同动作。
- 没有语义等价动作时，Agent 生成清晰标准名称，本地创建动作并返回稳定 ID。
- 用户可以改名、归档、合并动作并撤销最近一次错误合并；历史引用不得因改名而改变。

### 单动作历史与聊天快捷输入

- 动作详情按 ID 展示全部历史、趋势、媒体、个人笔记与分析。
- 用户在聊天输入框键入内容时，只在本地标准名称中匹配，不调用远程模型。
- 选择动作后把标准名称写入草稿，并显示该动作最近一条训练记录。
- 最近值只复用已有的组数、次数、重量和间歇，不分析动作顺序、疲劳或其他隐含上下文。
- 缺失字段保持缺失，不用默认值补齐。
- 点击候选只修改草稿；用户主动发送后才创建训练事实。

### 动作内容与建议

- App 包内预置常见动作的基础教练提示、动作示意图、主要/辅助肌群和动作模式，但它们只是
  静默内容目录，不会预先创建个人动作，也不会进入列表或 `list_exercise_names`。
- 只有用户通过聊天或训练实际形成动作后，才为命中的标准动作关联内置内容；未使用动作不可见。
- 内置内容只补充空字段，不覆盖用户编辑；目录升级只纠正自己管理的旧 bundled 图片引用。
  动作列表左侧显示动作示意图，详情支持多张动作图。
- 肌群图使用前后人体示意，展示通用主要肌群、辅助肌群和动作模式，不描述用户个人关节受力
  或医学结论。
- 内置目录未覆盖时，用户可以上传图片，或主动请求 AI 分别生成动作示意图和肌群图。
- 图片生成使用标准 Provider 的独立 image model；打开详情、记录训练和开始计划均不自动生成。
- 视频只接受用户上传、Soma 自有或已授权内容、外部链接及条款允许的官方嵌入。
- 不抓取、下载或重新分发 Keep、YouTube 等第三方平台课程视频。
- 打开动作详情、选择动作或开始训练默认不请求 AI。
- AI 建议只在用户主动选择“分析动作”或“优化本次训练”时生成并缓存。
- 开始训练时默认只执行确定性就绪检查，不自动比较容量 gap，也不批量生成所有动作建议。

### 计划、模板与训练事实

- `TrainingProgram` 表示周期安排，`WorkoutTemplate` 表示可复用的一次训练模板，
  `WorkoutSession` 表示一次实际训练。
- 修改计划产生新版本；开始训练时将当前模板快照到 Session。
- 开始后的 Session 不受后续计划调整影响。
- `WorkoutSet` 区分计划值与实际值，并支持热身组、工作组、跳过和未完成。
- 现有聚合 `WorkoutEntry` 继续作为真实历史，不拆成用户从未提供的逐组事实。
- 统计只使用实际完成值；计划值和 AI 建议值不得进入完成容量。

### 程序化带练

- 带练是一个从计划启动的临时沉浸流程，不新增顶层 Tab。
- 本地状态机负责动作说明、组前倒计时、执行、确认、休息、下一组和完成。
- 用户可以暂停、跳过、替换、调整实际值或提前结束。
- 每次完成组后立即保存草稿恢复点；网络或模型失败不影响训练继续。
- 带练运行时直接保存用户确认的确定性训练事实，这是对“聊天唯一创建路径”的受控例外。
- 完成后的 Agent Turn只总结既有 Session，不重复创建训练记录。

### 每动作自动录制一组

- 自动录像按本次 Session 显式开启；开启后默认覆盖后续每个动作，直到用户暂停或取消。
- 每个计划动作保存 `firstSetIsWarmup`：
  - `false`：自动录制第 1 组；
  - `true`：自动录制第 2 组。
- 如果首组标记为热身但没有第 2 组，就绪检查提示没有可录制工作组，但不阻止训练。
- 目标组倒计时结束后自动开始，用户确认该组完成时自动停止。
- 每个动作默认只保留一组视频；用户可以重录、替换或删除。
- 摄像头必须显示预览和系统指示；麦克风默认关闭。
- 相机中断、后台、磁盘不足或热压力不能阻止继续训练。

## 数据与隐私

- 动作、计划、Session、Set、录像和分析默认保存在当前本地数据空间。
- 内置目录和包内图片不是用户数据；AI 生成/用户上传图片保存为当前空间的 `PrivateMedia`，
  进入备份、恢复、清除、导出媒体引用和动作合并/撤销。
- 图片生成只发送动作名称、已保存的通用肌群/动作模式和绘图约束，不自动发送用户照片、视频、
  训练历史或身体数据。
- 训练录像默认不写入系统相册，也不自动发送给远程模型。
- AI 分析前明确列出将发送的视频、关键帧和关联训练上下文。
- 新模型必须进入开放导出适用范围评估、加密备份、恢复、主动清除和媒体引用回收。
- 演示与个人动作库完全隔离；测试只使用虚构动作、数值和授权媒体。
- 动作和视频反馈属于一般训练建议，不诊断伤病、骨骼或疼痛原因。

## 空态与失败态

- 没有动作时，输入框不显示空候选；第一次成功记录时自然创建动作。
- 内置目录未命中或图片生成失败时保留动作事实与中性占位，允许用户重试、上传或跳过。
- 动作 ID 已不存在时，Tool 返回可恢复错误，Agent 重新读取列表，不能退回字符串猜测。
- 模型错误创建重复动作时，用户可以合并并撤销；历史和媒体引用保持完整。
- 计划缺少器械、组数或休息时显示就绪提示，用户可以修改或仍然开始。
- 相机或 AI 分析失败时保留训练事实和原始视频，不伪装为已完成分析。
- 带练被系统中断后从最后持久化组恢复，不能把未确认组标记为完成。

## 明确不在范围

- 课程商城、社区、排行榜或第三个顶层训练 Tab；
- 抓取 Keep 或其他平台私有内容；
- 所有动作的实时视觉纠错、通用自动计数或伤病诊断；
- 每次进入动作或计划都自动调用大模型；
- 根据摄像头自动猜测任意动作的开始和结束；
- 因公共场馆规则或旁人入镜自动判断是否允许录像。

## 验收

- Agent 记录训练前读取完整动作 ID 与名称列表；语义相同表达归入同一 ID。
- 动作改名不改变历史；动作合并迁移所有引用并可撤销。
- 输入部分名称可以本地选择动作，再一键补入最近一条记录；过程不调用网络。
- 点击候选只修改草稿，发送后才形成训练事实，缺失字段保持为空。
- 旧聚合训练和新逐组训练在统计中都只计一次。
- 修改计划不会改变已开始或已完成 Session 的计划快照。
- 断网时可以完成带练、休息和逐组记录。
- 自动录像按 `firstSetIsWarmup` 选择第 1 或第 2 组，每个动作默认只有一段。
- 暂停或取消自动录像后不再为后续动作启动摄像头。
- 视频分析必须由用户主动触发，并可审查、编辑和删除。
- 空数据库不会因内置目录产生动作；创建一个已知动作后只激活它自己的说明和图片。
- 动作列表左侧展示动作示意图；详情展示多张动作图与前后人体肌群图。
- 图片生成只由用户点击触发，使用独立 image model，结果可删除、替换并随个人数据管理。
- 数据空间、备份恢复、清除、Dynamic Type、VoiceOver、相机中断和长中文文本通过验收。
