## 背景

Soma 已经通过聊天持续接收用户的训练、饮食、身体变化和日常感受，但这些原始表达只存在于
Session 对话中，不适合快速回顾。用户还需要在 Agent 失败后直接重试，而不是重新选择媒体、
复制文字或制造重复记录。

位置可以让原始表达成为更完整的个人足迹，也可以在用户忘记切换健身房时为本次 Agent Turn
提供更准确的场馆上下文。当地天气只在户外活动相关时提供一般性的强度与生活建议。

## 用户结果

1. “进展”内增加“足迹”入口，按时间倒序展示处理成功的用户原始表达。
2. 足迹卡保留原始文字、完整有序媒体、发送时间和用户授权后获取的位置。
3. Agent 处理失败的 Turn 不进入足迹；重试成功后只进入一次。
4. 聊天失败卡提供“重试”，复用原始文字、沙盒媒体和发送时的位置，不新增用户气泡。
5. 每次重试创建新的 Attempt 和 Trace，旧失败证据继续保留。
6. 发送时可选择获取一次前台位置；拒绝、超时或精度不足都不阻止消息与 Agent。
7. 已保存健身房可以绑定当前位置。发送位置唯一命中其他健身房时，本次 Turn 使用命中的
   场馆上下文，但不静默改变全局“当前健身房”。
8. 仅在文字明确涉及天气或户外活动时临时获取 Open-Meteo 当前条件，并向 Agent 提供最小
   风险提示。天气失败不阻止消息，也不影响足迹资格。
9. 数据查询向 Agent 返回稳定记录 ID；纠错优先调用对应 `update_*` 工具精确更新，当前消息
   明确要求删除时可以调用 `delete_record`。

## Turn 与成功边界

- 一次用户发送是一条稳定的 Turn，拥有原始内容、Session、媒体和可选位置快照。
- 首次处理与每次重试都是独立 Attempt；每个远程 Attempt 对应一条 Trace。
- Turn 只要有一个 Attempt 最终成功，就获得足迹展示资格。
- 已成功的 Tool 写入即使遇到最终回复失败也继续保留；此时 Turn 仍不进入足迹，等待重试。
- 跨 Attempt 的相同成功写入必须命中持久化幂等回执，不能重复创建训练、饮食、身体或健身房
  数据。
- 后续补图或纠错即使来自新 Turn，也要按来源、时间、类型、内容、结构化数值和纠错语义
  综合判断同一现实事件；唯一高置信命中时更新原记录并合并媒体。
- `update_workout`、`update_meal` 和 `update_body` 必须按查询得到的 ID 原位更新；当前
  Turn 的新媒体并入原记录。`delete_record` 只删除指定业务记录，不删除聊天 Turn 或共享媒体。
- Agent 误用 `record_*` 表达纠错时，本地多维合并仍作为安全网；歧义候选不得自动更新。
- 标准档没有 API Key 时在发送前阻止，不创建 Turn；已创建 Turn 的足迹资格仍只由持久化
  Attempt 状态决定，不能依赖是否存在一条教练文本来猜测。

## 足迹信息架构

- 足迹是聊天原始事实的只读投影，不复制媒体文件，也不拥有独立删除生命周期。
- 足迹位于“进展”内部，不新增第三个顶层 Tab。
- 卡片以用户原始表达为主体；Agent 回复不进入主 Feed。
- 可以显示“已记录训练”“已更新健身房”等轻量结果标签。
- 点击卡片进入对应 Session；用户可以从单条足迹移除位置，但不因此删除聊天或业务记录。
- 空态说明只有 Agent 成功处理的表达才会出现。

## 位置与健身房

- 默认关闭“随消息记录位置”，用户可以从聊天输入区或隐私设置主动开启。
- 只请求 `When In Use`，每次发送调用一次性定位；不持续更新、不使用后台定位或地理围栏。
- 位置快照保存经纬度、水平精度、采集时间和尽力解析的本地显示名称。
- 足迹只展示语义位置；原始坐标只保存在当前 SwiftData 数据空间。
- 远程 Agent 不接收原始坐标，只接收本次场馆和语义位置等最小必要上下文。
- 健身房匹配顺序：
  1. 用户文字明确指定；
  2. 位置唯一命中已绑定场馆；
  3. 用户手动选择的当前健身房。
- 位置不唯一、水平精度差或没有已绑定场馆时不猜测，继续使用手动当前健身房。

## 天气边界

- Open-Meteo 只在户外跑步、骑行、徒步、步行或明确询问天气等场景按需调用。
- App 把天气转换为高温、严寒、高湿或高紫外线等一般风险提示，不让模型据此臆造热量、
  饮食摄入或医学结论。
- Open-Meteo 原始响应不写入 SwiftData、聊天、Trace 或足迹，仅在当前 Attempt 内短暂使用。
- 当前天气获取失败时静默降级，不改变 Agent 成功规则。
- Soma 不把实时天气建议描述为应急、救生或医疗指导。

## 隐私

- 位置开关、用途说明和单条移除能力必须可见。
- 精确坐标、媒体和足迹只保存在当前本地数据空间，不进入日志或测试夹具。
- 天气请求只发送四舍五入到小数点后两位的公里级坐标；Open-Meteo 会同时看到设备 IP，
  故障排查日志可能保留坐标最多 90 天。
- 远程 Agent 只接收本次任务需要的语义场馆/位置和派生天气风险，不接收原始坐标、
  Open-Meteo 原始负载或精确天气数值。
- 演示数据不得使用维护者真实位置。

## 明确不在当前范围

- 社交关系、点赞、评论、公开分享和排行榜；
- 足迹地图、路线记录、后台持续定位和到离场通知；
- 自动改变全局当前健身房；
- 把 Open-Meteo 建成历史天气数据库；
- 跨设备同步、账户或云端足迹；
- 当前本地实现中，App 被终止后不续接同一 Attempt；[PRD 011](011-durable-agent-jobs-remote-continuity.md)
  改为恢复持久 Job、创建新本地 Attempt，或同步已由服务器继续的远程 Job。

## 验收

- 成功 Turn 出现在足迹一次；失败、取消和仍在运行的 Turn 不出现。
- 首次失败后点击重试，不新增用户气泡；重试成功后足迹只出现一次。
- 第一次 Attempt 已成功写入业务数据但最终失败时，重试不会重复写入。
- 查询结果包含业务记录 ID；显式更新按 ID 修改原记录，显式删除只有在用户当前消息明确
  要求时成功。
- 对同一餐、训练、身体或健身房进行补图/纠错时更新原记录，媒体有序合并；相邻但证据不同
  的真实事件仍保持独立。
- 重试图片与视频时从沙盒媒体恢复输入，不依赖 Photos 临时 URL。
- 位置关闭、拒绝、超时和精度不足时都能正常完成 Agent。
- 唯一命中已绑定健身房时，本次上下文使用命中场馆，全局当前健身房不改变。
- 天气只在相关文本中获取，Open-Meteo 失败不影响 Agent，原始天气不持久化。
- 足迹支持空态、长文本、混合媒体、语义位置、浅色/深色和 Dynamic Type。
- `make verify` 通过，并在模拟器和真机完成定位授权、重试和足迹手工验收。
