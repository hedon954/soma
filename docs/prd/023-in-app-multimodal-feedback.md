# PRD 023：应用内多模态反馈

- 状态：已实现，待生产服务配置与真机验收
- 日期：2026-08-09
- 修订自：[PRD 004](004-soma-current-product.md) 的设置与外部数据流边界
- 后续修订：暂无
- 上游依据：维护者明确要求反馈不跳转系统邮件 App
- 下游落地：[ADR 0051](../adr/0051-authenticated-in-app-feedback-email-delivery.md)

## 背景

设置页需要一个低摩擦反馈入口。`mailto` 或系统邮件编辑器会把用户带到邮件流程，也无法提供
符合 Soma 交互的单一文字与多媒体输入区。用户需要在 Soma 内写文字、选择照片或视频，点击
一次“发送”后直接把内容交给维护者邮箱。

## 用户结果

1. “设置 → 关于 → 发送反馈”进入 Soma 内置反馈页，不打开系统邮件 App。
2. 一个输入区同时承载文字草稿与照片/视频预览；可以只发文字、只发媒体或混合发送。
3. 点击“发送”后显示发送中状态；成功时明确提示并清空草稿，失败时给出可恢复原因并保留草稿。
4. 当前构建没有配置官方反馈服务地址时不伪装成功，明确提示服务暂不可用。

## 产品规则

- 反馈文字去除首尾空白后最多 5,000 字。
- 单次最多 10 项照片或视频，原始附件合计最多 25 MB；超限在上传前阻止。
- 收件人固定为 `hedonwang@gmail.com`，用户不填写或修改收件人。
- 每份草稿拥有稳定反馈 ID；同一草稿重试复用该 ID，防止响应丢失后重复投递。
- 不自动重试失败发送，不在后台悄悄补发；用户看到失败并主动重试。
- 离开反馈页即放弃未发送草稿和临时视频副本，不把反馈草稿写入身体业务数据库。

## 数据与隐私

- 只有用户点击“发送”后，填写的文字和明确选择的附件才离开设备。
- App 不自动附带聊天、Agent Trace、API Key、健康记录、位置、设备日志或其他业务数据。
- 请求复用 Soma Server 的匿名设备认证与签名；邮箱和邮件服务凭据只存在服务端 secret
  manager，不进入 iOS、日志或 Git。
- 附件先进入临时对象存储，服务端校验大小和摘要后交给邮件服务；投递被接受后立即删除上传。
  中断遗留对象由既有 7 天硬上限清理。
- Soma Server 不把反馈正文或媒体写入 PostgreSQL 或普通运行日志。邮件送达后，正文和附件会
  由收件邮箱及邮件投递商按各自策略保留，这是“发送邮件”本身不可避免的外部副本。
- 反馈投递与后台 Agent 开关、用户可编辑的远程 Agent 地址相互独立；Release 只读取构建时注入
  的官方反馈 Server 地址，避免把反馈交给任意第三方兼容服务。

## 明确不在范围

- 不读取或自动打包诊断日志、崩溃日志、聊天记录和健康数据。
- 不增加账号、反馈工单列表、处理状态追踪、双向客服会话或营销邮件订阅。
- 不在客户端保存 SMTP、Gmail 或邮件 API 凭据。

## 验收

- 纯文字、纯图片、纯视频和混合反馈均可在 Soma 内提交，不出现系统邮件 App。
- 空反馈、超过 5,000 字、超过 10 项或附件合计超过 25 MB 时不发起远程投递。
- 服务端只接受通过匿名设备签名的请求，固定投递到 `hedonwang@gmail.com`，并传递稳定
  Idempotency-Key。
- 成功后临时上传被删除；失败时 App 保留文字与附件供用户重试。
- 模拟器检查浅色/深色、Dynamic Type、键盘、长文本、附件横向滚动、错误态与成功态。
- `make verify` 通过。
