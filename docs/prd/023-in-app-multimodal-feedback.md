# PRD 023：应用内多模态反馈

- 状态：已实现，个人设备凭据待配置与真机验收
- 日期：2026-08-09
- 修订自：[PRD 004](004-soma-current-product.md) 的设置与外部数据流边界
- 后续修订：[PRD 024](024-chat-agent-feedback-tool.md) 增加聊天中的固定反馈 Tool，设置页入口继续保留
- 上游依据：维护者明确要求反馈不跳转系统邮件 App
- 下游落地：[ADR 0051](../adr/0051-authenticated-in-app-feedback-email-delivery.md)、[ADR 0052](../adr/0052-gmail-self-delivery-for-in-app-feedback.md)、[ADR 0053](../adr/0053-personal-only-direct-qq-mail-feedback.md)

## 背景

设置页需要一个低摩擦反馈入口。`mailto` 或系统邮件编辑器会把用户带到邮件流程，也无法提供
符合 Soma 交互的单一文字与多媒体输入区。用户需要在 Soma 内写文字、选择照片或视频，点击
一次“发送”后直接把内容交给维护者邮箱。

## 用户结果

1. “设置 → 关于 → 发送反馈”进入 Soma 内置反馈页，不打开系统邮件 App。
2. 一个输入区同时承载文字草稿与照片/视频预览；可以只发文字、只发媒体或混合发送。
3. 点击“发送”后显示发送中状态；成功时明确提示并清空草稿，失败时给出可恢复原因并保留草稿。
4. 页面不显示 Base URL、Server、邮箱、SMTP 或其他内部投递说明；凭据不可用时只保留草稿并
   给出通用失败提示。

## 产品规则

- 反馈文字去除首尾空白后最多 5,000 字。
- 单次最多 10 项照片或视频，原始附件合计最多 25 MB；超限在上传前阻止。
- 发件人来自本机 QQ 邮箱配置，收件人固定为 `hedonwang@gmail.com`；用户不在反馈页填写或
  修改邮件地址。
- 每份草稿拥有稳定反馈 ID；同一草稿重试复用该 ID，并映射为稳定邮件 Message-ID。SMTP
  不提供严格幂等保证，因此 App 不在后台自动重试，失败只允许用户主动重试。
- 不自动重试失败发送，不在后台悄悄补发；用户看到失败并主动重试。
- 离开反馈页即放弃未发送草稿和临时视频副本，不把反馈草稿写入身体业务数据库。

## 数据与隐私

- 只有用户点击“发送”后，填写的文字和明确选择的附件才离开设备。
- App 不自动附带聊天、Agent Trace、API Key、健康记录、位置、设备日志或其他业务数据。
- 当前个人使用阶段由 App 通过 TLS 直连 QQ SMTP，不调用 Soma Server，也不经过临时对象存储。
- QQ 邮箱地址与 SMTP 授权码只放在被 Git 忽略的本机 `FeedbackCredentials.plist`，随维护者
  个人安装包携带；不写入源码、日志或 Git。该例外禁止用于任何外部分发。
- 反馈正文与媒体不写入 PostgreSQL 或普通运行日志。邮件送达后，正文和附件会由 QQ 邮箱、
  Gmail 及其供应商按策略保留，这是“发送邮件”本身不可避免的外部副本。
- 对外开放前必须让 `make online-check` 通过：迁移到认证的服务端或 Serverless 凭据边界，
  从 App 删除并轮换 SMTP 授权码，再做生产冒烟测试。

## 明确不在范围

- 不读取或自动打包诊断日志、崩溃日志、聊天记录和健康数据。
- 不增加账号、反馈工单列表、处理状态追踪、双向客服会话或营销邮件订阅。
- 外部分发版本不在客户端保存 SMTP 或邮件 API 凭据。

## 验收

- 纯文字、纯图片、纯视频和混合反馈均可在 Soma 内提交，不出现系统邮件 App。
- 空反馈、超过 5,000 字、超过 10 项或附件合计超过 25 MB 时不发起远程投递。
- 当前个人安装包通过 QQ SMTP 投递到 `hedonwang@gmail.com`，并使用稳定 Message-ID 标记
  同一草稿重试；失败时 App 保留文字与附件供用户重试。
- 反馈页不出现服务地址、Server、邮箱或 SMTP 实现；TestFlight 与 App Store 归档在个人直连
  模式下必须被 `online-check` 阻止。
- 模拟器检查浅色/深色、Dynamic Type、键盘、长文本、附件横向滚动、错误态与成功态。
- `make verify` 通过。
