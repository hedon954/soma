## 背景

维护者连续遇到：桌面组件字色被底板吃掉、饮食可编辑卡拖慢全 App、快捷 Skill 仍注入全量提示、
听写要停顿才出字、进展宏量没有目标对照、动作库搜索压住分类、分类轴与身体部位重叠。

## 用户结果

1. 主屏幕快速记录组件在浅色、深色和着色模式下都能看清标题与入口。
2. 饮食分析后的可编辑卡保持原位审查，但不再因布局探测或隐藏 Tab 重算让全 App 卡顿。
3. 默认快捷按钮「记录饮食」强调写入记录；明确点选某一快捷按钮后，本轮只带该 Skill、对应工具
   和必要上下文，不再塞入其他 Skill 目录。
4. 点选快捷按钮且输入框为空时，填入该按钮的建议句；已有文字不覆盖。取消选择时，若草稿仍等于
   建议句则清空。
5. 按住听写时，未确认片段实时出现在输入框里；确认后才写入草稿。用户中途改字不会被后续猜测覆盖。
6. 进展「饮食与能量」按 Facts → Status → Breakdown → Action：顶部两张事实卡写已记录摄入与
   预估总消耗；主热量环心写已摄入／推荐摄入 kcal，不写还可摄入或完成百分比；下排蛋白质／碳水／
   脂肪用红、橙、紫指标色和肉块／麦穗／油滴图标写克数对照。热量环不重复「热量」标题，宏量单位
   与数字同行。点按热量环打开摄入明细，点按宏量环打开该营养素克数明细；明细只列分项，不重复
   卡面已有汇总。不足与超量只靠进度和
   颜色，不写不足／超量。当日未达推荐时底部再给一句仍可摄入，不可点开。周、月只保留日均摄入／
   消耗和图表，不展示营养环。周、月、年点图都不切换周期。
7. 动作库左侧分类顶满高度；搜索只与右侧卡片同宽。
8. 动作库保留身体部位；删除独立「受力肌群」轴；「动作模式」改为少量确定动作类型。

## 产品规则

- 快捷按钮默认标题改为「记录饮食」「训练记录」「近期分析」。已由用户改过名的按钮不覆盖。
- 选中快捷按钮时：固定身份与安全契约仍在；能力目录和其他 Skill 元数据不进入 System；信封
  `skills` 只含本轮 Skill；默认不再暴露 `load_skill`。未选按钮时行为与 PRD 000 相同。
- 「记录饮食」默认工具为餐食读写；「训练记录」为动作搜索／创建与训练读写；「近期分析」只读
  训练、饮食、身体。对话历史和权威本地时间始终保留。
- 听写预览不得另存草稿基线或历史转写；停止、发送、切会话仍先排空或丢弃过期回调。
- 推荐摄入由体重、健身目标和当日预估消耗确定性计算，缺资料时对应环不假装有目标。营养环只出现在日页。
- 周、月、年能量只给日均与图表；点图不切换周期。用户用顶部日／周／月／年自己切换。
- 动作类型从现有 `movementPatterns` 映射，不改写动作定义。无法映射的标签归入未标注。
- 餐次浮层仍须文字加色标；圆环状态色只用于有阈值的摄入进度，VoiceOver 读出不足或超量。

## 数据与隐私

不新增 SwiftData 字段、迁移或远程数据流。快捷按钮标题与建议句仍在 UserDefaults。听写音频留在
设备。测试只用虚构数据。

## 明确不在范围

云端语音、医学营养处方、HIIT 自动标注、器械／难度猜测、桌面上下文 Widget 回退。

## 验收

快捷聚焦提示词、建议句填充、听写预览不污染草稿、日页营养目标、周月不建环、动作类型映射、双主题
对比度均有确定性测试。视觉检查浅色／深色、Widget 着色、动作库布局与圆环空态。提交前 `make verify`。
