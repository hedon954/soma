## 背景

Soma 已经具备本地 Session、混合媒体、位置上下文、动态模型列表和流式 ReAct，但当前交互
仍把一些低频控制常驻在输入区，并且把历史 Session 当成只读归档。训练记录使用单一
`组数 × 每组次数 × 重量`，无法表达每组次数或重量不同的真实训练。

现有 Agent 上下文也存在三项关键缺口：

1. 视频当前没有使用供应商已经提供的直接视频输入，而是一律在本机抽取关键帧；抽帧失败时
   还会静默退化成没有画面的纯文本请求。
2. 后续 Turn 不能重新读取前面发送的照片或视频；跨 Turn 只带当前 Session 最近八条文字，
   每条截断到 160 字。
3. 长 Session 没有清晰的来回边界；本版明确固定为最近十个完整来回，更早内容只留在本机。

本版需求让主聊天页回到“只负责说话和看回复”，把会话、权限、场馆和模型复杂度放到真正
需要它们的时机与位置。

## 用户结果

### 1. 隐藏式 Session 抽屉

- 教练页移除左上角常驻的历史时钟图标。
- 用户从屏幕左边界向右滑时，交互式拉出 Session 抽屉；抽屉跟手移动，取消手势时回到原位。
- 抽屉顶部提供“新对话”，列表按最近活动时间倒序展示 Session，并标记当前 Session。
- 点击任意历史 Session 后，它成为当前 Session，抽屉关闭，用户可以在原聊天页继续发送，
  不再进入只读 Transcript 页面。
- Session 改为用户主导：跨天或重新进入前台不再强制创建新 Session。首次使用没有 Session
  时创建一个；用户点击“新对话”时才主动切换。
- 当前 Session 尚为空时再次点击“新对话”复用该空 Session，不制造连续空记录。
- Agent 正在处理时允许查看其他 Session，但在途 Turn 始终写回它最初所属的 Session；
  全局处理完成前不允许从另一个 Session 再发送。
- 隐藏手势不牺牲无障碍：教练页提供不可见的 VoiceOver 自定义操作“打开历史对话”。

### 2. 输入区只保留高频动作

#### 位置

- 输入区不再显示“位置开启/关闭”。
- 用户第一次**发送**文字或媒体时，Soma 在发送动作的上下文中显示一次用途确认：
  是否允许每次发送时获取一次前台位置，用于足迹、健身房匹配和按需天气。
- 选择允许后再触发系统 `When In Use` 权限；选择拒绝、系统拒绝或允许后，后续发送都不再
  自动弹出 Soma 自己的确认。
- 无论用户如何选择，当前消息都继续发送；定位失败、超时或精度不足仍不阻塞 Agent。
- 设置页继续提供“随消息记录位置”。系统权限已拒绝时，设置页解释原因并提供前往系统设置
  的恢复路径。
- 该状态是三态事实：尚未询问、已开启、已关闭，不能把“尚未询问”提前当成用户拒绝。

#### 健身房

- 健身房数量为 0 或 1 时，输入区不显示场馆选择器。
- 只有一个健身房时，它自动成为本次默认场馆上下文，无需用户确认。
- 健身房数量大于等于 2 时，输入区才显示紧凑的当前场馆切换入口。
- 健身房管理仍位于设置页；位置唯一命中其他场馆时只影响本次 Turn，不静默改变全局选择。

### 3. 逐组训练事实

训练不再以一组标量表达整项动作，而是保存有顺序的逐组数组。每一组至少可以独立保存：

```json
[
  {"reps": 10, "external_weight_kg": 10},
  {"reps": 10, "external_weight_kg": 20},
  {"reps": 12, "external_weight_kg": 14}
]
```

- 组数由数组长度派生，不再作为独立可编辑事实。
- `[10, 10, 10, 10]` 表示四组各十次；用户明确提供统一重量时，每一组保存相同重量。
- 每组的次数或外部负重未知时保持 `nil`；明确自重且没有外部负重时使用 `0`，两者不能混淆。
- 训练详情按顺序编辑每一组，支持新增、删除和调整单组次数或重量。
- 紧凑摘要可以显示总组数和总次数，但必须能展开看到逐组事实；重量不同时不能折叠成一个
  伪造的统一重量。
- 训练容量改为逐组求和：

  `已知容量 = Σ(该组次数 × 该组外部负重)`

  只累计次数和重量都完整且外部负重大于零的组。存在不完整组时，界面使用“已知训练容量”，
  不把部分数据伪装成整项训练的完整容量。
- `record_workout`、`update_workout`、查询结果、合并规则、开放导出、加密备份、热量估算和
  趋势统计都使用同一份有序逐组事实。

### 4. 视频与媒体分析必须可证明

- 原始视频继续留在本机。直接视频只读取已经保存到沙盒的稳定副本，并限制为 24MB；
  超限时不发送完整视频，改用本机关键帧。
- 视频输入由平台与模型能力矩阵决定：
  1. 当前仅对百炼中官方文档明确支持的 Qwen-VL、Qwen-Omni 和 QVQ 系列启用内联
     `video_url` Data URL；稳定副本满足 24MB 限制时优先直传；
  2. 平台只接受公网视频 URL 时，Soma 不为此建立公开上传服务，改用本机关键帧；
  3. 模型不支持直接视频、能力未知或直接输入被拒绝时，从稳定沙盒副本抽取、缩放和压缩
     关键帧降级；
  4. 模型连图片也不支持时，在发送前阻止并要求切换标准模型。
- 直接视频和关键帧不是同一种能力。UI 与 Trace 必须说明本次实际使用“视频”还是“关键帧”，
  关键帧路径不能声称理解了完整视频流。
- 抽帧必须从已经保存到 App 沙盒的稳定副本执行，不能依赖选择器的临时 URL。
- 只要用户附加了视频，必须证明本次请求包含有效的直接视频，或实际送入模型的帧数大于零；
  两者都没有时，本次 Attempt 以可操作错误失败，允许从沙盒原件重试，不能静默退化。
- Trace 记录附件数量、直接视频数量、实际发送帧数和失败阶段，但不记录视频/图片 Base64、
  原始媒体或私有路径。
- 首次发送与重试使用相同的图片标准化结果；不得出现首次发送原始大图、重试才发送压缩图的
  不一致。
- 关键帧只能支持可见姿态和场景判断。需要连续运动时序才能判断的结论必须说明限制，不把
  稀疏关键帧描述成医疗或专业动作诊断；直接视频也继续遵守 Soma 的非诊断边界。

### 5. 同一 Session 的媒体连续性

- 当前 Turn 的媒体始终优先进入模型。
- 最近十个来回中的用户图片和视频关键帧随各自历史用户消息从本机沙盒重新准备，使 Agent
  能直接理解“刚才的视频”“上一张图”等后续追问，而不是只看到媒体存在的文字提示。
- 单次请求最多提供十二张图片或视频关键帧：先保留当前 Turn，再按从近到远的顺序分配给
  历史 Turn；未进入额度的历史媒体在提示中明确标记为没有重新提供，模型不得臆测。
- 历史媒体只作为请求上下文，不能自动合并到当前 Turn 创建或更新的业务记录。
- 其他 Session 的聊天文字和媒体不进入当前 Session；已经写入的结构化身体、饮食、训练和
  场馆事实仍可作为全局个人数据被查询。

### 6. 长 Session 的上下文窗口

- 完整聊天、原始媒体引用、Event Cards 和 Trace 始终保存在本机，不因远程窗口截断而删除
  或改写。
- 每次远程请求只投影同一 Session 最近十个完整来回；一个来回由用户 Turn 和该 Turn 最后
  一次 Agent Attempt 组成，当前用户输入作为新的独立消息追加。
- 十个来回保留完整文字，不再使用“最近八条、每条 160 字”的无语义截断。
- 更早聊天不生成或注入滚动摘要；精确历史业务事实继续通过确定性查询工具读取，不能依赖
  模型猜测已经移出窗口的原始对话。
- Trace 记录历史来回数和实际重新提供的历史视觉帧数，不记录 Base64、私有路径或 thinking。

### 7. 平台与双档模型

- 平台列表增加“其他（OpenAI-compatible）”，用户必须填写 Base URL；URL 需通过
  `https`、host 和路径规范化校验。
- AI 配置分为“小模型”和“标准”两个 Tab。每档是独立的端点配置，可以选择平台、
  Base URL、API Key 和模型。
- “标准”是聊天发送的必配档；“小模型”可为空。设置页不提供远程 Agent 开关。标准档没有
  API Key 时，发送和重试会保留草稿与附件并直接打开 AI 服务设置，不产生失败 Turn；
  旧版本的单一配置迁移到“标准”，不猜测小模型。
- 获取到非空 `/models` 列表时只显示下拉选择，不同时常驻手写输入框；只有列表为空、获取
  失败或平台不提供列表时才显示手动模型 ID。
- 两个档位维护独立的平台、URL、Keychain 凭据和模型 ID。媒体始终使用标准档；已知平台的
  能力矩阵决定图片、内联视频或关键帧路径，其他平台保持未知并由真实请求验证。
- 本地路由器按任务风险和复杂度选择档位：
  - 短文本、无媒体、无业务写入和无安全敏感词的轻量问答可以使用小模型；
  - 图片/视频、多意图、复杂纠错、安全敏感建议、上下文压缩失败后的恢复使用标准模型；
  - 小模型缺失时使用标准模型。
- Trace 明确记录选择的档位、平台、模型和路由原因；不展示模型 thinking。

### 8. Agent 回复支持原生文字选择

- 用户长按 Agent 的最终回复和文字 Event Card 时，可以使用系统选区精确选择、复制和查找
  文字，行为与用户消息一致。
- 文字选择不能破坏 Markdown 的段落、列表、链接和行内代码显示。
- 流式输出完成后必须变为可选择文本；选择期间自动滚底不能抢走选区。
- 图片、视频、按钮和 Tool 状态卡不伪装成可选正文，并继续保留各自的无障碍标签。

## 数据迁移与兼容

- 旧 Session 和消息原样保留；升级后最近使用的有效 Session 成为当前 Session，不按自然日
  再创建一个新的空 Session。
- 旧训练若同时拥有合法的组数、次数和重量，确定性展开为相同的逐组数组。
- 旧训练只有部分字段时，只展开有可靠组数的部分；无法知道组数时保留旧字段作为兼容事实，
  不推测一组。
- 导出与备份格式升级版本。恢复旧快照时执行相同迁移；新快照保存逐组数组、Session 摘要和
  双档模型以外的业务数据。API Key 仍不进入备份。
- 位置首次确认状态与模型凭据属于设备设置，不作为健康业务记录导出。

## 隐私与失败边界

- 不新增账户、云同步、后台服务器或跨 Session 的原始媒体上传。
- “其他”平台与已知平台具有相同隐私披露：用户输入与必要的压缩图片、压缩视频或关键帧会
  发送到用户配置的端点，Soma 不控制其保留策略。
- Session 摘要可能包含私人身体信息，只保存在当前数据空间，并进入加密备份和主动清除范围。
- 历史抽屉、Trace 和错误信息不展示 API Key、Authorization 头、媒体 Base64、精确坐标或
  沙盒路径。
- App 被系统终止后仍不承诺继续 Agent；该边界不因 Session 可切换而改变。

## 明确不在当前范围

- 删除、合并、分享或跨设备同步 Session；
- 发送最近十个来回之外的历史聊天，或突破十二张视觉帧额度重发媒体；
- 为只接受公网 URL 的供应商建立视频 CDN、对象存储或临时公开上传服务；
- 后台持续定位或再次在聊天输入区放置位置开关；
- 为不同动作类型预建训练模板、课程或社交排行；
- 让模型自行改写 Tool Schema、显示 thinking 或绕过本地路由与幂等规则。

## 验收

- 教练页没有历史时钟；从左边界右滑可打开抽屉，VoiceOver 自定义操作也能打开。
- 新建两个非空 Session 后可来回切换并继续发送；跨天进入前台仍停留在用户选择的 Session。
- 切换 Session 时，在途回复只出现在原 Session；空 Session 不重复堆积。
- 首次发送只出现一次位置用途确认；允许、拒绝和系统拒绝后都不再自动弹出，设置页可修改。
- 0/1 个健身房时输入区没有场馆胶囊，2 个及以上时可以切换。
- `10kg×10、20kg×10、14kg×12` 保存为三项有序逐组事实，组数为 3，已知容量为
  `100 + 200 + 168 = 468kg`；修改第二组只改变该组和派生容量。
- 能力矩阵确认内联视频时优先发送压缩视频；不支持、超限或直接输入失败时使用关键帧。
  两条路径的 Trace 可区分；构造零帧失败时不发起伪装成视频分析的纯文本请求。
- 同一 Session 追问上一段视频时模型收到对应压缩视频或关键帧；其他 Session 的媒体不被
  带入，历史媒体不会成为当前业务记录的新附件。
- 构造十一轮以上长会话后，完整本地历史不变，远程请求只包含最近十个完整来回；有多次
  Attempt 的 Turn 只使用最后一次回复。
- `/models` 返回列表时没有常驻手写框；返回空或失败时出现手动模型 ID。
- 未配置标准档 API Key 时，点击发送或重试直接进入 AI 服务设置并显示配置提醒；返回后
  草稿与附件仍在，对话和 Trace 没有新增失败项。
- 未配置小模型时所有请求使用标准；配置后简单文字走小模型，媒体、记录、纠错与安全敏感
  任务走标准，Trace 可解释路由。
- Agent Markdown 回复在真机上可精确选择和复制，选择期间不会被自动滚动打断。
- 单元测试覆盖迁移、逐组容量、Session 选择、十回合窗口、媒体重取和模型路由；
  `make verify` 通过，并在 iPhone 尺寸模拟器及真机完成手势、权限、媒体和文字选择验收。
