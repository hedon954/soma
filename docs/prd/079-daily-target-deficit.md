- 下游落地：[ADR 0148](../adr/0148-daily-target-deficit.md)、[验收](../acceptance.md)、[工程原则](../../CLAUDE.md)

## 用户结果

减脂或增肌减脂用户可以在「设置 → 身体信息 → 健身目标」下修改每日目标热量缺口，默认 400 kcal。
保存后重新打开仍保留；进展中的推荐摄入和仍可摄入使用相同偏好，教练上下文说明这是用户设置。

## 规则

- 对减脂和增肌减脂目标生效，两者共用同一个每日缺口偏好；增肌和未选择目标保持已有规则。
- 推荐摄入 = max(0, 预估总消耗 − 每日目标热量缺口)。
- 仍可摄入 = max(0, 推荐摄入 − 已记录摄入)。
- 接受有限非负数，包括显式 0；清空后保存恢复默认 400，负数、非数字和非有限数不能保存，并显示纠正提示。
- 缺少消耗估算时不生成摄入目标。摄入超过推荐时仍可摄入为 0。
- 切换目标不会删除偏好，再切回减脂继续使用；偏好不是医学建议或经校准的身体事实。
- 实际热量缺口仍是预估总消耗减已记录摄入，不能与用户设置的目标缺口混淆。

## 数据与验收

本地个人资料新增可选数值，旧库和旧备份保持 nil，读取回退 400。备份恢复保留自定义值和 0。
不改变静息、残差系数、日活动择优、训练去重和历史健康事实，不新增权限、网络请求或 Agent Tool。

确定性验收覆盖默认、自定义、0、超大目标归零、增肌和未选择目标不变、缺估算、资料备份和磁盘重开、
进展投影与教练上下文；设置保存重开提供 UI 回归。iOS 测试必须在 Xcode 环境执行。

## 本地实现整合补充

- 减脂与增肌减脂共用可选目标缺口；0、小数与小数逗号可用。清空后保存恢复默认 400 kcal，并持久化为 nil；不影响其他目标。
- 超过 800 kcal 提供非阻塞提醒，不代表医学安全阈值；不沿用本地草稿的任意 10000 kcal 上限，仍拒绝负数、非数字和非有限值。用户偏好不是测量事实，不改写实际消耗或健康历史。
- 有界教练上下文与 ConversationRecorderShared 身体摘要复用同一目标判断、数值及“用户设置”说明。
