## 背景

v0.0.3 完成 GUI 精简后，真机使用暴露出三类新的体验断点。

第一类是**记录会被 LLM 状态阻塞**。Soma 已经把发送、执行和 UI 解耦成持久 Job 与 Event，
但发送入口仍保留两道硬门禁：标准档没有 API Key 时点击发送会被拦截并跳转设置；已有任务
在途时发送键直接失效。结果是用户在健身房连续记录时，一旦 Key 失效、额度用尽或供应商抖动，
就只能停下来处理配置，训练现场的记录窗口随即丢失。这与“请求与 UI 解耦”的目的相反。

第二类是**LLM 配置被过度折叠**。PRD 020 把 AI 服务收敛为“平台 → API Key → 模型”三步，
把 Base URL、图片生成模型和模型档位塞进「高级」。渐进披露适用于低频审查项，但不适用于
配置项本身：用户来这一页就是为了改这些值。折叠后出现两个具体故障：档位切换藏在高级里，
用户找不到小模型；非预设平台必须先展开高级才能填 URL，`opencode` 这类新平台无从配置。

第三类是**输入建议不够直接**。模型选择被实现为下拉 Picker，无法输入列表之外的模型 ID；
选中后又因为“返回时重新载入配置”覆盖了尚未落盘的选择，出现“选了模型但没保存”的缺陷。
聊天输入区的动作候选同样需要两步：先点动作名 chip，再点“上次训练”按钮，才能得到
“动作 + 最近一次训练”的完整草稿。

三类问题的共同解法是：**把不确定的执行时机交给队列，把确定的配置和候选值直接摊开。**

## 用户结果

1. LLM 不可用时发送不再被拒绝：消息、媒体与上下文快照照常落盘，标记为“已暂存”，
   用户可以连续记录多条，不需要等待或先去配置。
2. LLM 恢复后（保存 Key、换平台、供应商恢复、回到前台）暂存消息按先进先出自动补偿消费，
   不需要用户逐条重试。
3. 暂存状态在聊天里可解释：消息显示“已暂存”，输入区上方显示暂存条数与去配置入口。
4. 「AI 服务」更名为「LLM 配置」；标准模型与小模型恢复为页面顶部的两个档位分段，
   平台、Base URL、API Key、模型在同一屏直接可见，不再有「高级」折叠层。
5. 新增 `opencode` 平台；所有平台（含预设平台）都能改写 Base URL。
6. 模型是可自由输入的文本框；`/models` 拉到的列表以「输入历史」式建议出现在输入框下方，
   既能点选也能手输，选择后立即生效，返回设置首页或重新进入都不会丢失。
7. 聊天输入建议一步到位：输入动作名片段时，直接列出「动作名 + 最近一次训练数据」，
   点一次即填入完整草稿。

## 非目标

- 不改变 Tool Schema、业务写入路径与幂等边界；暂存只推迟执行时机，不改变执行语义。
- 不在设备离线时用本地规则伪造 Agent 回复；暂存消息在真实 LLM 执行前没有解析结果。
- 不引入账户、云端队列或跨设备同步；暂存队列完全保存在本机。
- 不新增服务器侧状态；`Server/` 的 Job 状态机不变。
- 不为模型建议引入排行榜、测速或跨平台竞价。

## 范围与要求

### 一、LLM 暂存与补偿消费

- 发送路径不再因“缺少 API Key”或“已有任务在途”拒绝落盘。用户消息、媒体引用、
  上下文快照与 `AgentJob` 仍在同一事务中保存，成功后才清空输入区。
- `AgentJob` 增加 `staged` 状态，表示“已持久化、等待 LLM 恢复”。进入 `staged` 的条件：
  - 标准档未配置 API Key（或远程执行未配置端点）；
  - 供应商返回鉴权、额度或服务端错误（401/403/408/409/425/429/5xx）；
  - 模型服务地址无效等可由用户改配置修复的错误。
- 短暂传输故障继续使用既有 `waitingForNetwork` 与指数退避，不进入 `staged`。
- 无法通过重试或改配置修复的错误（如请求本身非法、模型明确不支持多模态、媒体无法解析）
  仍然进入 `failed`，保留手动重试。
- 补偿消费触发点：App 启动、回到前台、保存 API Key、切换小模型启用状态、离开「LLM 配置」页、
  上一条任务结束、退避计时到期。逐字符编辑地址或模型不触发，避免用半截配置发起请求。
- 补偿按 `createdAt` 先进先出，保持全局串行；一次只运行一个本地 Agent。
- 暂存不改变业务写入的幂等边界：同一 `turnID` 的 Tool 写入仍由 Receipt 收敛为一次。

### 二、暂存状态的呈现

- 暂存中的用户消息在聊天中显示“已暂存，恢复后自动继续”，不显示伪造的教练回复。
- 输入区上方显示一条暂存提示：`N 条已暂存 · 去配置`；点击进入「LLM 配置」。
  没有暂存任务时该提示不出现。
- 发送键在有任务在途时仍然可用；连续发送的消息依次排队，不覆盖、不丢弃。
- 暂存提示与消息状态都不展示内部状态机名称、退避秒数或供应商原始报文之外的实现细节。
- 自动补偿期间教练回复不展示「重试」；只有需要用户决定的失败才展示该按钮，且此后不再自动重试。

### 三、LLM 配置页

- 入口与标题统一为「LLM 配置」；设置首页摘要显示当前平台与标准档模型。
- 页面顶部是「标准模型 / 小模型」分段控件，切换即载入该档配置。
- 每一档同屏展示：平台、Base URL、API Key、模型；标准档额外展示图片生成模型，
  小模型档额外展示「配置小模型」开关。没有「高级」折叠层。
- Base URL 对所有平台可编辑；切换平台时预填该平台默认地址，用户改写后按平台与档位保存。
- 平台新增 `opencode`（默认 `https://opencode.ai/zen/v1`）。provider 和模型 ID 不作为多模态
  能力证据；只有 `/models` 返回的明确能力字段才能标记支持或不支持。
- 模型输入框是纯文本输入；`/models` 结果以建议列表出现在输入框下方，点选即填入。
  列表为空、获取失败或平台未提供 `/models` 时，输入框继续可用。
- 候选行只显示模型 ID；候选不做条数截断，超过五条时列表自身可下划查看全部。
- 多模态能力说明只在模型已填写后出现；有明确目录字段时同时显示判断与来源，缺少来源时显示
  “未知”并由真实请求验证。禁止按模型名、`vision` / `vl` 字样或平台硬编码能力。
- 模型、Base URL、图片生成模型的改动即时落盘，不依赖「完成」按钮或返回时机。
- 刷新可用模型列表不得覆盖用户已填写的模型；只有模型为空时才自动填入建议值。

### 四、聊天输入的一步建议

- 输入动作名片段时，建议列表直接给出「动作名」加「最近一次训练数据」，
  点一次即把完整草稿填入输入框。
- 建议由本地确定性规则生成：合并旧版训练记录与带练组数据，取时间最新的一条有效容量；
  没有历史时只给动作名，不编造数值。
- 建议以「输入历史」样式呈现（输入框上方的纵向列表），与模型建议使用同一套组件。
- 建议最多 5 条；已归档动作不参与建议。

## 验收

见 [验收清单](../acceptance.md) 中「LLM 暂存与补偿」「LLM 配置」「输入建议」三组条目。
关键手工路径：

1. 清空标准档 API Key → 在教练页连续发送 3 条消息 → 三条都落盘并显示“已暂存”，
   输入区显示「3 条已暂存 · 去配置」。
2. 配置有效 API Key 并返回教练 → 三条按发送顺序依次执行，不需要手动重试，
   不产生重复业务记录。
3. 在「LLM 配置」手输一个不在 `/models` 列表中的模型 ID → 返回设置首页再进入 →
   模型仍是手输值；重新拉取模型列表也不覆盖。
4. 切换到小模型档 → 平台、Base URL、Key、模型同屏可见并可独立配置。
5. 选择 `opencode` 平台 → Base URL 预填 `https://opencode.ai/zen/v1` 且可改写。
6. 在教练输入框输入动作名片段 → 建议行同时显示动作名与最近一次训练数据 →
   点一次即得到完整草稿。

## 风险与限制

- 暂存队列只在本机。删除 App 或清除个人数据会同时清除未消费的暂存消息。
- 供应商长时间不可用时，暂存会持续累积；退避上限为 5 分钟，队列不会自行丢弃消息，
  用户仍可手动取消或删除对应对话。
- 暂存消息在真正执行前没有解析结果，趋势与统计不包含尚未消费的内容。
- `opencode` 与其他平台的模型目录由各平台维护；没有明确能力元数据时 Soma 保持未知，
  不用名称猜测，最终兼容性由真实请求验证。
