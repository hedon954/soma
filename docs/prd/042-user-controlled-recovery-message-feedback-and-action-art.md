## 背景

真机走查同时暴露出视觉、恢复和内容三个断点：深色模式的实心主按钮可能变成白底白字；聊天内
可编辑训练卡占用过多纵向空间；失败气泡之外又出现大号文字重试按钮。更严重的是，错误已经向
用户展示后，网络、供应商、前台恢复或配置变化仍可能在 ReAct Loop 外重新执行，并在成功后留下
旧错误文字，破坏“最终看起来像没有失败过”的恢复承诺。

AI 回复目前也缺少逐条反馈入口，维护者无法把用户评价稳定关联到对应 Turn、Job 与 Trace。动作图
目录虽已超过一百张，但五个真实常用名称仍可能落到占位图，且内置更新、生成图和用户上传图之间
依赖创建时间选择，无法表达明确所有权。

## 用户结果

1. 所有实心主按钮在浅色和深色模式均有明确反色前景；“开始训练”等关键操作不再消失。
2. 聊天内训练记录卡使用紧凑密度，减少外层、逻辑组、字段行与标签间距，但保留完整逐组事实、
   44 pt 触达和 Dynamic Type。
3. 失败卡使用独立珊瑚色文字与底色；重试是卡片右侧的单个图标按钮，不显示“重试”文字。
4. 手动重试复用同一 AI 气泡；开始新 Attempt 时删除旧 error/running 投影和失败文案，保留已成功
   step。成功后界面不留下旧失败痕迹。
5. ReAct 模型步骤在没有产生可见增量时最多执行三次 `1/2/4` 秒指数退避重试。错误越过 Loop 并
   向用户展示后，本地和远程路径都进入人工恢复屏障；启动、前台、配置变化和计时器均不再自动释放。
6. 每条已完成 AI 回复的时间右侧以 8 pt 间距放置简洁线框反馈按钮并保持同一水平线。点按后在当前
   消息下方原位展开紧凑反馈编辑器，不创建页面、Sheet 或导航转场；编辑器支持文字、图片、视频与
   1–5 星评分，不展示上下文说明。展开布局完成后自动平滑滚到当前反馈编辑器底部；完整上下文只在
   发送时按消息 ID 定向组装。投递成功后编辑器自动收起；失败保持展开并保留当前草稿和附件。
7. 高位下拉、胸托哑铃划船、单臂绳索下拉、杠铃深蹲和静态保加利亚深蹲均解析到确定的专属离线图；
   本次为 100 个不同动作新增内置图覆盖，目录专属图总数不少于 239。
8. 用户上传动作图永远优先；没有用户上传时，新版内置图优先于旧生成图和旧内置引用。

## 隐私与数据边界

- 逐回复反馈只在用户点按反馈并再次点按发送后出网。自动上下文仅含当前 Turn 的可见提问、可见
  AI 回复、媒体数量、Job/Trace ID、状态、模型名称和不含入参/出参/metadata 的步骤摘要。
- 不自动附带原始图片/视频、位置、API Key、Authorization、Trace context snapshot、模型原始
  input/output、完整日志、健康记录、其他 Turn 或其他 Session。
- 用户在反馈编辑器明确新选的图片/视频沿用 PRD 023 的 10 项、25 MB 与失败保留边界。
- 用户已明确选择远程持续执行且本轮包含直传视频时，设备同时上传有界关键帧作为同一 ReAct 重试
  预算内的降级输入；它们来自同一个用户已发送视频，沿用该远程 Job 的保留与清理策略，不创建第二个 Job。
- 不新增 SwiftData 持久字段、PostgreSQL 表、账户、云同步或后台反馈重试。

## 验收

- 仓库中不得出现原始 `.buttonStyle(.borderedProminent)`；训练计划、带练、反馈、分享、迁移恢复等
  所有原实心按钮统一使用显式前景/背景样式。
- iPhone 模拟器检查浅色/深色的开始训练按钮、聊天紧凑训练卡、失败卡与逐回复反馈入口；验证键盘、
  滚动、安全区、长错误和 Dynamic Type。
- 模型步骤前三次瞬态失败、第四次成功时记录四次请求和 `[1,2,4]` 退避；第四次仍失败则只呈现一次
  用户失败，不建立 Loop 外 retry task 或配置变化唤醒。
- 手动重试后同一 `responseMessageID` 不含 error item；已成功 Tool 卡保留，最终成功回复不含旧错误文字。
- 逐回复反馈 envelope 覆盖评分、可见提问/回复与脱敏步骤摘要，且不超过 5,000 字；叶子反馈按钮
  自行持有原位展开状态，入口只携带消息 ID，上下文延迟到发送时定向读取，编辑器没有“随反馈附带的
  上下文”提示，也不发起页面切换；展开后以当前消息专属底部锚点自动滚入可见区域，收起不强制改变
  阅读位置。投递成功后叶子组件自动收起；失败保持展开并保留文字、评分和附件。
- `ExerciseLibraryTests` 验证至少 239 个专属图、五个指定名称、Bundle 资源存在、用户图优先和无用户图
  时新版内置图优先；所有素材运行时离线读取。
- `make check` 与 `make verify` 通过。
