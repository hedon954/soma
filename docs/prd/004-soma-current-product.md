## 产品定义

Soma 是一款无账户、本地优先、聊天驱动的 iOS 私人身体智能。它通过一个 AI 教练理解用户的训练环境、训练行为、饮食和身体变化，并把用户明确提供或可靠识别的信息转化为可审查的本地记录。

Soma 不以“功能数量”为价值，而以四个闭环为价值：

1. 用户自然表达；
2. Agent 理解并调用确定性工具；
3. 结构化事实进入个人时间线；
4. 用户可以审查、纠错并看到趋势。

## 信息架构

### 教练

- 非结构化身体事实的默认创建入口；训练计划的结构化 GUI 编排例外见 PRD 012；
- 对话按本地 Session 持久化；当前 Session 按数据空间恢复，不因跨天或进入前台自动切换；
  从左边界右滑可打开历史抽屉、新建 Session 或选择旧 Session 继续对话；
- 支持文字、系统语音，以及单次最多十项的多图片、多视频和混合附件；三项起在聊天中按微信式牌组折叠，折叠态按首图方向选择稳定卡片画布，后图在同一画布上缩小、旋转和向右露出，避免极端比例撑乱聊天；显式展开后按各自比例排列并可再次收起，点击任一聊天媒体进入统一全屏查看，图片可缩放、多项可左右切换；
- 支持原生文本选择与划句复制；用户绿色气泡中的选区使用随浅色/深色外观自适应的高对比色，
  不与气泡品牌色混淆；
- 教练回复使用完整 Markdown 渲染，表达以结论、必要依据和下一步为主，避免过程复述、冗长表格和多级标题；
- 健身房达到两个时，输入框上方才提供当前场馆的紧凑切换入口；
- 健身房照片在本轮创建，或用户紧邻下一轮补充场馆名称时，保存到对应 `GymMedia` 档案；
- 发送被接受后收起键盘、清空草稿与附件并滚到消息底部，随后原位等待 Agent 回复；
- 一次 Agent 回复由文字、Skill、Tool 和错误等有序 Event Cards 组成，流式追加并持久保留；
  较长的 Tool 执行结果默认折叠但保留完整内容，用户可在原卡片内展开和再次收起；
- 远程 Agent 每次接收同一 Session 最近十个完整来回；历史用户消息中的图片和视频关键帧
  从本机沙盒按视觉额度重新附加，当前消息媒体优先；
- 页面切换期间继续处理当前消息。
- 每次发送先原子保存 Turn、媒体引用、上下文快照与 `AgentJob`，成功后才清空输入区；
  本地执行到达系统后台租约边界时可恢复，远程持续模式由服务器继续纯远程步骤；
- 输入动作名称片段时，本地展示动作库候选；选中后可再选择最近一条真实训练容量，所有点击
  只修改草稿，用户主动发送后才创建训练记录。

### 进展

- “AI 当前上下文”作为页面首项，优先展示当前健身房、可用器械与最近训练；
- 只有 Agent 成功处理的用户原始表达进入“足迹”，保留文字、媒体、时间和用户授权的位置；
- 训练、饮食和身体的最近记录与完整列表；
- GitHub 风格训练连续性；
- 可拖动、可切换粒度的体重趋势；
- 由训练记录实时派生的训练容量趋势；
- 所有结构化记录均可编辑、保存和左滑删除；健身房、训练、饮食与身体记录中的媒体点击后
  进入放大查看浮层，并可在浮层内独立解绑，不删除聊天原件或系统相册。

### 主屏幕、锁屏组件与系统快捷入口

- 中尺寸 Widget 提供文字、拍照、照片/视频三个快速入口；
- 锁屏为文字、拍照、照片/视频分别提供独立入口，并适配行内、圆形和矩形三种系统位置；
- App Shortcuts 暴露相同三种录入意图；
- 入口打开 Soma 后直接进入教练、聚焦文字输入或呈现对应系统选择器；
- Widget 不直接写业务数据或运行 Agent，所有记录仍通过聊天和固定 Tool Call 创建；
- 锁屏状态下先遵循系统解锁与隐私验证，再进入 Soma，不绕过系统访问相机或媒体；
- 组件不引入 App Group、账户或新的云端数据流。

### 设置

设置按使用频率分层：

1. 个人与训练：身体信息、健身房；
2. 服务：AI 教练、健康数据与设备；
3. 更多：隐私与安全、高级设置；
4. 关于：Soma 版本与产品主张。

低频的演示数据切换、提示词、Skills 和执行日志继续下沉到高级设置。执行日志在开发者
设置内直接可见；固定 Tool 协议不作为设置项展示。

### 动作库、训练计划与带练

- `ExerciseDefinition` 以稳定 ID 串联聊天训练与计划训练，Agent 先读取当前空间完整
  `{id,name}` 列表后由模型完成语义复用或创建；
- 动作详情展示旧聚合训练与新逐组 Session 的统一历史、容量趋势、教练提示、通用主要/辅助
  肌群、用户示范视频和授权/外部指导来源；
- App 包内静默预置常见动作说明、动作示意图和前后人体肌群图；只有用户实际形成的动作才关联
  并显示这些素材，未使用动作不会进入个人动作库或 Agent 名称列表；
- 动作列表左侧显示示意图，详情支持多图、用户上传，以及显式点击后的 AI 图片生成兜底；
  打开详情、记录训练和开始计划不会自动生成图片；
- 计划使用不可变模板版本；开始训练冻结处方到 Session，计划值、AI 建议与实际 Set 分层；
- 计划既可由 Agent 从聊天生成，也可在 GUI 中从当前动作库选择、排序并配置处方后确定性创建；
  两条路径共用稳定动作 ID、验证和不可变版本，不调用模型补齐空值；
- 本地带练状态机负责动作说明、倒计时、确认、休息、暂停、跳过、替换、恢复与确定性总结，
  断网和 Provider 失败不阻断已开始训练；
- 用户可为 Session 显式启用前置摄像头自动录像。首组非热身录第 1 组，首组热身录第 2 组，
  每个动作默认保留一段且麦克风关闭；
- AI 计划优化、动作内容和视频复盘只在用户主动点击时执行。视频复盘通过持久 Job 保存证据、
  局限、输入指纹和可编辑建议。

## 身体信息

个人档案支持：

- 昵称；
- 生理性别；
- 出生年月，而不是需要逐年维护的年龄；
- 身高与参考体重；
- 健身目标；
- 健康备注。

年龄由出生日期动态计算。体态图不只存在于单条聊天附件中，也作为身体记录历史展示，便于长期回溯。

## 训练热量估算

热量估算是可解释、可复现的本地能力，而不是让模型自由心算：

`消耗热量 = MET × 参考体重(kg) × 时长(小时)`

数据优先级：

1. 用户明确提供的训练时长；
2. Apple 健康导入的实际时长与活动能量；
3. 无氧训练缺少时长时，仅为热量估算推算时长。

无氧推算可使用组数、次数、用户明确提供的间歇，以及每次动作约四秒的保守节奏。推算时长必须标记为“估算”，不能回填到训练记录的实际时长字段。缺少体重或训练信息不足时不输出假精确值。

## 外部健康数据

### Apple 健康

在用户明确授权后，只读导入最近一年的：

- 体重；
- 训练；
- 训练活动能量。

外部样本先转换为 Soma 的 `BodyEntry` 或 `WorkoutEntry`，再参与现有列表与趋势，不能维护一套平行的数据模型。

### Keep 与 COROS

- Keep 没有面向普通第三方 App 的稳定公开直连接口；如果 Keep 把数据写入 Apple 健康，Soma 可经 HealthKit 导入。
- COROS 可通过 Apple 健康同步部分体重和训练数据；完整云端直连依赖合作方 OAuth/API 凭据，当前不假设可用。

### 去重和增量

- 每个数据空间、来源和数据流保存独立增量游标；
- 使用外部样本 ID 去重；
- 同步来源删除，避免外部删除后 Soma 仍保留失真记录；
- 重复同步不得重复计入训练容量、连续性或体重趋势。

## 数据真值规则

1. 未提供的数据保持 `nil`。
2. 训练容量只使用有组数、次数和外部重量证据的记录。
3. 体重趋势只使用真实体重值。
4. 热量估算保留 MET、计算时长和“时长是否推算”。
5. AI 的观察、估算和用户明确事实在界面与数据中可区分。
6. 用户可以修改或删除所有由 AI 生成的业务数据。

## AI 平台与降级

- 默认使用用户配置的 OpenAI-compatible Provider，在设备内执行流式 ReAct、本地 Tool 和
  Trace；标准模型 API Key 是本地模式发送和重试的前提。
- “后台持续处理”默认关闭。用户明确开启后，当前消息可经 Soma Server 使用 Soma 管理的
  Provider 凭据执行；每条消息仍可选择“本次仅本机”。
- 本地模式缺少 API Key 时保留草稿与附件并打开 AI 服务设置，不创建失败 Turn 或 Trace；
  远程模式不会上传用户 BYOK。
- 远程服务、协议或认证不可用时，尚未接受的 Job 保留在本地可恢复队列；已经接受的远端 Job
  不并行启动本地副本。需要 SwiftData 的 Tool 明确等待设备。
- 模型或多模态能力错误以可操作语言显示，并保留失败 Trace。
- 失败 Attempt 可以从原始用户消息重试；旧 Trace 保留，成功 Tool 写入跨 Attempt 幂等。
- 数据查询返回稳定业务记录 ID；Agent 可显式更新或删除用户指定的训练、饮食和身体记录。
  跨消息补图/纠错仍由本地多维规则合并，避免模型误用新增工具时制造重复。

## 隐私与边界

- 当前实现无账号、无登录、无 CloudKit；可选远程执行使用每次安装的匿名设备身份，不引入
  用户账户或云端业务数据库。
- 业务数据库和媒体仅保存在 App 沙盒。
- API Key 使用 ThisDeviceOnly Keychain。
- 删除 App 会删除本地数据。
- 远程模型接收本次输入、同一 Session 最近十个来回，以及视觉额度内的标准化图片、视频
  关键帧；百炼中确认支持的 Qwen 模型还可接收不超过 24MB 的稳定视频副本。不读取其他
  Session，沙盒媒体原件不会被移动或删除。
- 位置在首次发送时询问，启用后只在发送时获取一次；远程模型不接收原始坐标。天气只按需向 Open-Meteo
  发送公里级坐标并临时使用，不写入足迹或 Trace。
- 主屏幕/锁屏 Widget 和 App Intent 只传递录入意图，不读取或持久化身体数据。
- 设置提供按年月日组织的饮食/训练开放导出、外部加密自动备份与恢复，以及主动清除个人
  数据；三者不包含或删除系统相册和 Apple 健康源数据。
- Soma 提供一般健身建议，不做医疗诊断。
- 远程模式只上传当前文字、所选图片或视频关键帧和最小上下文；原始训练视频、用户 BYOK、
  完整 SwiftData、Keychain 与原始坐标不上传。终态消费后清理内容，所有内容最长保留 7 天，
  非内容元数据最长 30 天。

## 明确不在当前实现

- 社区、关注、排行榜、课程商城；
- 跨设备业务数据同步；
- Keep/COROS 未获授权的私有 API；
- Agent thinking 展示；
- 用户自定义 Tool、Tool Schema 或输出协议；
- 未部署 Soma Server 时，App 被系统终止后只能在下次打开时恢复本地 Job，不能继续纯远程
  ReAct；部署与运维入口见 [Server README](../../Server/README.md)；
- 通用实时动作计数、任意动作的摄像头自动识别、伤病诊断与未授权第三方课程抓取。
