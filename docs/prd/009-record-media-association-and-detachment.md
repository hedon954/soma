# PRD 009：记录媒体归档与单张解绑

- 状态：已实现，待真机媒体验收
- 日期：2026-07-31
- 关联基线：[PRD 004](004-soma-current-product.md)
- 关联决策：[ADR 0026](../adr/0026-bounded-gym-media-attribution.md)

## 问题

健身房创建可能跨两个 Turn：第一轮上传照片，第二轮只回答场馆名称。当前图片只保存在聊天，
导致健身房档案有器械和环境摘要但没有照片。健身房及训练、饮食、身体详情也只能查看整个
媒体集合，无法单独移除错误或不再需要的照片。

## 用户结果

### 健身房照片归档

- 本轮附带图片并执行 `update_gym` 时，全部图片进入对应 `GymMedia`，首图作为封面。
- Agent 看图后，用户下一轮要求创建健身房或只回答名称时，历史消息明确告诉模型这组图片
  可通过 `media_source=recent_gym_turn` 引用；模型在 `update_gym` 中选择该来源后，上一轮
  图片归入新建或更新后的健身房。
- 只允许 `update_gym` 按模型明确声明使用紧邻上一轮、同一 Session 的图片；隔过其他 Turn
  或跨 Session 时不自动归档，也不向模型暴露本机文件路径。
- Tool 结果明确返回实际保存的照片数量，Agent 不得把无图写入描述成已保存。

### 单张媒体解绑

- 健身房详情的每张照片提供删除按钮和二次确认。
- 训练、饮食与身体详情中的每张照片或视频提供相同的单项移除能力。
- 移除健身房封面后，剩余最新照片自动成为封面；引用该照片的器械缩略图同步更新。
- 移除记录媒体后，`mediaAttachments` 与旧 `imagePath/mediaPath/mediaKind` 兼容字段同步。
- 删除只解除当前业务档案的引用，不删除聊天原件、其他记录引用或系统相册。
- 最后一项媒体移除后，媒体区回到空态，业务记录本身保留。

## 失败与隐私

- 明确引用上一轮照片但无法解析到紧邻图片时，Tool 返回可恢复错误并要求重新附加。
- 不扫描完整聊天寻找“看起来相关”的图片，不跨 Session，也不把历史附件传给其他业务 Tool。
- UI 不暴露沙盒路径；测试和截图只使用虚构媒体。

## 验收

- 先发两张虚构健身房照片，再单独要求创建或回复名称；请求中的紧邻历史消息包含
  `recent_gym_turn` 引用说明，Tool 填写该来源后档案中出现两张照片。
- 插入一个无媒体 Turn 后再回复名称，不自动归档更早照片。
- 健身房删除首图后封面顺延；删除最后一张后封面为空。
- 训练、饮食、身体各从两项媒体中移除一项，剩余顺序不变，聊天原附件仍可查看。
