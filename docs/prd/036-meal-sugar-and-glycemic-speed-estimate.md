## 背景

现有饮食记录可审查热量、蛋白质、碳水与脂肪，但不能回答一餐含多少糖，也不能把精制碳水、纤维、
蛋白质、脂肪和食物形态对消化速度的共同影响整理成可回看的判断。直接给出个体血糖峰值或曲线需要
个人连续血糖等证据，超出照片和文字能支持的范围。

## 用户结果

1. 菜品与整餐都可保存、编辑并导出可空的「总糖」克数；它包含天然糖与添加糖，不冒充添加糖。
2. 证据足够时，整餐显示「较慢／中等／较快」的餐食组成升糖速度估算和简短依据。
3. 估算明确说明实际反应因人而异，不给出血糖峰值、曲线、疾病风险或诊断。
4. 修改菜品或份量后，旧的速度与依据立即失效，直到用户明确编辑或 Agent 重新估算。
5. 未提供或无法可靠判断的糖分、速度和依据保持为空，不补常见值或零。

## 产品规则

- 产品字段叫「总糖」，不叫「添加糖」。只有包装标签或配料等证据足够时，文字说明才可额外讨论
  添加糖；结构化字段始终记录总糖。
- `glycemic_speed` 只能是 `slow`、`moderate` 或 `fast`，必须与非空
  `glycemic_assessment` 成对出现。缺一项时整个评估无效。
- 判断依据只使用当餐可审查的组成证据，例如精制程度、纤维、蛋白质、脂肪、烹饪与食物形态；
  不把总糖克数单独等同于个体血糖反应。
- 菜品仍是营养事实来源。所有菜品都有总糖时整餐总糖由统一求和规则派生；任一缺失则整餐为空。
- 聊天双卡片和饮食详情均展示总糖。速度与依据只在整餐评价区展示，并持续显示非诊断说明。
- 新字段进入本地备份、可读导出、Tool 查询与 Tool 结果；不新增远程身体数据库或新的触发条件。

## 数据与隐私

- 三个整餐字段和菜品总糖只保存在当前本地数据空间，随现有用户主动备份／导出流程流转。
- 远程模式仍只在用户主动发送且明确启用时处理当轮内容；Server 不保存饮食业务事实。
- 日志、测试、文档与 PR 只使用虚构餐食，不含真实健康记录、照片、邮箱或完整 Trace。

## 不在范围

- 不计算个体血糖峰值、时间曲线、胰岛素反应、糖尿病风险或医疗诊断。
- 不接入连续血糖仪，不新增每日糖摄入目标、告警或饮食羞辱性评分。
- 不从「碳水」机械换算「总糖」，也不在证据不足时推断添加糖。

## 验收

- 新建、更新、查询和原位编辑能往返总糖、速度与依据；非法枚举或不成对字段被拒绝。
- 菜品总糖完整时派生求和，缺项时为空；修改菜品后旧评估被清除。
- 备份恢复与开放导出保留全部新字段；旧快照缺字段仍可解码。
- UI 在浅色／深色、Dynamic Type、长依据与 VoiceOver 下可读，并持续展示非诊断说明。
- `make check`、`make verify` 与 `npm --prefix Server run check` 通过。

## 证据依据

- [FDA：Added Sugars on the Nutrition Facts Label](https://www.fda.gov/food/nutrition-facts-label/added-sugars-nutrition-facts-label)：总糖包含天然存在与添加的糖，二者不能混称。
- [JAMA：个体餐后血糖反应预测研究](https://pubmed.ncbi.nlm.nih.gov/30735238/)：相同食物的餐后反应存在个体差异，个体预测需要额外生理因素。
- [Nature Medicine：个体餐后血糖反应差异](https://pubmed.ncbi.nlm.nih.gov/40467897/)：纤维、蛋白质和脂肪等因素的影响也存在显著个体差异。
