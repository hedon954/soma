# PRD 078：残差系数加所选日活动能量

- 状态：已实现；真机数据待验收
- 日期：2026-11-06
- 版本：0.0.32（修订 0.0.31 的总消耗公式，不单独发版）
- 修订自：[PRD 076](076-adaptive-energy-system.md)（总消耗不再使用参考日差额，也不再把日活动能量排除在总量之外）、[PRD 075](075-healthkit-daily-activity.md)（活动能量进入总消耗的方式）、[PRD 000](000-origin-through-0.0.11.md)（全天消耗公式）、[工程契约](../../CLAUDE.md)
- 后续修订：[PRD 079](079-daily-target-deficit.md)（新增摄入目标设置；总消耗公式不变）
- 下游落地：[ADR 0147](../adr/0147-residual-energy-coefficient.md)、[BUG 0068](../bugs/0068-health-activity-cancels-lifestyle-baseline.md)、[验收](../acceptance.md)

## 背景

0.0.30 的总消耗把日活动能量留在观察里，避免和参考日差额里的步行、训练重复计算。结果是当天已经记下的活动能量不改变总消耗。已确认改为：总量使用静息乘一个残差系数，再加上择优后的那一份日活动能量。

## 用户结果

同一套静息和同一个系数下，日活动能量从 100 kcal 变为 400 kcal 时，预估总消耗增加 300 kcal。明细相加等于总量：静息、基准额外消耗（静息 ×（系数 − 1））、活动消耗。活动消耗可以在可靠时拆成训练活动消耗和其余活动消耗；这两项只解释同一份日活动能量，不能再把训练加到总量上。

没有日活动读数时不编造数字，已记录的训练仍留在训练列表里；若训练自身有已知活动能量，且没有日活动读数可包含它，则只把这份已知训练能量计入总量。显式 0 是有效读数。缺少静息资料时不凭活动能量补出全天总消耗。

## 产品规则

- 预估总消耗 = 当日静息 × 残差系数 + 所选日活动能量。
- 系数由独立提供方给出，公式里不写死倍率。当前提供方只返回既有默认数值 1.4，作为初始回退。
- 该系数表示「静息 + 所选活动能量没有覆盖的估算消耗」相对静息的倍率，不是传统全天体力活动水平。不把它宣称为已验证的个人生理系数。
- 不按参考日步行差额扣减，也不按训练时长把训练能量摊进基线。
- 日活动能量只使用已经择优的一份整包。COROS 与 Apple 的活动能量不相加。HealthKit `activeEnergyBurned` 不含静息。
- 训练列表、按日分享继续排除日常活动记录。
- 体重和饮食的动态校准尚未接入系数提供方。以后只替换提供方内部，消费方仍用上面的公式。

## 数据与隐私

不新增持久模型、远程数据流或健康读取类型。仍不读取静息、心率、睡眠或路线。健康事实和派生依据不进入模型、备份、导出或 Server。

## 明确不在范围

- 用体重或摄入反推系数，或声称 1.4 已经是科学验证的残差系数。
- COROS OAuth、MCP、Partner API。
- 把多个来源的日活动能量加总，或把已包含在日活动能量里的训练再加一次。

## 验收

- 同一静息、同一系数下，100 kcal 与 400 kcal 活动能量使总量相差 300 kcal。
- 静息、基准额外消耗和活动消耗相加等于总量；可靠拆分时训练与其余活动消耗相加等于所选日活动能量。
- 所选日活动能量存在时，训练不再叠加；没有读数时不编造，已知训练能量不丢失；显式 0 不回退成训练能量。
- 系数来自提供方。默认是 1.4；换一个提供方取值会改变总量，公式本身没有写死 1.4。
- 两条日常活动记录的活动能量不相加。训练列表和分享仍排除日常活动。
