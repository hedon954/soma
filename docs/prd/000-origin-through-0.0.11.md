## 产品是什么

Soma 是无账户、本地优先、聊天驱动的 iOS 私人身体智能。路径固定为：

```text
自然表达 → 流式 ReAct → 确定性工具 → 可审查记录 → 长期趋势
```

最低系统 iOS 17。四个 Tab 为教练、训练、进展、设置，各自保留导航栈。不提供账户、云端身体
数据库或医疗诊断。

## 用户结果

1. 用文字、照片、视频和语音向教练陈述事实；训练计划可在专用 GUI 编排，但与聊天共用同一数据
   与验证边界。
2. AI 写入的训练、饮食、身体、健身房记录都能回看、编辑和删除；未提供的字段保持为空。
3. 缺少 API Key 时消息仍落盘暂存，恢复后按 FIFO 补偿，不丢用户输入。
4. 可从动作库组建当前训练计划，一步开始带练；倒计时只取景，开组后放大录制，计划结束立即分享
   并回到训练主页。
5. 可选远程持续执行默认关闭；业务记录仍由本机固定 Tool 审查落地。
6. 演示与个人数据空间隔离；导出、加密备份与个人清除可用。
7. 每条已完成 AI 回复都能原位提交文字、媒体和 1–5 星反馈，并只附带当前 Turn 的有界脱敏上下文。

## 产品规则

### 教练与会话

- 聊天是非结构化事实的默认创建路径。输入区只保留加号、文本、语音和发送。
- Session 按自然日解析；用户可继续旧会话、长按标题改名、左滑删除该会话聊天图，不删除业务记录。
- 成功来回后可异步生成标题；手动标题优先。消息底部单行时间，用户消息可带位置。
- Session 倒序分页读取最近 10 条及更早哨兵；向上到顶后每次追加 10 条并保持阅读位置。短内容顶部
  对齐，超过一屏时首次定位到底部，用户主动阅读历史后不被流式更新持续抢回。
- 快捷按钮完整 CRUD，各自持有工具白名单；未选按钮时注册当前协议全部 Tool，选中后只注册白名单。
  Skill 只提供专业方法，不是动态工具。
- AI 正文用本地受控 Markdown；记录卡跟在产生它的步骤之后。饮食原位审查分为可编辑菜品清单与
  只读派生汇总。
- 一次 AI 回复始终是一条消息和单一连续文本面；内部流式分块不泄漏成多条消息。无换行长段落
  的尾部成本必须有界，完成态 Markdown 在后台准备；流式期间跟随当前回复的真实底部。
- AI 回复的时间与反馈入口固定在同一底部元信息行；反馈编辑器在当前消息下方原位展开，不创建
  页面或 Sheet，成功后收起，失败保留草稿。
- 用户可主动中断正在执行的 Agent；中断与可见失败共用同一气泡和人工重试屏障，已完成 Tool
  写入继续如实保留。
- Agent 处理中发送键原位变为暂停；已完成 Tool 仍可审查，暂停后沿用人工重试边界。执行日志与反馈
  各保留独立 44 pt 触达区，图标在相邻槽内相向对齐。
- App 回前台保留当前 Session、滚动与草稿，不重新选择当天会话；跨日发送仍通过发送前门禁。
- 有序混合媒体贯穿聊天、Agent 与审查；点击进入只读全屏。

### 记录真值

- 缺失值为 `nil`，不补常见值。容量只使用完整有效的组数 × 次数 × 外部重量。
- 热量用本地 MET；推算时长只用于热量并保留推算标记。
- 训练、饮食、身体的 create 每次新增；纠正只走 update。业务身份为本机 Int64。
- 饮食营养从菜品事实派生：全部有值时显示精确总计，部分有值时显示已知小计；仅修改相同单位的
  份数时按比例调整已有估算，其他字段互不猜测或联动。
- 不保存图片无法稳定识别的总糖；证据足够时可成对保存升糖速度与依据，不冒充个体血糖预测。
  餐次优先尊重用户明确表达，否则按本地发生时刻确定早餐、午餐、下午点心、晚餐或加餐。
- 建议食用顺序只排列实际识别到的食物；证据不足时省略，菜品或份量变化后清空。记录详情可编辑，
  Tool 查询、备份与导出保留该值；旧记录与备份缺项按空值恢复。
- 外部健康数据经用户授权的 Apple 健康读取，先归一化再用外部 ID 与游标去重。

### 训练计划与带练

- 动作有稳定身份与内置内容；侧别和按次数/按时长归动作定义。计划只保留当前状态，不维护业务
  版本链；已开始 Session 使用不可变处方快照。
- 训练记录的次数或时长目标以动作库定义为准，旧记录不得反向覆盖动作定义。
- 教练基于当日原始训练生成计划时，同时建立一次已完成 Session；原始训练记录只通过关系连接，
  不复制，删除该 Session 也不删除原始记录。
- 计划动作用独立逻辑组保存类型、目标、重量与备注；计划组间歇与左右换侧间歇归动作配置，开始
  Session 时才编译到逻辑组。最后一组不生成组间歇，实际休息证据仍逐组保存。
- 带练确定性状态机：一步选择录像策略，计时/休息自动推进，动作记录先于 Session 完成。
- 倒计时小窗取景，开组后放大录制；预览与历史缩略 aspect fill。相机完整 activation 有界，
  预览宿主所有权、朝向锁定与失败可见性必须保留。
- 计划总览保留动作库主要/辅助肌群身份。专属离线动作图不少于 100。

### Agent

- 原生流式 Tool Calling；Tool Schema 系统所有，不能被用户提示词覆盖。
- 发送先原子保存 Turn、媒体、上下文与 Job。同气泡 step 检查点续跑不递增 attemptNumber。
- 活动执行预算与业务时间解耦；等待用户、网络或前台不计时。文字、图片、视频总预算分别可在
  3–60 分钟内配置，默认 3/5/10 分钟；首增量门禁保持 20/40/60 秒。
- 尚无可见增量的瞬态模型步骤最多执行三次 1/2/4 秒退避；错误一旦展示，本地和远程都进入人工
  恢复屏障，只能由用户释放，后续消息继续受 FIFO 屏障。
- 本轮 Agent 身体上下文只使用称呼、生理性别、动态年龄、身高、最新有效体重及日期、目标和限制；
  不维护独立参考体重。
- 本机与远程使用设备生成的版本化模型输入；远程进入 `waitingForDevice` 等本机执行固定 Tool。
- 十轮外对话在 Loop 前滚动压缩，可审查、可回退。

### 界面与系统入口

- 频率优先的黑白双主题；彩色只用于语义图标与数据。实心主按钮在浅深主题使用明确反色前景；
  失败卡为珊瑚色并把人工重试收在右侧图标。教练与任一根 Tab 的再次点按不产生副作用；训练、
  进展、设置仅在详情页再次点按时回根，普通 Tab 切换保留各自导航栈、草稿和滚动位置。
- 进展趋势通过有界本地快照呈现，单项数值能回到实际记录、来源或公式；不集中堆叠说明，也不
  预测个体未来减重速度。当前周期层级与消耗估算分别由后续 PRD 054、053 定义。
- 异步进展快照有明确加载、成功和失败状态；失败可重试，刷新失败保留旧内容。同一数据空间的
  后台写入可原位失效，其他数据空间不触发无关刷新；旧请求不得覆盖新 revision。
- 全产品 Switch 使用系统外形和统一开启状态色，浅深主题均能辨认，且不能只靠颜色表达状态。
- 免费签名阶段 Widget 只提供静态快速记录与锁屏入口，不使用 App Groups。
- 设置页末端可直接发送应用内反馈；个人阶段经本机 QQ SMTP 投递到固定维护者邮箱。
- 动作图显示优先级为用户上传、新版内置、生成图、占位；专属离线动作图不少于 239，升级不能
  覆盖用户素材。

## 数据与隐私

- 业务库、原始媒体和用户 API Key 默认留在设备；Keychain 为 ThisDeviceOnly。
- 远程执行需一次性明确授权；服务器不是身体业务事实源。
- 测试、日志、Issue 不得含真实身体照片、健康记录或密钥。
- 逐回复反馈只在用户主动发送时出网；自动上下文限当前 Turn 的可见问答和脱敏 Job/Trace 摘要，
  禁止附带原消息媒体、位置、密钥、完整日志和其他会话。

## 明确不在范围

- 账户系统、云同步身体库、任意代码工具、展示模型 thinking。
- 情境化动态主屏组件（暂缓，待 App Groups Team）。
- 把 Keep/COROS 做成独立直连（无稳定授权时只走 Apple 健康）。

## 工程行为边界

- 行为保持拆分不得改变 Tool Schema、Job/Event、SwiftData 字段、LLM 契约或 Server HTTP API。
- 对话、训练、媒体和设置实现按现有能力目录维护；不引入平行 DTO、DDD application/use-case/
  repository 层或新的 `AppServices` 上帝对象。
- 数据访问查询优先：纯数量使用 `fetchCount`，明细把业务键、时间、状态、排序和 `fetchLimit`
  下推到数据库；Job 领取、业务去重和 HealthKit 去重不得整表读入内存。
- 最低系统保持 iOS 17，不绕过 SwiftData 直改 SQLite；物理 `#Index`、提高最低系统或引入版本化
  schema 必须单独决策迁移与回滚。PostgreSQL 索引只经只向前 migration 修改。
- 活 PRD/ADR 固定为压缩起点加最近三个营销版本；发布时把滑出版本原文归档，并把仍有效状态合并
  进压缩起点。归档保留在 Git，Agent 默认不读取。
