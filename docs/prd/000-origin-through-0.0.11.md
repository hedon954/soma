## 产品是什么

Soma 是无账户、本地优先、聊天驱动的 iOS 私人身体智能。路径固定为：

```text
自然表达 → 流式 ReAct → 确定性工具 → 可审查记录 → 长期趋势
```

最低系统 iOS 17。四个 Tab 为教练、训练、进展、设置，各自保留导航栈。不提供账户、云端身体
数据库或医疗诊断。

## 用户结果

1. 用文字、照片、视频和语音向教练陈述事实；训练课程可在专用 GUI 编排，但与聊天共用同一数据
   与验证边界。
2. AI 写入的训练、饮食、身体、健身房记录都能回看、编辑和删除；未提供的字段保持为空。
3. 缺少 API Key 时消息仍落盘暂存，恢复后按 FIFO 补偿，不丢用户输入。
4. 可从动作库组建当前训练课程，一步开始带练；倒计时只取景，开组后放大录制，计划结束立即分享
   并回到训练主页。
5. 可选远程持续执行默认关闭；业务记录仍由本机固定 Tool 审查落地。
6. 演示与个人数据空间隔离；导出、加密备份与个人清除可用。
7. 每条已完成 AI 回复都能原位提交文字、媒体和 1–5 星反馈，并只附带当前 Turn 的有界脱敏上下文。

## 产品规则

### 教练与会话

- 消息与没有所属回合的业务记录按实际发生时间排列。已有回合卡片的记录只出现一次。

- 会话目录每次读取 14 个 Session，按更新时间倒序与身份稳定排序；已加载页跨抽屉、会话和 Tab 保留。
  保存只局部合并变化，删除移除身份；下一页排除已缓存身份，不递增 offset 或重读前缀。切数据空间清空，读取失败保留已有页并可重试。
- 必要追问或确认使用 ask_user_questions，每轮 1–3 题、每题最多 6 个独占整行的选项；普通选项点击即发送，
  可按需要提供自填。确定且已授权的选项可绑定现有工具与完整参数，由本机确定性 Job 执行，不再调用模型。
  新用户消息使旧问题失效；历史按钮、重复点击与迟到结果不得产生副作用。提问成功结束本轮，不阻塞 FIFO。
  选项权限不能超出当前工具曝光范围；未知事实仍保持未知，不为已明确授权且事实充分的操作重复确认。

- 聊天是非结构化事实的默认创建路径。输入区只保留加号、文本、语音和发送。
- Session 按自然日解析；默认标题为业务时区 `MM月dd日 - 周X`。用户可继续旧会话、长按标题改名、
  左滑删除该会话聊天图，不删除业务记录。手动标题优先。消息底部单行时间，用户消息可带位置。
- 入队即预建同一响应气泡；等待、失败与人工重试都在原位复用，不新建第二条回复。
- Session 倒序分页读取最近 30 条及更早哨兵；向上到顶后每次追加 30 条并保持阅读位置。短内容顶部
  对齐，打开 Session 停在最后一条消息末尾，用户主动阅读历史后不被流式更新持续抢回。
  单次再选教练保持原位，只有系统双击回到尾部。
- 快捷按钮完整 CRUD，各自持有工具白名单；未选按钮时注册当前协议全部 Tool，选中后只注册白名单。
  Skill 只提供专业方法，不是动态工具。选中后 System 只保留身份与安全契约，信封只含本轮 Skill，
  默认不暴露 `load_skill`。点选且输入框为空时填入该按钮建议句，已有文字不覆盖。
- 听写音频留在设备。未确认片段只作输入框预览，确认后才追加草稿；不保存听写前基线，过期回调
  不覆盖手改。iOS 26 在设备与语言支持时用系统本地 SpeechTranscriber，旧系统用严格本地识别，
  不把录音送上云端。
- 用户发送或明确引用的视频以完整文件交给模型，不自动换成关键帧；媒体页点击后自动播放。
  模型明确拒绝视频输入时，自动改用覆盖全片的有限画面再试一次，并说明改用了多少张画面。
  单个视频至少 8 张、大约每秒 2 张、最多 24 张；多个视频共享这 24 张，每个至少 8 张，超过 3 个须分开发送。
  单张最长边 768 像素，回退画面合计不超过 8 MiB。断网、超时、限流、授权或已经开始输出时不回退。
  画面准备失败或图片也不被接受时保留原视频并说明下一步。失败提示只写可以确认的原因、结果是否保留和下一步，
  不展示服务商原文、内部标识或调用栈。
- AI 正文用本地受控 Markdown；记录卡跟在产生它的步骤之后。饮食原位审查分为可编辑菜品清单与
  只读派生汇总。
- 一次 AI 回复始终是一条消息和单一连续文本面；内部流式分块不泄漏成多条消息。无换行长段落
  的尾部成本必须有界，完成态 Markdown 在后台准备；流式期间跟随当前回复的真实底部。
- AI 回复的时间与反馈入口固定在同一底部元信息行；反馈编辑器在当前消息下方原位展开，不创建
  页面或 Sheet，成功后收起，失败保留草稿。
- 用户可主动中断正在执行的 Agent；中断与可见失败共用同一气泡和人工重试屏障，已完成 Tool
  写入继续如实保留。
- Agent 处理中发送键原位变为暂停；已完成 Tool 仍可审查，暂停后沿用人工重试边界。执行日志与反馈
  各保留独立 44 pt 触达区，图标在相邻槽内相向对齐。
- App 回前台先画出缓存首帧，保留当前 Session、滚动与草稿，不重新选择当天会话；恢复工作在首帧
  之后可取消执行。跨日发送仍通过发送前门禁。
- 快捷相机由根层单一状态机独占展示；重复 URL 在未完成阶段幂等，后台或锁屏结束当前请求。
- 有序混合媒体贯穿聊天、Agent 与审查；点击进入只读全屏。

### 记录真值

- 缺失值为 `nil`，不补常见值。容量只使用完整有效的组数 × 次数 × 外部重量。
  训练工具在用户没有说明外部重量或非最后一组间歇时写入 0：0 kg 表示自重，0 秒表示没有休息。
- 教练上下文和跨轮引用使用本机 Int64 `record_id`、`exercise_id`、`program_id`、`session_id`。
- 热量用本地 MET；推算时长只用于热量并保留推算标记。聊天训练卡和训练详情的预计消耗可编辑；
  清空后按原公式重算。用户在文字或图片明确给出训练热量时，创建与修改均采用用户值；未提供才用公式。
- 逐组运动时长按秒存储，界面按「x时x分x秒」省略为零的单位；输入接受「30分」或裸秒。
- 训练、饮食、身体的 create 每次新增；纠正只走 update。业务身份为本机 Int64。
- 饮食营养从菜品事实派生：全部有值时显示精确总计，部分有值时显示已知小计；仅修改相同单位的
  份数时按比例调整已有估算，其他字段互不猜测或联动。
- 不保存图片无法稳定识别的总糖；证据足够时可成对保存升糖速度与依据，不冒充个体血糖预测。
  餐次优先尊重用户明确表达，否则按本地发生时刻确定早餐、午餐、下午点心、晚餐或加餐。
- 日摄入明细显示餐次文字前缀和固定双主题配色；未知热量写未估算，不能与真实 `0 kcal` 混淆，
  明细不重复卡面已有汇总。
- 建议食用顺序只排列实际识别到的食物；证据不足时省略，菜品或份量变化后清空。记录详情可编辑，
  Tool 查询、备份与导出保留该值；旧记录与备份缺项按空值恢复。
- 用户连接 Apple 健康后，个人空间只读步数、步跑距离和活动能量。每个自然日保存一条活动记录。
  可优先使用 Apple、COROS 或步数较大的来源。三项指标取自同一来源，保留各自的缺失值与真实零值。
  日常活动在进展中单独列出，从训练列表和训练分享中排除。
- 个人空间可只读健康体重和体脂。每项保留其测量时间和来源，读权限拒绝或无结果时保留已导入值。
  健康同步只维护导入记录。按日合并及区间展示规则见 [PRD 080](080-healthkit-body-mass.md)。
- 饮食记录是否完整、生活活动和校准依据可逐次审查。只有用户明确提供的生活事实才进入计算。

### 训练课程与带练

- 课程描述一次训练处方。计划从锚定日开始循环，按天排列动作、课程、已有计划或休息日。
  拒绝循环引用、缺失内容、空周期和超过 14 天的组合。可在次日补练，错过完整周期后重新确定起点。
  开始训练时固定本次处方快照，之后修改课程只影响未来训练。
- 教练可以提问并起草计划。用户可单选、多选或自填，在编辑器确认后才保存。训练页的最近训练每页 14 条。

- 动作有稳定身份与内置内容；侧别和按次数/按时长归动作定义。计划只保留当前状态，不维护业务
  版本链；已开始 Session 使用不可变处方快照。
- 动作库按「全部动作、身体部位及主要肌群、动作类型」浏览；动作类型由既有模式确定性映射，
  名称搜索与分类路径取交集。未知标签保持未标注，不猜测器械或难度，也不改写动作定义。
- 训练记录的次数或时长目标以动作库定义为准，旧记录不得反向覆盖动作定义。
- 教练基于当日原始训练生成计划时，同时建立一次已完成 Session；原始训练记录只通过关系连接，
  不复制，删除该 Session 也不删除原始记录。
- 计划动作用独立逻辑组保存类型、目标、重量与备注；计划组间歇与左右换侧间歇归动作配置，开始
  Session 时才编译到逻辑组。最后一组不生成组间歇，实际休息证据仍逐组保存。
- 训练 Tool 使用 Schema v4：目标类型、侧别、逻辑组、effort 与逐组间歇。热量用发生时点前最近
  体重与完整证据；真实时长优先，否则每次约 4 秒加已记录间歇并标推算。缺事实保持 `nil`。
- 带练页面只渲染按稳定 ID 构建的不可变快照，不持有 Session/Performance/Set/Effort 对象。
- 准备动作页紧凑展示本次待练分组、次数或时长、重量与动作级间歇，主操作固定可见。只有尚未开始、
  没有实际数据或录像的动作可以调整或替换；只改本次 Session 处方快照，取消保持原状，不回写课程
  与动作库。替换列表只用不可变候选，按稳定 ID 回当前 Context 获取；缺失历史保持空，不沿用其它动作目标。
- 带练确定性状态机：一步选择录像策略，计时/休息自动推进，动作记录先于 Session 完成。
- 倒计时小窗取景，开组后放大录制；预览与历史缩略 aspect fill。相机完整 activation 有界，
  预览宿主所有权、朝向锁定与失败可见性必须保留。
- 计划总览保留动作库主要/辅助肌群身份。专属离线动作图不少于 100。
- 训练分享固定白纸黑字与橙黄色主视觉，突出大号容量和可审查的合并组次；图像独立于 App 双主题，
  原生分享弹层仍适配双主题。导出宽 440 pt、高至少 956 pt，短会话铺满纸面，内容超出时才加高。

### Agent

- 原生流式 Tool Calling；Tool Schema 系统所有，不能被用户提示词覆盖。
- Tool 数字参数按注册 Schema 归一化无单位数字与简单分数；无法确定的值不猜测、不写入。
  仍不合法的参数以带字段、预期类型和 `retryable` 的 `role: tool` 结果返回，同一 Loop 内由模型修正。
- 发送先原子保存 Turn、媒体、上下文与 Job。同气泡 step 检查点续跑不递增 attemptNumber。
- 活动执行预算与业务时间解耦；等待用户、网络或前台不计时。文字、图片、视频总预算分别可在
  3–60 分钟内配置，默认 3/5/10 分钟；首增量门禁保持 20/40/60 秒。
- 尚无可见增量的瞬态模型步骤最多执行三次 1/2/4 秒退避；错误一旦展示，本地和远程都进入人工
  恢复屏障，只能由用户释放，后续消息继续受 FIFO 屏障。
- 本轮 Agent 身体上下文只使用称呼、生理性别、动态年龄、身高、最新有效体重及日期、目标和限制；
  不维护独立参考体重。
- 本机与远程使用设备生成的版本化模型输入；远程进入 `waitingForDevice` 等本机执行固定 Tool。
- 连续会话保留最近 30 个完整来回；轮数超过 30 或历史文本超过 30,000 tokens 才压缩，恰好达到门槛不压缩，最新单轮不切半。
  摘要只覆盖实际移出的来源，带时间、指纹与范围，修订、删除或重叠后重建；不可用时用有界确定性摘要，原聊天与媒体仍留本机。
- 相对日期绑定原 Turn 的发送时间与时区，排队和重试保留原语境与成功写入。首次执行在前序 FIFO 写入后观察状态，
  恢复保留冻结的 Prompt/Skill/Tool 配置，更改从下一轮生效；历史授权、摘要和工具文本不得扩大本轮权限。
  稳定上下文段保留原生 Tool 配对与输入前缀；413 与 token 超限要给恢复提示，不重复成功工具，不承诺供应商缓存命中。

### 界面与系统入口

- 月、年训练明细按日期及同日发生时间倒序；趋势图保持时间正序，日、周与身体记录顺序不变。

- 频率优先的黑白双主题；彩色只用于语义图标与数据。实心主按钮在浅深主题使用明确反色前景；
  失败卡为珊瑚色并把人工重试收在右侧图标。教练与任一根 Tab 的再次点按不产生副作用；训练、
  进展、设置仅在详情页再次点按时回根，普通 Tab 切换保留各自导航栈、草稿和滚动位置。
- 进展按日、周、月、年查看历史。首次进入默认今天的日视图；手动周期在切 Tab 后保留。日看当天
  记录，周看训练频率，月看容量与体重变化，年看按月积累。点图表不切换周期。
- 全天消耗 = 当日静息 × 残差系数 + 所选日活动能量。系数由独立提供方给出，初始回退为既有默认数值 1.4，
  表示静息与所选活动能量未覆盖的估算消耗，不是传统全天活动水平。当前版本训练项的计算见 [PRD 081](081-training-energy-in-total.md)。缺少活动读数时保留未知。
  不读取设备静息能量。累计缺项按 0 加总并保留未知数；缺少全天必要资料时不显示人体消耗为 0。
  日列表每条训练同时给出容量与已估算热量。
- 减脂与增肌减脂共用目标缺口，默认 400 kcal，清空后恢复默认。超过 800 kcal 时显示非阻塞提醒。
  推荐摄入为预估总消耗减目标缺口，仍可摄入为推荐量减已记录摄入，两者下限均为零。
- 日页底部写当前热量缺口和仍可摄入。周、月只累计已结束、且同一天同时有已记录摄入和可估算消耗的日期；
  没有饮食记录、热量缺项、无法估算消耗和未来日期不参与。显式记录的 0 kcal 有效。没有有效日期时显示待估算，不显示 0。
  缺口可以是负值，表示盈余。缺口基于已记录摄入，不能当成全天饮食已经记全。
- 日页「饮食与能量」按事实卡 → 营养环 → 明细：顶部写已记录摄入与预估总消耗；主热量环心写
  已摄入／推荐摄入 kcal，不写还可摄入或完成百分比；下排蛋白质／碳水／脂肪对照克数。点按环打开
  对应分项，不重复卡面汇总。周、月、年只保留日均与图表，不展示营养环；点图不切换周期。
- 能量依据用紧凑数值列表；公式、来源和诊断在计算明细。摄入与总消耗可点开彩色分项浮层。
  单项数值能回到实际记录、来源或公式；不集中堆叠说明，也不预测个体未来减重速度。
- 异步进展快照有明确加载、成功和失败状态；失败可重试，刷新失败保留旧内容。同一数据空间的
  后台写入可原位失效，其他数据空间不触发无关刷新；旧请求不得覆盖新 revision。
- 全产品 Switch 使用系统外形和统一开启状态色，浅深主题均能辨认，且不能只靠颜色表达状态。
- 免费签名阶段 Widget 只提供静态快速记录与锁屏入口，不使用 App Groups。主屏幕快速记录组件
  在浅色、深色和着色模式下都保持标题与入口可读。
- 设置页末端可直接发送应用内反馈；个人阶段经本机 QQ SMTP 投递到固定维护者邮箱。失败区分
  未配置、授权失效和网络拦截，蜂窝拦截时提示改用 Wi-Fi；成功先打钩再收起。
- 动作图显示优先级为用户上传、新版内置、生成图、占位；专属离线动作图不少于 239，升级不能
  覆盖用户素材。

## 数据与隐私

- 健康事实及派生依据仅在本机使用，排除于教练批量历史、应用备份和导出。个人库采用完整文件保护并排除系统备份。
- 业务库、原始媒体和用户 API Key 默认留在设备；Keychain 为 ThisDeviceOnly。
- 远程执行需一次性明确授权；服务器不是身体业务事实源。
- 测试、日志、Issue 不得含真实身体照片、健康记录或密钥。
- 逐回复反馈只在用户主动发送时出网；自动上下文限当前 Turn 的可见问答和脱敏 Job/Trace 摘要，
  禁止附带原消息媒体、位置、密钥、完整日志和其他会话。

## 明确不在范围

- 账户系统、云同步身体库、任意代码工具、展示模型 thinking。
- 情境化动态主屏组件（暂缓，待 App Groups Team）。
- 厂商云同步、向 Apple 健康写入数据，以及读取静息能量、心率、睡眠和路线。

## 工程行为边界

- 行为保持拆分不得改变 Tool Schema、Job/Event、SwiftData 字段、LLM 契约或 Server HTTP API。
- 对话、训练、媒体和设置实现按现有能力目录维护；不引入平行 DTO、DDD application/use-case/
  repository 层或新的 `AppServices` 上帝对象。
- 数据访问查询优先：纯数量使用 `fetchCount`，明细把业务键、时间、状态、排序和 `fetchLimit`
  下推到数据库；Job 领取和业务去重不得整表读入内存。
- 最低系统保持 iOS 17，不绕过 SwiftData 直改 SQLite；物理 `#Index`、提高最低系统或引入版本化
  schema 必须单独决策迁移与回滚。PostgreSQL 索引只经只向前 migration 修改。
- 活 PRD/ADR 固定为压缩起点加最近三个营销版本；发布时把滑出版本原文归档，并把仍有效状态合并
  进压缩起点。归档保留在 Git，Agent 默认不读取。

- 发布前使用与发布工作流一致的 Xcode 完成构建与测试；复杂表达式拆成明确中间值，避免云端类型检查超时。
