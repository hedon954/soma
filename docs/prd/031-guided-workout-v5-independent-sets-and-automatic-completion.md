## 背景

v0.0.6 已拥有计划版本、确定性带练、三种录像策略、动作终态训练记录投影、Int64 业务身份与
动作关系，但主路径仍有四类断裂：

1. 点击“开始训练”后还要进入准备页、展开录像选项、选择策略并再次点击开始；
2. 计划处方只保存动作级统一组数、次数、重量和间歇，无法真实表达左右、时长以及各组差异；
3. 休息归零和最后一组结束仍要求额外确认，计划执行与动作记录的完成顺序不够明确；
4. 系统提前结束录像后，Camera、Coordinator 和 View 对同一次请求存在多个终态与警告源，可能
   先后提示两次失败，甚至把系统实际成功保存的视频当作失败删除。

本版本把“用户眼中的一组”与“左右实际执行”分层，同时减少开练和收尾操作。它不引入账户、
服务器训练事实、自动姿态识别或模型生成的实时控制。

## 用户结果

1. 点击“开始训练”后直接选择“每个动作录第一组”“每一组都录”或“不录像”，选择后立即开练。
2. 不论初始策略如何，带练主界面始终保留可发现的录像按钮，用户可以随时录制当前或下一次执行。
3. 每个动作在动作库统一配置全身 / 左右分开 / 只左边 / 只右边，以及按次数或按时长；左右分开时
   固定先左后右。计划组和训练记录不再各选一次。
4. 每个逻辑组只编辑该动作定义下有意义的参数（次数或秒数、按侧别有效的重量、热身/工作、间歇
   和备注），不以动作未提供的字段补成常见值。
5. 计时组到期自动完成；左右间歇和组间间歇归零后自动进入下一次执行的三秒倒计时。
6. 顶部进度先按动作分大段，再按该动作逻辑组分小段；左右分开组能表达完成一侧和完成两侧。
7. 下一动作语音除名称外，说明组数以及每组次数或秒数；各组不同时逐组摘要。
8. 最后一次执行完成后，Soma 自动保存动作记录、完成计划执行并进入本地分享预览，不要求再次
   点击“保存并结束”。
9. 每个已实际完成的动作形成一条可编辑、可删除的训练记录；一次计划执行由这些动作记录与保留
   跳过、恢复、录像等证据的 Session 共同组成。
10. 动作记录与计划执行都显示本地热量估算；缺少有效参考体重时明确引导填写，但不阻断训练、
    不写入 `0 kcal`，也不自动改写历史。

## 已锁定语义

- “每个动作录第一组”指每个动作的首个 **工作逻辑组**，跳过所有热身组。
- `.both` 的左右执行合计为一个逻辑组，固定顺序是左侧、左右间歇、右侧；左右重量、实际结果
  和录像分别保存。
- `.none` 表示动作无需拆分左右，不代表缺失值；`.left/.right` 只创建对应一侧执行。
- 每个逻辑组严格选择按次数或按时长。次数和秒数不能同时有效，也不能用常见值补空。
- 每组处方完全独立。编辑器可以复制上一组，但复制结果是新的独立数据，不形成共享默认值。
- 新动作仍停留在明确的“准备本动作”阶段，避免用户还未换器械就自动开组。
- 本地分享预览不是系统分享。只有用户在预览页点击“分享”后，才打开系统分享面板。

## 产品规则

### 计划详情与概览

计划详情首屏按以下顺序展示：

1. 无标题、完整块状、可点击编辑的计划概览；
2. 根据动作肌群与逻辑工作组确定性生成的训练效果总览；
3. 动作列表；
4. 默认折叠的历史、统计与版本信息。

原“目标”迁移为计划级 `overview`；不再展示“目标”“当前模板”两个标题行。模板名称、版本和
安排提示继续作为版本与调度事实保存，但不占用计划首屏。

### 独立逐组处方

- `ExerciseDefinition` 保存 `laterality` 与 `targetKind`；计划动作编辑器可以改这两项，但写入动作
  本身，不在每组再选。
- 每个 `TemplateSetPrescription` 独立保存顺序、`warmup/working`、从动作复制的目标类型、次数或
  秒数、逐侧重量、左右间歇、组后间歇与可选备注。
- `.both` 显示左右重量与左右间歇；其他侧别只展示有意义的重量输入。
- GUI 默认把连续相同组收成一句，例如 `热身 1×8次 · 工作 4×8次`。用户可以改这一批的组数和重量；
  要改其中一组时再展开。收起编辑仍写入独立 `TemplateSetPrescription` 行，不引入共享默认值，
  也不把未提供的字段补成常见值。
- 支持逐组新增、复制、删除和排序。删除最后一个有效组后不能开始训练，并提供返回编辑的入口。
- 训练效果按逻辑工作组聚合；`.both` 不因拥有两个原子执行而把同一逻辑组重复加权。
- 本版不增加 RPE/RIR、节奏、距离、配速、坡度、阻力或自动递增规则。

### 一步开始训练

- 点击计划页“开始训练”直接显示三项系统操作，不进入第二个准备表单。
- 用户选择任一录像策略后立即创建不可变 Session 快照并进入首个动作介绍。
- 缺动作、没有有效组、目标类型与目标值冲突等处方错误在计划页阻断，并引导编辑。
- 缺器械、未知重量或缺参考体重是非阻塞提示；不能通过额外开始页增加摩擦。
- 初始选择只决定自动录像策略，不取消用户之后主动录像的能力。

### 逻辑组、原子执行与自动推进

- `WorkoutSet` 表示用户看到的逻辑组；`WorkoutEffort` 表示一次 `none/left/right` 原子执行。
- `.both` 编译为同一 Set 下的 left、right 两个 Effort；其余侧别只有一个 Effort。
- 次数组由用户点击完成；计时组根据持久截止时间到期自动写入实际秒数并完成。
- 左右间歇与组间间歇结束后自动进入现有三秒开组倒计时，不再显示“开始下一组”。
- 暂停冻结倒计时；恢复、View 重建、重复 tick、前后台切换或重启只能提交一次状态转换。
- 跳过当前 Effort 不伪造实际数值；`.both` 仅完成一侧时保留部分完成证据。

### 分段进度与语音

- 顶部进度每个动作占一个等宽大段，大段内按逻辑组数量切分。
- 普通组完成后小段全填充；`.both` 完成左侧后半填充、完成右侧后全填充。
- 当前、完成、跳过和失败状态同时使用形状、图标或可访问性文本，不只依赖颜色。
- UI、语音和 Tool 摘要共用确定性处方 formatter：
  - 参数统一：“下一个动作：深蹲，3 组，每组 10 次。”
  - 计时统一：“3 组，每组 30 秒。”
  - 热身与工作不同：“热身 1 组 8 次，工作 4 组每组 8 次。”
  - 参数不同：“3 组：12 次、10 次、8 次。”
  - `.both` 追加“左右各做，左侧先开始”。
  - 计划列表用同一套收纳规则，并带上有值的重量与间歇。
- 同一阶段和同一秒仍只播报一次，进入新阶段取消过期语音。

### 录像策略、主动录像与失败恢复

- 自动策略为 `disabled / firstWorkingSetPerExercise / everySet`，持久值继续兼容既有 wire 值。
- 主界面始终展示录像按钮，不隐藏在 `…` 菜单：
  - Effort 进行中点击立即开始或停止；
  - 倒计时、休息或动作介绍时点击，表示下一 Effort 开始录像；
  - 权限拒绝时按钮仍可见，并提供系统设置入口或继续不录像。
- 每次自动或手动请求建立独立 attempt，绑定唯一目标 Effort。attempt 只能终结为保存、失败或取消
  一次；同一 attempt 最多投影一个用户警告。
- attempt 必须在权限、配置、Capture Session 启动和写文件请求之前建立；用户决定权限的等待与系统
  机器阶段分开表达，权限返回后的配置、`startRunning()`、连接验证和写文件启动都必须有有限终态。
- 用户明确选择自动录像后，在动作介绍或开组倒计时期间执行可见的 camera-ready preflight；选择
  “不录像”时继续不占用相机，直到用户点击常驻录像按钮。请求权限、启动相机、已就绪、录像中和
  不可用都必须在执行页可见，不能只在真正写文件时出现取景器。
- 系统提前结束、App 后台、运行中断和用户停止都必须清除活动 attempt。再次 stop 是幂等消费，
  不能制造第二个失败。
- 系统错误携带“录像实际成功完成”标记且文件有效时必须保留视频；不能只因 `error != nil` 删除。
- 系统中断、后台或异常提前停止产生的可播放文件作为“部分录像证据”保留，并给出一次可恢复警告；
  它不能仅凭文件非空或 success key 为 true 就冒充按预期完整完成。用户明确停止仍可正常保存。
- 自动 attempt 失败后暂停本次自动录像，训练继续；用户主动重试建立新 attempt，因此新失败可以
  再提示一次。暂停状态必须在界面可见，重新进入页面不能清空提示后继续静默跳过自动录像。
- 系统中断结束、媒体服务重置或 App 返回前台后，重新验证 Session 与 video connection；失效时
  重建或让当前 request 明确失败，不能继续使用已经中毒的共享准备任务。
- 日志只保存 attempt、阶段、错误 domain/code 和成功标记，不记录动作、重量、视频路径或帧。

### 动作训练记录、计划执行与完成顺序

- 每个动作的全部 Effort 进入 completed/skipped 终态后，至少一个 Effort 完成时物化一条
  `WorkoutEntry`；全跳过不创建空记录。
- 训练记录只复制实际完成 Effort 的侧别、次数/时长、重量、休息与录像证据，缺失保持 `nil`。
- 每个 Performance 与投影记录拥有显式一对一关系和唯一 projection key；恢复、重试、启动回填
  和重复 materialize 不得创建第二条。
- 用户单独删除投影记录后继续保留 suppression 事实，不得由原始 Session 重新“复活”。
- `WorkoutSession` 继续是计划执行事实，不新增重复的 `PlanExecution` 模型。
- 最后一个 Effort 完成时严格按以下顺序收口：
  1. 物化最后一条动作训练记录；
  2. 验证全部 Performance 终态；
  3. Session 标为 completed/finalized；
  4. 结束系统训练投影；
  5. 进入本地 `WorkoutShareSheet`；关闭预览后回到训练 Tab 主页，不再经过「查看分享」中间页。
- 任一步失败保留已经成功保存的事实，展示可重试错误；未完成收口前不展示成功分享页。

### 热量与身体信息

- 热量继续使用本地、确定性的 MET 公式，不调用模型。
- 动作记录优先使用 Effort 实际时长；次数组缺少实际用时时，才允许使用明确标为估算的规则时长。
- 左右间歇和组间间歇只按实际记录计入；计划时间不能冒充实际时间。
- 参考体重取 Session 开始时间之前最近的有效身体记录，再回退 `UserProfile.referenceWeight`。
- 计划执行热量由关联动作训练记录求和；不能再按 Session 总 elapsed 重算并重复计算休息。
- 保存 MET、计算时长、是否估算和算法版本。估算时长只用于热量，不回填实际训练时长。
- 缺体重时返回结构化缺失要求，在计划页和分享页提供身体信息入口；训练继续，热量保持为空。

## Tool、备份与迁移兼容

- 新计划 Tool 使用嵌套逐组处方，并递归验证枚举、范围、未知字段及次数/时长 union。
- 新 Job 只看到新 schema；升级前已经排队或恢复的旧计划 Tool Call 经确定性转换器展开为独立组。
- `start_program` 保持既有 wire 录像策略值，不让 Server 成为训练业务数据来源。
- 启动门禁将 `goal` 原样视为 `overview`；旧 `targetSets=N` 展开为 N 个独立组，并保留首组热身。
- 旧模型没有可靠左右证据，因此迁移为 `.none`；禁止根据动作名称猜侧别。
- 旧模型只支持次数，迁移为 repetitions；缺失次数继续为 `nil`。
- 旧快照和备份必须显式解码；解码失败中止迁移，不能静默得到空处方。
- 个人与演示空间分别迁移、校验和写 marker；全部成功前不开放业务 Root 或 Agent runner。
- SwiftData 打开路径见 [ADR 0075](../adr/0075-current-swiftdata-schema-without-historical-versions.md)：
  只打开当前模型，不维护历史 VersionedSchema 链。

## 数据、隐私与可访问性

- 处方、Session、Effort、动作训练记录、热量与视频都默认留在当前本地数据空间。
- 新模型和字段进入加密备份、恢复、开放导出、清除和双空间隔离验证。
- 不录像时不启动相机；麦克风仍不加入 Capture Session，视频不自动进入相册或发送模型。
- 缺体重提示不展示诊断结论；热量仅是一般活动估算。
- 新控件提供 VoiceOver label/hint/value，支持 Dynamic Type、深浅色、长计划概览和长动作名称。

## 失败态与恢复

- 处方无效：留在计划详情并定位可编辑问题，不创建半成 Session。
- 相机失败：训练继续，常驻按钮和恢复建议保留，同 attempt 不重复警告。
- 倒计时恢复：按持久 deadline 和 revision 收敛到唯一状态，不因过期任务重复完成。
- 动作记录物化失败：Session 不提前完成，已保存 Set/Effort 保留，用户可以重试收口。
- 分享渲染失败：已完成训练不回滚，提供重试分享或返回训练历史。
- 缺体重：热量为空并提供填写入口，不能显示 `0 kcal` 冒充估算结果。

## 明确不在范围

- 自动计次、姿态识别、实时动作评分、旁人检测或伤病诊断；
- RPE/RIR、节奏、距离、配速、坡度、阻力或复杂超级组；
- 服务器训练事实数据库、账户、社区排行榜或自动上传训练录像；
- 自动调用模型生成完成总结或热量；
- 对旧历史训练做隐式热量回填。

## 验收

1. 点击“开始训练”只需再选择一次录像策略即进入首个动作，不出现第二个开始按钮。
2. 三种初始策略下主界面均有可访问的录像按钮；同一 attempt 失败最多一个警告，新 attempt 可再次提示。
3. 动作定义上的四种 laterality 与两种完成方式可编辑；组只出现该定义下有意义的次数或时长与重量，带练仍可执行和恢复。
4. `.both` 一个逻辑组生成两个 Effort，固定左后右，左右录像可独立播放，进度先半填后全填。
5. 计时和休息到期自动推进且只推进一次；暂停、重建 View、前后台和重启不重复完成。
6. 进度按动作和逻辑组分段；语音准确播报组数与次数/秒数，异构组逐组摘要。
7. 每个完成动作先出现唯一训练记录；全跳过不建记录；Session 聚合不重复统计。
8. 最后一组不显示“保存并结束”，自动完成后进入本地分享预览，系统分享仍需用户点击。
9. 热量使用动作记录求和和当时可用体重；缺体重时为空、可引导填写且不阻断训练。
