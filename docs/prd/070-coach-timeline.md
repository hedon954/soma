# PRD 070：教练页按发生时间排列事件

- 状态：已采纳，已实现
- 日期：2026-09-29
- 版本：0.0.26
- 修订自：
  - [PRD 000](000-origin-through-0.0.11.md)（教练页只按消息渲染当天会话）
- 后续修订：暂无
- 下游落地：[ADR 0139](../adr/0139-coach-timeline.md)、[验收](../acceptance.md)

## 背景

带练、以及任何不经过当前这条回复写入的饮食和身体记录，会进训练和进展，却不出现在当天的教练页。
教练页如果只保存输入框产生的消息，同一个人的一天会被拆成两套时间。

## 用户结果

打开某一天的教练会话时，按发生时间看到这一天的消息，以及这一天里没有挂到任何聊天回合上的
训练、饮食和身体记录。同一次带练的多条训练记录排在一起，用现在的记录卡展示。

已经由某条教练回复展示过的记录不重复出现。气泡、记录卡、输入区和空会话引导的外观不变。
没有消息、也没有这类记录时，空会话引导仍在。

向上加载更早消息时，比当前已加载窗口更早的记录先不插入，避免把尚未翻到的早晨记到页首。

## 产品规则

- 事件的时间用记录自己的发生时间，不用投影写入的时间。
- 带有 `sourceTurnID` 的记录留在原来的回复里。
- 同一次带练（同一个 `sourceWorkoutSessionID`）合成一个事件，内部仍是原来的训练记录卡。
- 不补写用户句子或教练回复，也不把这些记录写进模型上下文。
- 删除或修改记录后，教练页上的同一张卡跟着变；统计仍只读记录本身。

## 数据与隐私

不新增持久字段，不把记录复制进 `CoachMessage`。读取范围是当前会话业务日的训练、饮食和身体记录。

## 明确不在范围

- 不改气泡、记录卡和输入区的视觉。
- 不在此版本做打开时的预测条。
- 不把休息、跳过或计划相位写进这条时间线。

## 验收

同一天先有带练、后有消息时，训练记录卡出现在消息之前或之后，顺序跟发生时间一致。
聊天里已经展示的记录只出现一次。执行 `make check`。
