# 2026-07-28：真正的 ReAct、数据可信度与可观测性

## Agent 重构

- 将早期预设式/本地演示回复升级为真正的多轮 ReAct Agent。
- 明确采用 OpenAI-compatible 原生 Tool Calling：
  - 模型可以自然说话；
  - 模型可以返回 `tool_calls`；
  - App 执行本地工具；
  - 结果以 `role: tool` 返回模型；
  - 循环直至最终回复。
- 移除“模型必须输出自定义决策 JSON”的错误约束。
- 工具通过 API 注册，不再把工具清单手写进系统提示词。
- 使用 `SwiftOpenAI` 承担网络和 SSE，不重复维护底层客户端。
- 全程流式调用；暂不展示 thinking。

## 数据写入与真实性

- 增加查询用户数据、记录训练、记录饮食、记录身体、更新健身房和切换健身房等本地工具。
- 同一 Trace 中的重复写入去重。
- 工具错误回传模型，不静默失败。
- 明确“没有的数据就为空”：
  - 不再自动补 60 秒间歇；
  - 不再自动补训练时长；
  - 不在证据不足时生成动作评分或负荷判断。
- 已完成的 Tool 写入在最终回复失败时仍然保留，并在 UI 中说明。

## CRUD 交互

- 训练、饮食、身体、健身房和器械均支持审查、修改和删除。
- 详情页进入即编辑，字段显示固定名称。
- 修改后才显示保存键。
- 列表支持左滑删除。
- 删除操作改为红色垃圾桶图标，并移除重复的“删除”文字。
- 记录详情补充原始文字、训练图片/视频、食物图片和体态图。

## 演示与个人数据

- 建立彼此隔离的演示/个人 SwiftData 容器。
- 增加一键切换，确保演示统计不污染个人数据。
- 随后将切换入口从聊天页移入高级设置，降低正常使用时的误触风险。

## 开发者设置

- 新增角色与安全策略的系统提示词编辑。
- 提示词支持 Markdown 编辑与预览。
- 明确工具与输出格式是系统内置协议，不允许用户配置。

## 渐进式 Skills

首批加入七项可编辑 Skill：

1. 健身房分析；
2. 用户健身计划制定；
3. 动作分析；
4. 饮食分析；
5. 体态分析；
6. 运动趋势分析；
7. 运动量分析。

系统只披露目录，Agent 通过 `load_skill` 按需读取全文。Skill 加载作为特殊 Span 进入执行日志。

## Trace、Span 与流式 Event

- 每条用户消息保存一条完整 Trace。
- 成功和失败都记录。
- 增加模型、Skill、工具和最终输出 Span。
- 记录平台、模型、输入预览、结果/错误、Token、相对时间和耗时。
- 把每个 Span 生命周期建模为 Event，执行时实时传给 UI。
- 调整 Trace 详情的信息层级、左对齐与错误排版，减少重复红字和视觉噪声。
- 暂不实现失败重试。

## 统计

- 训练容量由运动记录实时派生，而不是静态演示数字。
- 不完整记录不参与训练容量，避免假数据改变趋势。

## 当日纠正的错误方向

- 预设回复冒充 Agent。
- 自定义 JSON 决策协议。
- 在提示词中重复列出 Tool。
- AI 自动补齐用户未提供的字段。
- 把工具和输出格式暴露给用户编辑。
- Trace 结束后才整体刷新。
