# ADR 0036：训练计划允许 GUI 确定性创建与编排

- 状态：已采纳
- 日期：2026-08-03
- 维护者：Soma maintainers
- 部分替代：
  - [ADR 0002](0002-chat-write-path-review-gui.md) 的“聊天是所有业务对象唯一创建路径”
  - [ADR 0030](0030-deterministic-guided-workout-and-session-recording.md) 中计划只经聊天创建的范围
- 后续替代：暂无
- 上游依据：[PRD 012](../prd/012-gui-training-program-authoring.md)
- 关联：[ADR 0029](0029-versioned-training-plans-and-session-facts.md)

## 背景

ADR 0002 用聊天取代传统业务表单，避免用户先理解数据库结构。该原则适合训练、饮食、身体等
自然发生的事实，但训练计划是用户主动设计的有序结构：同一屏比较动作、拖动顺序和配置处方
比逐轮描述、等待模型理解更直接、更可预期。

现有计划详情已经允许 GUI 编辑并生成新版本，说明 GUI 编排本身已经是产品边界的一部分；只把
“第一版创建”强制留在聊天，会形成没有必要的入口断层。

## 决策

1. 聊天继续是非结构化身体事实的默认创建路径，也是 AI 生成或调整计划的入口。
2. 训练计划创建是受控 GUI 例外：用户可从计划库选择已有动作并确定性创建第一版模板。
3. GUI 不创建动作；只能引用当前空间已激活、未归档的 `ExerciseDefinition`，因此不破坏静默
   动作目录和渐进形成动作库的边界。
4. GUI 与 Agent 共用 `TrainingPlanStore`、稳定动作 ID、验证规则和不可变模板版本；View 不直接
   拼装或分散保存 SwiftData 模型。
5. 空白处方字段保持 `nil`。创建器不提供常见默认值，不自动生成建议，也不触发远程请求。
6. 入口位于“进展 → 训练计划”，不新增顶层导航。列表、空态和工具栏都能发现新建能力。
7. 带练仍是另一项受控例外，只保存用户在已启动 Session 中确认的事实；本 ADR 不改变 ADR
   0030 的状态机、快照和录像边界。

## 未选择的方案

- 继续只允许聊天创建：无法利用结构化编排的视觉优势，并让无模型即可完成的工作依赖模型。
- 在创建器里展示全部包内动作：会让未使用动作提前进入用户心智，破坏静默激活规则。
- 为每个处方提供默认容量：看似快捷，但会把用户没有表达的目标伪装成事实。
- 新建第二套 GUI 数据模型：会造成 Agent 与 GUI 计划的版本、验证和备份语义漂移。
- 新增顶层“训练”Tab：计划创建是低频能力，不应扩大顶层信息架构。

## 结果

### 正向影响

- 用户可以选择最适合任务的入口：聊天负责生成与自然修改，GUI 负责精确组合。
- 第一个模板版本和后续 GUI 版本使用同一套确定性规则，数据与历史仍可解释。
- 创建计划不消耗 Token，也不依赖网络或 Provider 可用性。

### 成本与限制

- “聊天优先”不再等于“所有对象只能从聊天创建”，后续例外仍必须由 PRD/ADR 明确授权。
- 用户必须先在当前空间形成动作，才能在 GUI 中选择；创建器不是完整动作目录。
- 创建和版本编辑需要共享 UI 草稿与验证，避免两条界面逐渐漂移。

## 验证

- `TrainingPlanTests` 覆盖 GUI 来源创建、稳定动作引用、连续顺序和空值不补齐。
- 模拟器验证列表入口、空动作状态、动作选择、排序删除、错误提示和保存后导航。
- `make check` 验证本 ADR 与 ADR 0002/0030、PRD 012 与 PRD 004/010 的双向生命周期链接。
- `make verify` 验证现有 Agent 创建、版本快照、带练和数据管理行为没有回归。
