# ADR 0152 · 教练连续性与进展刷新

- 状态：已采纳
- 日期：2026-11-19
- 部分替代：[ADR 0000](0000-origin-through-0.0.11.md)（教练双击、视频能力确认与降级、诊断投递与餐次完整性）
- 上游依据：[PRD 082](../prd/082-coach-progress-reliability.md)
- 下游落地：[BUG 0071](../bugs/0071-unverified-video-input.md)（本机发送门槛与手动换模型）、[ReAct 协议](../react-agent.md)、[验收矩阵](../acceptance.md)

## 背景

批量创建训练后教练渲染与进展刷新共同占用主线程。新版同时需要更可靠的餐次完整性、诊断投递和媒体边界。

## 决策

教练双击回当天会话尾部，单击保留位置。当前会话业务日期决定标题按钮。数据空间、会话和记录日期构成草稿与媒体的边界。训练视频需要原片时序分析。本机用所选模型的目录能力确认，远程用部署能力协商确认。未知时只查询模型目录，确认后才发送完整视频。能力不足时保留原件和可恢复状态。日账由设备计算，直连模型的日账读取见 [ADR 0153](0153-agent-daily-energy-read.md)。

SwiftData 保存后按输入类型标记快照失效。同一日期范围持有最近一次成功投影，加载完成后替换值。展示输出的落盘不重复触发相同投影。已有有效餐次的记录和用户确认没吃都覆盖该餐次，保存时的归类来源单独保留。周期计算以同一天的有效摄入和消耗配对求和，纳入已齐全的今天。活动来源整包选择和四项总消耗继续使用现有服务。

系统确认的崩溃按事件指纹进入持久队列；同一进程同一时间只有一个投递者。邮件采用稳定 Message-ID，报告标明发生区间和生成时间。SMTP 接收后本机在回执落盘前终止仍可能重复。备份媒体由单次受控普通读取生成密文与摘要，完成清单就绪后原子提交。重量校正只针对维护者指定个人设备，先预览，保留原始与目标值，防止重入。

## 结果

同一范围内允许继续读取上一次进展快照。完整度来源可回溯到实际餐食或指定日期、餐次的确认。并发诊断投递使用单一发送入口。

## 验证

回归覆盖同一批次写入、读快照与写输出、取消、历史日期切换、重复诊断、混合重量组、跨日缺餐、媒体与工具可用性。真实数据只允许在对应设备检查。
