# ADR 0023：训练以有序逐组证据为事实来源

- 状态：已接受
- 日期：2026-07-30
- 维护者：Soma maintainers
- 替代：[ADR 0006](0006-data-truth-and-derived-metrics.md) 的标量训练容量部分

## 背景

`WorkoutEntry` 当前只有一个 `sets`、`reps` 和 `weight`，只能表达每组完全相同的训练。
真实训练常见递增重量、递减次数、热身组和力竭组。把 `10kg×10、20kg×10、14kg×12`
压成一个平均重量或统一次数会直接污染记录、训练容量和后续建议。

## 决策

- 新增不可变、可编码的 `WorkoutSetEvidence` 值类型，按顺序保存每组的 `reps` 和
  `externalWeightKG`；未知值为 `nil`，明确无外部负重为 `0`。
- `WorkoutEntry` 的新事实来源是有序数组。组数由数组长度派生，总次数由已知次数求和。
- 训练容量逐组计算，只累计 `reps > 0` 且 `externalWeightKG > 0` 的完整组。存在不完整组时
  结果命名为“已知训练容量”。
- 每组是最小编辑单元。详情页、Tool Schema、查询、合并、导出、备份和 Agent 回复都保留
  顺序，不把不同重量的组重新折叠成标量。
- 训练级 `restSeconds`、`durationMinutes` 和媒体暂不拆到每组；本需求不预建未提出的逐组
  计时器。
- 旧标量字段作为兼容读取入口：
  - 合法 `sets + reps + weight` 展开为相同的 N 组；
  - 有可靠 `sets` 时可展开已知的 reps/weight，缺失项保持 `nil`；
  - 没有可靠 `sets` 时不猜测数组长度。
- 数组非空时它是唯一权威来源；新写入不再维护一套可能漂移的标量副本。
- `record_workout` 和 `update_workout` 使用 `set_entries` 数组；持久化幂等签名与记录合并把
  规范化后的有序组纳入比较。

## 未选择的方案

- 继续使用统一组数、次数、重量：无法表达需求。
- 只增加 reps 数组、重量仍全局统一：仍无法表达不同重量的组。
- 保存平均重量或总容量：丢失原始事实，无法可靠纠错。
- 立即增加逐组间歇、RPE、节奏和完成状态：超出当前需求。

## 结果

### 正向影响

- 训练记录、容量趋势和 Agent 建议都能追溯到具体组。
- 修改一组不会重写整项动作，也不会伪造其他组。
- 旧记录可以确定性迁移，缺失信息继续为空。

### 成本与限制

- SwiftData、Tool Schema、CRUD、合并、测试、导出和备份需要同步迁移。
- HealthKit 训练通常没有逐组证据，导入记录会继续保持数组为空。
- 部分组缺失时容量是已知下限，不能与完整总容量混为一谈。

## 验证

- 覆盖相同组、混合重量/次数、未知值、自重、单组编辑和旧标量迁移。
- 验证 `10×10 + 20×10 + 14×12 = 468kg`，且组数派生为 3。
- 备份恢复、开放导出和 Agent 查询往返后保持顺序与 `nil`。
