# ADR 0155 · LLM 请求的固定 System 与动态 User

- 状态：已采纳
- 日期：2026-11-20
- 版本：未发布
- 修订自：[ADR 0000](0000-origin-through-0.0.11.md)（模型输入前缀与任务快照）

## 背景

模型请求需要能在仓库里按场景完整审阅。把个性化人格、Skill 目录和日期等内容混入 System 消息，
会让同一场景的固定前缀随请求变化。

## 决策

文本模型场景使用完整的 `xxx_system_prompt.md` 和 `xxx_user_prompt.md`。System 直接使用打包后的固定文本，
固定任务约束和授权边界在此声明。用户正文、人格、Skill 和业务事实通过 User 模板注入。
工具说明和参数随各自 Schema 进入原生 API 的 `tools`。预填和界面文案随入口代码维护。

本机直连和远程执行使用同一设备输入组装。发送时冻结实际 System、人格、Skills 和工具定义。
升级前已保存的快照和检查点继续使用已有内容。SwiftData 字段和远程请求协议继续沿用现有结构。
图片生成使用该端点的单个 prompt；恢复和降级作为同一场景的追加消息。

## 结果

可以按场景对照完整的 System 与 User 模板。不同用户与快捷 Skill 下，教练 System 的字节保持一致。
工具集合、历史前缀和供应商实现仍会影响缓存命中。资源配对和静态 System 由 `make check` 验证。
