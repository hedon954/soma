# ADR 0137：统一上下文计划、稳定 Turn 帧与可追溯摘要

- 状态：已采纳，已实现
- 日期：2026-09-12
- 版本：0.0.24
- 上游依据：[PRD 067](../prd/067-agent-context-management.md)
- 部分替代：[ADR 0000](0000-origin-through-0.0.11.md)（历史窗口、消息恢复与输入快照）；[ADR 0120](0120-focused-shortcut-prompt.md)（配置冻结时点，快捷聚焦和权限交集保持）

## 背景

旧实现按较短的固定轮数组织历史，跨轮会重新拼接 Prompt，且没有保存原生 Tool 调用和回执。
这会过早压缩，也会在时间、配置或恢复路径改变时让模型混淆历史事实与本轮状态，并削弱跨轮
前缀缓存命中。模型上下文容量和缓存保留均由 Provider 决定，应用只能控制稳定前缀、历史边界
与每轮事实的来源，不能把 256k 等容量假定写成系统承诺。

## 决策

1. 投影和摘要共用 30 轮 / 30k 历史文本选择结果；摘要只覆盖实际移出窗口的来源。
2. 原始发送时间、业务日期、时区绑定 Turn。首次执行在前序 FIFO 写入后获取业务状态，
   以观测时间标识；恢复保留原输入和成功回执，必要新状态追加为更新。
3. 固定契约置前，每轮动态信息置于带 Turn 身份的消息中。同一上下文段复用已发送帧，
   跨轮保留原生工具配对；压缩、媒体选择、历史修订、配置改变可以建立新段。
4. Prompt / Skill / Tool 配置冻结实际内容，凭据不入快照。权限以当前工具边界验证，
   历史授权、摘要、工具文本不得扩大本轮写入。紧急撤权优先于缓存。
5. 摘要带来源内容指纹、时间与覆盖范围。修订、删除或扩大窗口导致重叠时重建；压缩输入
   分批，模型输出与确定性回退均有硬预算。摘要提供背景与回查引用，不覆盖当前数据库。
6. JSON 信封和现有 Job/checkpoint/摘要 Data 列允许增加可选字段及版本化编码，旧数据按
   缺失处理。模型输入升级需双端验证，旧 checkpoint 保留兼容读取；不增加 SwiftData 模型
   或不兼容列，不需要业务数据重建。编码变化同步数据库与 Agent 协议文档。
7. Loop 内不任意删除图片或重写前缀；历史媒体仍按回指发送。请求体 413 与 token 超限
   分开，保持现有人工恢复屏障。用量缺项保持未知，本地与远程分别记录缓存计数。

## 结果

同一有效上下文段能复用固定系统契约、历史消息、原生 Tool 帧和冻结配置；新 Turn 只追加本轮
消息。时间、结构化业务状态和用户修订有明确边界，缩短历史不会把旧日期或授权视作当前事实。
缓存命中通过 Provider 返回的 token 指标观测，未返回时保持未知。

## 取舍

严格最近 30 轮在长会话中可能每轮更新摘要并损失缓存。未采用提前批量压到更小窗口，
也不通过扩大工具白名单或重发无关历史媒体换命中率。共同前缀只是可复用条件，供应商
路由、保留时间等仍影响真实命中。恢复需要最小必要快照，避免保存完整 Trace 的副本。
