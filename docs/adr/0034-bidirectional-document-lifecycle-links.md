# ADR 0034：文档修订与替代关系使用双向生命周期索引

- 状态：已采纳
- 日期：2026-07-31
- 维护者：Soma maintainers
- 部分替代：[ADR 0010](0010-repository-governance-and-xcodegen.md) 的文档治理范围
- 后续替代：暂无

## 背景

PRD、ADR、Bug、Research 和工程协议会随着产品演进发生修订、部分替代和正式落地。如果只有
新文链接旧文，维护者从旧基线出发时看不到当前结论；如果直接改写旧文，又会丢失当时为什么
作出决策的历史。

仅依赖目录索引或正文中的自然语言提及，也无法自动验证关系是否完整。

## 决策

1. 所有文档生命周期关系必须双向：
   - 旧文使用“后续修订”“后续替代”或“下游落地”链接新文；
   - 新文使用“修订自”“替代”“部分替代”或“上游依据”链接旧文。
2. 关系写在文档头部，正文可以解释范围，但不能替代头部索引。
3. 对应目录 README 同步状态和核心变化，作为人类导航入口。
4. 部分替代必须说明被改变的具体边界；旧文未被改变的内容继续有效。
5. 一份新文影响多份旧文时逐项链接，不强行维持单线历史；“双向链表”在实现上允许分支图。
6. PRD、ADR 和 Bug 模板预留生命周期字段；Research 转正式文档时使用上下游字段。
7. `scripts/check-document-lifecycle-links.rb` 扫描生命周期字段，并要求每条本地关系在目标文档
   中存在反向边。
8. `make check` 执行该脚本；缺失反向链接视为仓库契约失败。

## 未选择的方案

- 只在新文链接旧文：无法从旧基线发现现行决策。
- 直接覆盖旧文：丢失决策上下文和未被替代的有效部分。
- 只维护 README 表格：索引容易与文档头部漂移，且无法表达精确范围。
- 要求严格单前驱单后继：产品决策会分支和汇合，不适合强行线性化。
- 只靠人工 Review：规则稳定且可自动化，应进入质量门禁。

## 结果

### 正向影响

- 从历史或现行文档出发都能追到完整演进关系。
- 部分替代不再被误解为整份文档失效。
- 研究、故障和正式决策之间有可验证的交付链。
- Agent 和维护者可以可靠识别当前有效边界。

### 成本与限制

- 每次新增替代关系至少修改两份文档和一个目录索引。
- 自动检查只验证关系存在和文件可达，替代范围是否准确仍需 Review。
- 外部 URL 不参与反向链接检查。

## 验证

- 为现有 PRD 链、被替代 ADR、BUG 0004 和两份 2026-07-31 调研回填双向关系。
- 删除任意一侧生命周期链接时，`scripts/check-document-lifecycle-links.rb` 必须失败。
- 本地目标不存在时，Markdown 链接检查和生命周期检查都必须失败。
- `make check` 通过。
