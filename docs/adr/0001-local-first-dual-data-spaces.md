# ADR 0001：无账户、本地优先与双数据空间

- 状态：已采纳
- 决策阶段：2026-07-27

## 背景

训练视频、体态图、体重和饮食都属于高度私密的个人数据。产品同时需要内置足够完整的演示内容，便于没有真实记录时验收界面和统计。

## 决策

1. 不建设账号、登录、后端数据库或 CloudKit 同步。
2. SwiftData 与媒体文件留在 App 沙盒；API Key 写入 ThisDeviceOnly Keychain。
3. 演示数据和个人数据使用独立的 SwiftData 容器。
4. 数据空间切换位于高级设置，不出现在高频聊天界面。
5. 远程 AI 默认关闭；只有用户主动启用并发送内容时才传输本次任务所需信息。

## 未选择的方案

- 单一数据库加 `isDemo` 字段：查询容易漏过滤，统计可能混入测试数据。
- 登录后云同步：与“纯私人工具”的目标冲突，并显著扩大隐私与运维面。
- 首页常驻数据空间切换：演示方便，但正常使用后价值很低且容易误触。

## 结果

- 两个空间不复制、不合并，也不共享记录。
- 同一外部来源在不同空间中必须维护不同的同步游标。
- 删除 App 会删除本地业务数据；产品必须清楚说明这一边界。
