# ADR 0004：Skills 渐进披露，Tool 协议固定

- 状态：部分已替代
- 决策阶段：2026-07-28 至 2026-07-29
- 后续替代：[ADR 0050](0050-per-turn-tool-group-exposure-and-parallel-calls.md) 修订运行时工具暴露策略（Tool 契约本身仍固定）

## 背景

健身房、计划、动作、饮食、体态和统计各自需要较长的专业指令。每次把所有说明塞进系统提示词会增加 Token、降低注意力，也不利于高级用户单独调整。

另一方面，Tool 名称、参数和输出协议直接决定能写入什么数据，属于系统安全边界。

## 决策

- 系统提示词只披露八项 Skill 的 ID、名称和摘要。
- Agent 按需调用只读 `load_skill`，获得该 Skill 的完整 Markdown。
- Skill 加载形成独立 Span。
- 角色、安全策略和各 Skill 文本允许高级用户编辑、预览和恢复默认。
- Tool 清单、描述、JSON Schema 和输出协议由 App 固定注册，不对用户开放。

当前 Skills：

1. 健身房分析；
2. 用户健身计划制定；
3. 动作分析；
4. 饮食分析；
5. 体态分析；
6. 运动趋势分析；
7. 运动量分析；
8. 运动热量估算。

## 未选择的方案

- 每次注入所有 Skills：上下文成本高，模型不需要的规则会互相干扰。
- 允许用户修改 Tool Schema：可能破坏数据完整性、安全策略和本地执行。
- 把 Tool 说明复制进提示词：形成两份事实来源。

## 结果

Skills 是可调的专业方法，Tools 是不可调的系统能力。新增 Skill 不等于新增工具；需要写入新数据时必须单独评审 Tool 与数据模型。
