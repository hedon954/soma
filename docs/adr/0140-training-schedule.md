# ADR 0140：训练计划是锚定日上的课程周期

- 状态：已采纳，已实现
- 日期：2026-09-29
- 版本：0.0.26
- 维护者：Soma maintainers
- 上游依据：[PRD 071](../prd/071-training-schedule.md)
- 部分替代：[ADR 0000](0000-origin-through-0.0.11.md)（仅「计划」所指的对象；课程处方、带练快照和聊天优先仍然有效）
- 后续替代：暂无
- 下游落地：[验收](../acceptance.md)

## 背景

`TrainingProgram` 保存一堂课的当前处方。产品名已经改为训练课程。训练计划需要开始日、
周期和每一天的课程或休息，并且要容忍缺席，而不是把错过的课积成欠账。

## 决策

新增 `TrainingSchedule`。周期槽位按顺序存在 `slotsData`，锚定日存在 `anchorDate`。
今天的格子是间隔天数对周期长度取余。

未完成的课程只保留一堂：应练日和次日都还是这一堂；次日结束仍未完成，则写入一条跳过闭合，
游标前进到下一天的课。明确休息写入休息闭合。完成不另存一份，读取该课程在应练日或次日的
已完成 `WorkoutSession`。

`reanchorRequired` 在「自锚定日或其后最近一次训练记录起，已满一整轮没有新记录」时置上。
置上之后不再按旧锚定日推今天，直到用户选择从今天接上。接上时把锚定日移到使今天落在
第一堂课的那一天，并清掉这个标记。

课程重量不被这次计划改写。准备页对本次 Session 的调整保持原语义。

同时只有一份 `active` 计划。保存另一份进行中的计划时，其余进行中的计划改为归档。

## 未选择的方案

- 用 `scheduleHint` 文本推断今天该练什么。那句备注不是日期。
- 错过的每一天都保留为待补课程。欠账会让人躲开计划。
- 停满一轮后自动把重量按天数减轻。没有记录不能当成体能下降。
- 停满一轮后只要又练了一次就自动恢复旧相位。相位已经对不上，要由用户从今天接上。

## 结果

### 正向影响

- 训练计划和训练课程可以同时存在，并且说的是不同的事。
- 缺席一天仍只有一个开始动作；满一轮后计划会停住，而不是继续报一个过时的「今天」。

### 成本与限制

- 跳过和休息是计划上的闭合，不是训练记录，也不进入热量统计。
- 最常完成的课只统计本计划里的课程，不统计计划以外的自由训练。
- 旧备份没有这份模型时恢复为空，不猜测计划。

## 验证

- `TrainingScheduleResolverTests` 覆盖应练、补做、过期、休息、停住和重新锚定。
- `make check` 通过。
