# ADR 0093：逐条 AI 回复使用有界多模态反馈上下文

- 状态：已采纳，个人使用阶段
- 日期：2026-08-23
- 维护者：Soma maintainers
- 部分替代：[ADR 0000](0000-origin-through-0.0.10.md) 中用户反馈邮件只承载表单文字与附件、不带聊天或 Trace 摘要的边界
- 上游依据：
  - [PRD 042](../prd/042-user-controlled-recovery-message-feedback-and-action-art.md)
  - [BUG 0031](../bugs/0031-feedback-sheet-transition-jank.md)

## 背景

设置页通用反馈无法稳定定位具体 AI 回复。让用户手工复制 Trace 会增加摩擦，也容易暴露敏感入参；
完全不带执行信息又无法判断是模型、工具、队列还是投影问题。

## 决策

1. 每条非流式 AI 回复使用 `text.bubble` 线框反馈图标，以 8 pt 间距放在时间右侧并保持同一水平线，
   继续保留 44 pt 触达区域；图标在当前消息下方原位展开复用的紧凑 `FeedbackView`，不发起页面、
   Sheet 或导航切换。每条回复提供独立的反馈编辑器底部锚点，用户点按展开、布局完成后由聊天滚动区
   平滑滚到该锚点；收起不强制滚动。收起按钮仍属于当前回复的叶子组件。
2. 表单增加 1–5 星评分，继续支持文字、图片和视频；评分、文字或附件至少一项存在才允许发送。
3. 用户主动发送时，正文附带当前 Turn 的可见用户文字、可见 AI 文字、原消息媒体数量、消息/Turn/
   Job/Trace ID、Job backend/state/attempt、所选 Skill/快捷按钮、provider/model/status、最近二十个
   Span 的 kind/title/status/duration/error，以及 App/系统版本。
4. 自动上下文禁止包含原消息媒体字节、位置、API Key、Authorization、endpoint、Trace input/output/
   metadata、context snapshot、完整日志、健康记录、其他 Turn 和其他 Session。
5. 总正文继续服从 5,000 字上限；长文本和步骤摘要在设备上截断。用户在反馈编辑器新选择的媒体仍是
   唯一自动上下文以外的附件。
6. 编辑器不展示“随反馈附带的上下文”说明；隐私边界继续由产品契约与发送内容保证。投递成功后，
   逐回复叶子编辑器自动收起；设置页通用反馈继续显示成功确认。失败不后台重试，逐回复编辑器保持
   展开并保留当前文字、评分和附件。
7. 每条回复的叶子反馈按钮自行持有原位展开状态，只携带稳定的 AI 消息 ID；根 `CoachView` 不持有
   反馈路由状态、不订阅全部 Trace，也不在点按入口时构建完整 envelope。用户点按发送后才按消息 ID
   定向读取当前 Turn、Job 与 Trace；临时视频删除也不在收起交互的主线程路径执行。

## 结果

- 维护者可以把评价定位到确定回复和执行步骤，同时不需要用户复制诊断信息。
- 反馈编辑器展开与收起不再承担页面转场、聊天树重算、Trace 解码、全量集合扫描或同步文件删除，教练页也不会因无关
  Trace 变化扩大刷新范围。
- 反馈数据边界从“只含表单”扩大为“用户触发的单 Turn 有界 envelope”，仍不进入身体数据库或
  PostgreSQL；对外分发前的凭据迁移门禁不变。
