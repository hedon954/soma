# ADR 0142：训练页最近训练按未缓存身份分页

- 状态：已采纳，已实现
- 日期：2026-10-10
- 维护者：Soma maintainers
- 上游依据：
  - [PRD 073](../prd/073-training-session-pages.md)
  - [ADR 0134](0134-session-history-page-cache.md)（未缓存身份分页；本决策换到已结束的训练 Session）
- 部分替代：无
- 后续替代：暂无
- 下游落地：[验收](../acceptance.md)

## 背景

训练根页用一条 `fetchLimit = 4` 的查询取出已完成和已放弃 Session，界面再截成 3 条。把上限改成更大的 `fetchLimit` 或用偏移翻页，都会在新训练插入顶部、或删除中间一项之后重复和漏项，也会在根页一次物化全部历史。

## 决策

训练 Tab 根持有这份列表缓存，位置在「最近训练」区块之外，换到教练、进展、设置再回来不丢。

每页在 MainActor 查询最多 14 条。状态只包括已完成和已放弃。排序是 `startedAt` 倒序，然后是 Session 身份倒序。已缓存身份的排除条件下推到数据库。不使用偏移，也不把 `fetchLimit` 逐次放大后重读前缀。

返回满 14 条才显示「更早的训练」。不足 14 条结束。恰好整页是尾页时，下一次空查询关掉按钮，不另查总数。按钮点击才查询；滚动到区块附近不自动连拉后续页。

同一容器里，新完成或新放弃的 Session 只插入缓存顶部；删除只移除对应身份。进行中和暂停不进入缓存。无关模型保存不触发查询。缓存绑定当前 `ModelContext`，切换数据空间即清空。下一页失败保留已加载页，并允许重试同一次查询。

行、左滑删除和复盘跳转继续用现在的 Session 行。进展页的 `WorkoutHistoryQuery` 仍分页 `WorkoutEntry`，每页 50，本决策不修改它。

## 未选择的方案

- 根页改成「查看全部」再进入第二份列表。训练页上能翻的就是这一个列表，不留下 3 条预览。
- 复用进展页的动作历史。一次训练在那里被拆成多行，和现在的 Session 行不是同一份名单。
- 用偏移分页。顶部插入一次新训练就会跳过或重复边界上的那一条。

## 结果

### 正向影响

- 最近训练可以继续往前翻，根页不再为了 3 条预览截断查询。
- 增删只改对应身份，已翻到的页保持稳定。

### 成本与限制

- 排除条件随已加载页数变长。这是用户实际翻过的次数，不是全表。
- 每个 Session 行仍是独立的单行 List，以便在根页 ScrollView 里左滑。页大小保持 14，避免把这个结构一次铺到全部历史。

## 验证

`TrainingSessionHistory` 的确定性测试覆盖 14 与尾页、同 `startedAt`、顶部插入、删除、失败保留、空页关闭按钮，以及更换 `ModelContext` 后缓存为空。`make check` 与 `make verify`。
