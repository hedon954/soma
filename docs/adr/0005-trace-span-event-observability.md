# ADR 0005：一条消息一条 Trace，Span 通过 Event 流式渲染

- 状态：已采纳
- 决策阶段：2026-07-28

## 背景

Agent 会经历多轮模型调用、Skill 加载、数据查询和写入。只保存最终回答无法解释成功来自哪里，也无法定位多模态或工具失败。

## 决策

- 一条用户消息对应一条完整 Trace。
- `model`、`skill`、`tool` 和 `output` 是四类 Span。
- Span 的开始、增量、结束和错误都表现为 Event，执行期间实时传递给 UI。
- Trace 无论成功、失败或取消都落盘。
- 持久化层按 Span ID 更新同一条记录，不按 token 新建对象。
- 记录输入预览、结果/错误、相对时间、耗时、模型与 Token；不记录密钥、Authorization 头或媒体 Base64。
- 当前不支持一键重试。

## 未选择的方案

- 只记录最终答案：无法诊断失败步骤。
- 任务结束后一次性展示时间线：正确但体验迟钝。
- 保存模型私有思维链：没有必要，且增加隐私和供应商差异。

## 结果

Trace 同时服务用户信任和开发诊断。UI 可以简洁，但底层事件必须完整；失败摘要需要指向具体失败 Span。
