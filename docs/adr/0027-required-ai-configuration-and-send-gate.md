# ADR 0027：AI 必配与发送前配置门禁

- 状态：已接受
- 日期：2026-07-31
- 维护者：Soma maintainers
- 部分替代：[ADR 0001](0001-local-first-dual-data-spaces.md) 的远程 AI 开关，以及
  [ADR 0025](0025-tiered-model-profiles-and-routing.md) 的“启用远程 Agent”前提

## 背景

Soma 的核心录入闭环依赖 Agent 理解自然语言和媒体，再调用确定性工具写入可审查记录。
如果设置页同时提供“启用远程 ReAct Agent”开关和无 Key 本地分析器，产品就会出现两个表面
相似、能力和数据真值却不同的聊天模式。用户可能在没有真实模型参与时误以为照片、视频或
自然语言已经被可靠解析。

API Key 是用户开始发送前唯一需要解决的硬前提。这个前提应在发送动作发生时就清楚处理，
而不是先创建一条注定失败的消息，或要求用户理解内部的“远程 Agent”运行模式。

## 决策

- 设置页不再展示远程 Agent 开关、本地/远程模式标签或相关启用提示。Soma 的聊天处理始终
  使用用户配置的 OpenAI-compatible Agent。
- 标准模型的 API Key 是发送新消息和重试失败消息的前提；小模型继续允许不配置。
- 用户在标准档没有 API Key 时点击发送或重试：
  - 不创建用户消息、Agent Attempt、Trace 或业务记录；
  - 保留当前草稿和待发送附件；
  - 直接打开“设置 → AI 服务”，并提醒完成平台、模型和 API Key 配置。
- `ConversationProcessingService` 的产品路径只运行远程流式 ReAct，不再根据数据空间或
  开关进入本地规则分析器。
- 已有聊天、业务记录、趋势和设置仍然可以离线查看与编辑；“AI 必配”只约束依赖 Agent 的
  新发送和重试，不把 App 变成启动即阻塞的配置向导。
- 保存 API Key 本身不会发送任何健康数据。只有用户明确发送消息时，Soma 才按既有隐私
  边界上传当前输入、同 Session 最近十个来回和视觉额度内的媒体表示。

## 未选择的方案

- 保留默认开启的远程开关：开关仍在暴露没有产品意义的内部运行模式。
- 发送后再返回缺少 Key 的失败气泡：污染对话历史，也让用户误以为消息已经进入处理。
- 无 Key 时继续运行本地关键词解析：无法满足多模态和自然语言能力边界，容易产生伪真值。
- 首次启动强制配置：会阻塞用户先查看隐私说明、演示记录和现有数据。

## 结果

- 聊天只有一条可解释的处理路径；UI 不再让用户选择 Soma 是否“有 AI”。
- 未配置状态在数据落盘前被拦截，草稿和附件不会丢失。
- 标准档配置成为完整 Agent 能力下限，小模型仍只是可选的成本与延迟优化。
- 离线查看与本地 CRUD 不受影响，远程数据流仍只由明确发送触发。

## 验证

- 单元测试覆盖标准档无 Key 和有 Key 两种前提，不依赖历史开关。
- 模拟器清空标准档 Key 后发送文字或附件，应直接进入 AI 服务并显示提醒；返回聊天后草稿和
  附件仍在，且没有新增 Turn 或 Trace。
- 配置标准档 Key 后，同一草稿可以正常发送并进入远程流式 Agent。
