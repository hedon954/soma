# ADR 0144：HealthKit 每日运动记录与活动能量去重

- 状态：已采纳并实现；真机数据待验收
- 日期：2026-10-21
- 版本：0.0.30
- 维护者：Soma maintainers
- 部分替代：[ADR 0000](0000-origin-through-0.0.11.md)（日汇总无样本 cursor；自然日覆盖与真实来源）、[工程契约](../../CLAUDE.md)（三项只读接入）
- 上游依据：[PRD 075](../prd/075-healthkit-daily-activity.md)、[HealthKit 调研](../research/2026-10-20-healthkit-daily-activity.md)
- 下游落地：[验收](../acceptance.md)、[数据库结构](../engineering/database-schema.md)

## 背景

用户需要每日步数、距离、运动消耗形成一条现有运动记录，参与统计；不需要单独活动卡片或来源/读取时间展示。
COROS 通过 Apple 健康提供源事实，三项日汇总可能包含当天训练，不能重复计量。

## 决策

三项 HealthKit 日统计只读，默认 cumulativeSum 获取系统合并值；独立 separateBySource 查询仅保留逐日来源元数据，不加总来源数值。
每个自然日写一条 WorkoutEntry，externalSource 为 appleHealth，externalID 为 daily:yyyy-MM-dd，既有唯一 projectionKey 保障身份。
三个指标与 source 保存在新增可空 dailyActivityData；旧记录 nil，使用兼容的新增可空字段迁移。字段为空不伪造训练组、重量或时长。
成功结果按指标覆盖，失败/未完成不覆盖；三项均空删除记录。原样本不镜像，无样本 cursor。

根生命周期持有同步，MainActor 写入共享 Store 并保存，既有 ModelContext.didSave 使进展快照失效刷新。
前台重读近 30 日，额外历史日窗口有独立 owner；切空间、后台和断开取消，以 generation 拒绝迟到结果。
不另存日汇总文件；连接状态仍使用受保护且排除备份的独立文件。

能量投影从每日记录加载事实参考，动态估算按 [ADR 0145](0145-adaptive-energy-system.md) 统一计算；活动日合计不替代生活参考，也不与已计算的步行和训练重复相加。
现有训练记录仍显示原始热量；日/周/月/年图表、缺口及推荐目标共享同一去重投影。
这是本产品统计口径，不将活动读数解释为全天覆盖完整的证明。

个人库和目录采用 complete 文件保护并排除系统备份。应用备份/导出过滤 appleHealth 运动记录，内部恢复回滚快照保留字段。
模型上下文与读取工具过滤这些记录；无 Server/模型新数据流；最小训练只读权限见 ADR 0145，无健康写回。
断开只停止同步，已同步记录保留；清空/恢复删除记录与连接。用户在 Apple 健康修改源数据，后续同步覆盖。

## 未选择的方案

- 独立活动仪表卡：复用运动记录路径即可满足需求，不增加来源与时间元数据呈现。
- 在原系数 × 静息 + 训练增量上再加活动 kcal：活动及训练可能被重复计量。
- 手工相加来源、步数推算热量、构造训练明细：缺少事实依据。
- 新建样本镜像、后台交付或 Watch App：超出三项每日记录的范围。

## 结果

一个自然日对应一个稳定运动记录，既有列表、进展及能量统计共用数据。代价是个人库需要排除系统备份，应用备份过滤可重新同步的健康记录。
来源在数据中可追溯，页面只显示用户需要的三项指标。数据缺失和失败独立处理，不能由同步次数增加数值。

## 验证

确定性测试验证记录覆盖、部分失败、清空、来源、备份/模型边界、0/nil 与统计去重。旧字段兼容、空间隔离及完整 make verify 为门禁。
虚构数据界面检查不替代真实 COROS、权限、删除回调、锁屏保护和系统多来源合并的真机验收。
