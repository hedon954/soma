# ADR 0150：健康导入按自然日一条记录，列表去分组并随区间筛选

- 状态：已采纳并实现；真机健康授权、后台唤醒与真实旧库升级仍待验收
- 日期：2026-11-10
- 版本：0.0.35
- 维护者：Soma maintainers
- 部分替代：[ADR 0000](0000-origin-through-0.0.11.md)（健康身体测量的存储与展示）
- 后续替代：暂无
- 上游依据：[PRD 080](../prd/080-healthkit-body-mass.md)
- 下游落地：[验收](../acceptance.md)、[数据库结构](../engineering/database-schema.md)、[工程原则](../../CLAUDE.md)

## 背景

用户认为按天分卡使体重记录页复杂，希望 Apple 健康同步时每天只保留一条数据进入 Soma，用当天较晚的有效样本覆盖当日健康记录，并直接平铺所选时间区间内的列表；每一条天然代表一天，不再需要日期分组、条数和折叠。体重与体脂仍是 HealthKit 中的独立样本，不能因为一次只同步到体脂就抹掉体重，也不能把同日不同时间伪称同一次测量。手动/教练记录不得被健康同步删除或压缩。

## 决策

1. 健康导入的产品记录改为每个本地自然日一条 `BodyEntry`：`externalSource=appleHealth`，稳定键 `externalID=bodyDay:<yyyy-MM-dd>`。日边界使用设备当前日历的 `startOfDay`。时区切换可能导致个别样本落在相邻日，不另做跨时区重放。
2. 当天各指标独立取最后一次有效样本组成日摘要：后到或更晚的体脂只更新体脂，不清空已有体重，反之亦然。乱序到达时，只有不早于已存样本（同时间再以样本 UUID 字符串决胜）才覆盖该指标。
3. 各指标保留真实采样时间、来源名、bundle 与 HealthKit 样本 UUID（`healthDayEvidence`）。列表不得把不同时间写成同一次测量；详情按指标分别展示时间与来源。同日多来源仍只一条健康日记录；仅当当日已有指标的来源身份一致时才展示单一品牌图标（如官方 Keep），否则使用中性图标并如实列出多个来源，不谎称全来自 Keep。
4. 增量仍用 `HKAnchoredObjectQuery` 与现有 `bodyMass` / `bodyFat` 游标。锚定增量只用于发现受影响日与应用更新；当已存获胜样本被 HealthKit 明确删除时，对该日该指标做有界重查，回退到上一有效样本，若该指标已空则只清空该指标，两条都空才删除这条健康日记录。重查失败、权限拒绝或无法与「暂无样本」区分的空结果，以及空增量，都不得擦除本地健康日记录。
5. 不再把原始 HealthKit 样本作为产品列表中的 `BodyEntry` 长期保存。现有 `bodyMass:` / `bodyFat:` 健康行按本地已导入样本做幂等折叠：按日取各指标最后一条写入日记录，然后只删除这些已被折叠的健康样本行。手动/教练行（`externalSource==nil`）及已存腰围字段一律保留。若无法向 HealthKit 做全量重查，就只依据本地已导入样本重建，不猜测删除用户数据。
6. 手动记录不按天压缩，同日可与健康日记录并存；健康同步不得改写或删除它们。健康导入行仍只读。备份/导出与教练批量身体历史仍过滤 `externalSource=appleHealth`。断开、代际与空间守卫不变。
7. 「体重记录」列表取消日卡头、记录数、折叠与分组，改为按时间倒序平铺；日期只在行内出现一次（展示该条的自然日，不单用一个时钟时间冒充双指标采样时点）。一周／一个月／三个月／一年（默认一个月、锚定真实现在的日历半开窗）同时筛选趋势图和列表；窗口过滤在查询层完成，加载该窗内全部记录，避免分页偏移漏掉窗内较早记录。

## 未选择的方案

- 仅在展示层继续按同秒或同日配对，持久化仍保留全部原始样本行。
- 把手动记录也压成每天一条，或健康同步删除手动行。
- 删除全部 `BodyEntry` 后重导；无权限时猜测清空历史健康记录。
- 同日不同来源仍展示单一 Keep 图标。
- 区间只裁图表、列表继续全量并按日分卡。

## 结果

列表更简洁，健康数据按天收敛且体重与体脂可同列；代价是失去产品层的完整原始样本清单，删除回退依赖有界 HealthKit 重查，本地折叠在尚未导入的样本上可能暂时不是「当天全局最后一条」，下次成功同步后再收敛。

## 验证

确定性测试覆盖按日更新与覆盖、同日多次与多源、双指标互不擦除、删除回退、乱序重跑、历史样本行折叠且手动保留、拒权/空结果不擦除、日边界与区间查询。`make verify` 为门禁；模拟器夹具验证每日一行、区间同步列表、无分组冗余、明细区分来源时间、浅深色与大字号末行。真机授权、后台与真实旧库升级另记。
