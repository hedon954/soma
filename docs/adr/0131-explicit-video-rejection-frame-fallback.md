# ADR 0131：明确拒绝视频后使用有界画面回退

- 下游落地：[BUG 0063](../bugs/0063-explicit-video-rejection-has-no-compatible-input.md)
- 状态：已采纳，已实现
- 日期：2026-09-10
- 版本：0.0.23
- 上游依据：[PRD 063](../prd/063-video-compatibility-and-actionable-errors.md)
- 部分替代：[ADR 0000](0000-origin-through-0.0.11.md)（视频不支持时拒绝抽帧；语音、原件保留与其他决策不变）
- 下游落地：[ReAct 协议](../react-agent.md)、[远程 Job 协议](../engineering/agent-job-protocol.md)、[验收](../acceptance.md)

## 背景

完整视频请求在模型仅接受图片时被拒绝。用户明确要求继续利用画面，同时保留原始媒体和
既有工具结果，因此需要受控且可恢复的兼容路径。

## 决策

模型请求默认保留完整视频。只有可验证的 video_url / video 输入能力拒绝或明确配置的不支持，
才将当前尚未产生有效增量的模型请求切换到画面输入一次，不重启整个 ReAct Turn。
HTTP 400/415/422 的明确不支持信号可判定；401/403、429、5xx、超时、取消和泛化 invalid request 不行。

设备使用系统视频解码均匀覆盖完整时间范围，单视频目标数量为 `min(24, max(8, ceil(时长秒数 * 2)))`。
多个视频共享最多 24 张，每个先分配 8 张再轮流增加；超过 3 个视频或不可解码时明确失败。
最长边 768、JPEG 编码、总原始画面数据最多 8 MiB，取消时释放解码任务与临时文件。

画面只追加到原视频所在用户消息，不移动历史引用，不覆盖既有照片。回退提示作为受控过程状态，
模型提示说明静态画面限制，不向正文预写“完整视频分析”段落。模型上下文与恢复保留回退模式，
已经完成的工具批次仍按既有幂等与 checkpoint 协议恢复。

远程模型输入增加可选的视频到备用画面清单，包含时间与时长；不改变身体业务数据库。
服务器声明回退能力，验证清单、引用和预算。Provider 使用完整视频时排除备用画面；明确拒绝后
只切换本次模型请求，后续步骤与重启从持久事件确定使用画面。旧任务没有备用画面时明确失败，
不能静默丢弃视频。App 不因服务器缺少此能力而假装视频已经分析。

## 结果

不支持完整视频的模型仍可分析抽样画面，但不能据此判断完整节奏或连续轨迹。
采样有明确数量、体积与时间范围限制；App 和服务端必须共同实现模式恢复。

## 未选择的方案

不把所有错误视为视频不支持；不无条件抽取大量帧；不只取开头；不在产生输出或工具参数后重发；
不重跑已完成的业务工具；不把画面发送失败降为纯文本；不新增服务器任意解码或业务工具权限。

## 验证

错误判定与预算使用纯函数测试；虚构可播放视频验证尺寸、覆盖、取消和空结果；本机/远程请求体、
工具幂等、模式持久化及恢复分别回归，完整门禁与真机证据分别记录。
