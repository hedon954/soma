## 背景

COROS 活动日汇总不覆盖全部低强度生活活动，不能据此停用生活系数；日汇总也无法区分跑步步数与日常步行。
个体消耗需要结合长期证据估算，并能回看每次调整依据。

## 决策

计算基于可编码 Sendable 值类型，由本地纯函数产生每日组件、排除理由和校准候选。
固定 Tool 只写用户明确事实；HealthKit 适配器只读最小类型，健康推导不进入模型上下文。
持久化区分源事实、参考版本、每日估算与校准评估；引用和必要快照支持复算，重复输入幂等。
新增 EnergyContextEntry 和 EnergyEvidenceEntry 两个独立表，不改变旧身体记录；前者保存用户事实，
后者保存私有健康推导。内部回滚快照保留两表，应用备份移除推导依据；旧备份缺项按空表恢复。
View 只呈现共享投影，不重新实现热量公式。
record_energy_context 为固定事实写入工具，两端 Schema 同步；按用户明确的日期范围覆盖事实，
最多 31 日，不扩张确认范围。工具只返回事实保存结果，不返回私有健康推导。
饮食完整性绑定餐食输入指纹，用户只编辑生活信息不会自动重新确认已经变化的餐食。
生活事实指纹参与参考选择，修改或删除后不继续采用失效来源建立的参考；原历史证据仍可审查。

当前总消耗已由 [ADR 0151](0151-training-energy-in-total.md) 改为静息 × 残差系数 + 所选日活动能量 + Soma 已记录训练消耗。下列参考日差额和「日活动能量不再相加」只保留为当时的决策，不再作为当前总量。

每日计算当时采用研究指定的参考日差额和训练时段替换；动态系数为总估算与静息的比值。
设备日活动能量当时不替代基线，也不再与已经计算的步行和训练相加。
训练原始身份或显式关联决定去重；仅时间重叠视为冲突，不能擅自合并或重复入账。
区间外步行使用一致来源统计，不能从多源日总量减单源训练距离。
WorkoutEntry 新增可空 calorieScopeRaw，旧库为空时保持未知。MET 公式结果明确标记 metGross，
用户值仅在有明确证据时标 active 或 gross；修改其它训练字段不得覆盖用户提供的热量。
create_workout / update_workout 增加可选 calories_scope（active / gross / unknown），模型不能声明 metGross。
训练关联存在私有 EnergyEvidenceEntry.association 修订，包含自然日、时区和明确的一对一身份；
解除生成新修订。按 Session 聚合本地全部动作的净能量，再优先采用关联设备的有效能量，设备
缺能量时回退到整场本地估算。未知时段且有其它来源时暂不累加这条未知训练。

近期习惯水平采用合格结束日的 ΣT/ΣR。未来七日优先采用有效的明确计划和已知目标，缺项不补零；
无计划才使用至少三个完整同星期日。计划预测沿用本地 MET 近似、扣除被替代时段，单独呈现，
不存成实际运动、正式缺口或校准输入；日期到来后采用事实。过期或待重新锚定的计划停止给数值。

长期学习只拟合一个 kcal/天修正 C，不同时推断个人静息、步幅、MET 和饮食漏报。
门槛、趋势敏感性及每周控制参数与 PRD/研究一致；累积越界暂停，不无限漂移。
校准启动需独立留出验证；评估冻结采用的参数和输入指纹，以生效时间向前应用。
重算历史与当时估算明确区分，修订保留前驱；恢复生成新生效事件。

## 未选择的方案

不根据 COROS 日热量判定全天覆盖；不以零或缺样本推断缺失活动；不按一天秤重差推断脂肪消耗。
不将粗职业档、7700 或敏感性范围宣称为个人生理测量或统计置信区间。
不上传健康依据，不增加厂商 API、账户或服务端身体事实库。

## 验证

确定性单元测试、模拟/留出轨迹、旧库兼容、删除和重算、来源/备份边界、统一投影、双主题及完整 make verify。
真实个体准确度与设备权限交互不能由公式演算、截图或安装元数据替代。

## 结果

用户无需挑选系数，每日活动和长期修正有统一且可复算的来源。成本是新增本地证据持久化、
最小训练读取与完整性事实；自动校准必须先验证，数据不足保持估算或暂停。
