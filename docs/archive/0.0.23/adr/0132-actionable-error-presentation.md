# ADR 0132：用户错误与机器诊断分离

- 状态：已采纳，已实现
- 日期：2026-09-10
- 版本：0.0.23
- 上游依据：[PRD 063](../prd/063-video-compatibility-and-actionable-errors.md)
- 部分替代：[BUG 0025](../../../bugs/0025-guided-recording-terminated-by-connection-reconfiguration.md)（普通录像提示附带技术标识的呈现要求）
- 下游落地：[BUG 0064](../../../bugs/0064-raw-errors-without-recovery.md)、[错误呈现清单](../../../engineering/user-facing-errors.md)、[远程 Job 协议](../../../engineering/agent-job-protocol.md)、[验收](../../../acceptance.md)

## 背景

各页面直接使用 SDK 错误、服务商 JSON 或内部 ID，用户无法确认操作结果，也无法据此恢复。
录像错误已有原因分类，但把诊断标识放在主提示里；启动失败直接展开完整诊断。

## 决策

`AppErrorMessage` 是呈现边界，按真实类型、系统域、状态码与受控错误分类给出原因及下一步。
未知原因明确保持未知，不将所有失败归因为网络，不输出服务商响应或内部标识。
App、Views、Components 不读取 `localizedDescription`、`displayDescription` 或 `errorDescription`；
由仓库静态门禁检查。既有中文业务验证可以保留，但必须有可执行的恢复建议。

远程 Provider 以稳定错误分类区分授权、额度、限流、长度、视觉能力、配置和临时故障。
原始响应仅有界用于内存分类，不持久化或直接呈现；限流可以进入已有瞬态退避，额度不足不重试。
恢复文案只能指向当前实际存在的入口，不要求用户操作未开放的远程设置。

工具协议保留机器可读失败以供模型纠正参数；UI 对已落盘的旧失败另做安全呈现，不改写恢复事实。
录像阶段与技术码留在诊断；启动详细诊断由用户展开或导出。普通提示保留具体可确认原因，
已经保存的业务记录和可播放的部分录像不得被描述为丢失。

## 结果

错误文案集中维护且能通过确定性测试验证。新错误类型必须明确分类及真实恢复入口；
不能仅为满足文案规则吞掉原因，也不能将安全诊断内容重新塞回普通错误卡。
不新增持久字段或迁移，既有远程事件 JSON 仅扩充稳定错误码。
