# ADR 0046：LLM 配置直接摊开，候选值统一为输入历史式建议

## 背景

[ADR 0025](../../0.0.1/adr/0025-tiered-model-profiles-and-routing.md) 规定 `/models` 返回非空列表时只使用
Picker，理由是“避免重复控件和保存列表外的错误 ID”。PRD 020 又把 Base URL、图片生成模型
和档位切换折叠进「高级」，理由是渐进披露。

两条决策叠加后在真机上产生了三个具体故障：

1. Picker 无法输入列表外模型。供应商私有部署、灰度模型和 `/models` 未收录的新模型都填不进去。
2. Picker 的选择只存在于 View state。返回上一层时，父页面的 `onAppear` 先于子页面的
   `onDisappear` 执行，重新载入的旧值覆盖了尚未落盘的选择，表现为“选了模型但没保存”。
3. 折叠「高级」把配置本身藏了起来。用户进入这一页的唯一目的就是修改这些值；
   非预设平台必须先展开高级才能填 URL，等于让新平台无法配置。

渐进披露的适用对象是“审查时不需要看到的信息”，不是“进入这一页就是要改的字段”。
同一时期，聊天输入区的动作候选也暴露了相同性质的问题：候选被做成两级按钮，
先选动作再选最近训练，用户需要两次点击才能得到一条完整草稿。

## 决策

1. 「AI 服务」更名为「LLM 配置」。命名描述用户要配置的对象，而不是内部服务分层。
2. 档位从「高级」里的 Picker 提升为页面顶部的分段控件：标准模型 / 小模型。
   两档共享同一套字段布局，切换即载入该档配置。
3. 每一档在同一屏直接展示平台、Base URL、API Key、模型；标准档追加图片生成模型，
   小模型档追加启用开关。LLM 配置页不再有「高级」折叠层。
4. Base URL 对所有平台可编辑，不再区分“预设平台”和“其他”。切换平台预填该平台默认地址；
   用户改写后按 `平台 × 档位` 独立保存。
5. 模型是纯文本输入。`/models` 结果以「输入历史」式建议列表出现在输入框下方，
   点选即填入，也可以完全手输。列表为空或获取失败不影响输入。候选行只显示模型 ID：
   多模态能力属于「选定之后才需要知道」的信息，不在每行重复；候选不做条数截断，
   超过五条时列表自身滚动，露出的下一行同时充当可滚动的提示。
   能力说明只在模型非空时出现，占一行，并明确说明说的是多模态能力。
6. 配置字段即时落盘：模型、Base URL 与图片生成模型在值变化时立即写入，
   不依赖「完成」按钮、返回时机或 `onDisappear`。View 不再承担“最后一刻保存”的责任。
7. 刷新模型列表不覆盖非空模型值。只有模型为空时才用列表中的首选项自动填入。
8. 新增 `opencode` 平台，默认 `https://opencode.ai/zen/v1`。Soma 走 Chat Completions，
   该平台上只提供 `/responses` 的 GPT / Codex 系模型按不支持标注，Claude 与 Gemini 系
   标注为支持视觉，其余保持未知并由真实请求验证。
9. 「输入历史式建议」成为跨场景的统一组件：LLM 模型建议与聊天动作建议共用同一个纵向
   建议列表。建议行提供主文本与说明文本，点选一次即写入完整值。
10. 聊天动作建议一步到位：一行同时给出动作名与最近一次训练容量，来源是本地确定性合并
    （旧版训练记录 + 带练组数据，取最新有效值）。没有历史时只给动作名，不补默认数值。

## 未选择的方案

- 保留 Picker 并额外常驻手写框：ADR 0025 拒绝过的重复控件问题依然成立，
  两个控件写同一个值也会引入新的一致性问题。
- 用可编辑 `Menu` 模拟“可输入的下拉”：iOS 上没有原生形态，实现出来的交互既不像
  输入框也不像选择器。
- 继续用「完成」按钮统一保存：设置已经是底部 Tab，没有天然的“完成”时刻，
  这正是模型丢失缺陷的成因。
- 把 Base URL 继续留在高级、只为 `opencode` 开特例：会让平台列表的可配置性取决于
  Soma 是否预置，扩展性最差。
- 聊天建议改为多级菜单或 sheet：把一次输入变成一次导航，比现在的两次点击更重。

## 结果

### 正向影响

- 配置页的字段与用户意图对齐：进来要改的东西全部直接可见可改。
- 模型既能手输也能点选，私有部署与新模型不再被 UI 挡住。
- 即时落盘消除了一整类“返回后设置丢失”的缺陷，与页面呈现方式解耦。
- 输入历史式建议在配置页和聊天页保持一致的心智模型，聊天记录草稿从两步降到一步。

### 成本与限制

- LLM 配置页的信息密度高于 PRD 020 的其他页面，这是刻意的例外，不作为其他页面的先例。
- 手输模型 ID 允许保存无效值，错误只能在真实请求时暴露；错误文案需要保持可解释。
- `opencode` 的模型目录由平台维护，Soma 的能力标注是保守启发式，不是完整能力矩阵。

## 验证

- 单元测试覆盖模型建议在“列表为空 / 有列表 / 手输值不在列表中”三种情况下不被覆盖。
- 单元测试覆盖 `opencode` 的默认地址、端点拼接与多模态能力标注。
- 单元测试覆盖动作建议的确定性合并：只取最新有效容量，无历史时不编造数值，
  归档动作不出现，最多 5 条。
- 模拟器验证：手输模型 → 返回设置首页 → 重新进入，值保持不变；再次拉取列表也不覆盖。
- 模拟器验证：两档分段切换后字段独立，互不串写。
