## 背景

饮食、训练和 Agent 恢复已有单一事实来源，但聊天审查层仍暴露了几处平行语义：营养只要有一个
菜品缺字段就显示“未估算”；份数变化不能同步已有估算；旧训练记录还能用自身字段覆盖动作定义；
在途 Agent 也没有用户可见的停止入口。设置与消息元信息仍有不必要层级和不等距留白。

## 用户结果

1. 饮食汇总始终从菜品列表派生。全部菜品都提供某项营养时显示精确总计；只有部分菜品提供时显示
   `≥ 已知小计`，不再用“未估算”隐藏已有信息。
2. 用户只修改菜品“份数”且数量单位未变时，当前热量、蛋白质、碳水和脂肪按新旧数量比例缩放；
   修改名称、热量或任一宏量营养时不联动其他字段。
3. Agent 处理中的回复提供主动中断。中断保留已经完成的 Tool step 和业务写入，在同一回复进入
   人工屏障；用户点重试后走正常错误恢复链路，后续消息继续遵守 FIFO。
4. 聊天训练卡以动作定义决定次数/秒数及侧别，旧记录不能形成第二套配置源。聊天密度去掉重复卡层，
   保留与设计稿一致的动作头、目标/侧别标签、内联完成值、重量、间歇和连续组 `×N`。
5. 设置根页移除“更多”分组标题，低频入口直接平铺并按任务、后台、数据、隐私、高级排序；显示位于
   关于之前，反馈仍在最后。身体信息直接展示称呼与可选出生日期，不使用“填写出生日期”开关。
6. 处理中提示与消息时间使用同一左边界。AI 时间、执行日志、反馈三个可见元素保持等距，三个入口
   仍各自拥有不少于 44 pt 的触达区域。

## 真值与交互规则

- 已知小计不是完整总计，必须以 `≥` 表明下界；缺失字段继续保存为 `nil`，不能为了消除文案而补零。
- 份数联动只接受相同非数字单位的正数变化，例如 `1 颗 → 2 颗`；单位改变、无法解析、零或负数不缩放。
- 主动中断不是成功。它持久化取消事件并转为 `waitingForUser`，不得触发网络、前台或计时器自动恢复。
- 训练记录继续无损保存当次 evidence；动作定义只纠正展示与编辑语义，不伪造不存在的重量、间歇或录像。
- 出生日期未选择时保持 `nil`；展开日期选择器本身不等于用户已经提供日期。

## 数据、隐私与兼容

- 不新增 SwiftData 字段、模型注册或 PostgreSQL migration；既有个人与演示空间无需迁移或重建。
- 营养缩放只发生在本地可审查草稿，保存后仍走既有菜品派生汇总。
- 中断只新增本地已有 Job/Event 状态的确定性投影；远程任务使用既有取消端点，不新增身体数据或日志字段。

## 验收

- 单元测试覆盖完整/部分营养派生、同单位份数缩放、跨单位不缩放、其他字段不联动，以及动作定义把
  旧次数投影为秒数和全身侧别。
- Agent 测试覆盖主动中断进入 `waitingForUser`、同气泡取消事件、可重试投影与 FIFO 人工屏障。
- 模拟器检查聊天训练卡、处理中行、元信息等距、设置与身体信息的浅色/深色、Dynamic Type、键盘、
  滚动和安全区。
- `make check`、`make verify` 通过；真机中断手感和触达继续单列验收。
