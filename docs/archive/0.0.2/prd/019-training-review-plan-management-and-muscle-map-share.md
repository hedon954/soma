## 背景

v0.0.1 交付后，维护者按真实一周训练走查发现九类问题，集中在“记录回顾、计划管理、
带练反馈与视觉表达”四个层面：

1. 训练记录列表全量平铺，没有按天分组，也没有时间筛选和分页；数据积累后不可用。
2. 记录行有视频时显示黑底播放按钮缩略图，破坏列表视觉层级。
3. 教练回复的段落、列表在 UI 中黏连成一团。经排查是流式渲染缺陷而非模型输出问题：
   Markdown 完整解析模式会剥离换行并把块结构存入属性，现有渲染没有重建段落。
4. 训练历史行只显示“完成 N 个动作”，看不出执行的是哪个训练计划。
5. 训练计划归档后没有恢复入口，GUI 也没有删除计划的能力（Agent Tool 已有）。
6. 带练“录制本组”失败时既不弹提示也不解释按钮为何禁用。
7. AI 按需生成的动作图片风格互相不一致，也与 App 设计语言不协调。
8. 计划详情的“版本历史”只有 `v2 · 名称 · 日期`，没有任何变更信息量。
9. 动作肌群图依赖静态位图或 AI 生成，不稳定、不统一；同时缺少训练完成后的分享能力。
   参考同类产品的做法，肌群受力图应由程序按“逐块肌肉点亮”方式确定性生成
   （见 [ADR 0044](../adr/0044-programmatic-muscle-map-and-training-share-poster.md)）。

## 用户结果

1. 训练与饮食记录按自然日分组展示，标题下用「全部 + 实际有数据的月份」芯片筛选，点日期可折叠当天，
   滚动时分页加载；空筛选结果有明确空态（芯片与折叠由 PRD 034 修订）。
2. 训练记录通过 `exerciseID` 关联动作库：列表显示动作插画、规范名与主要肌群；详情展示
   关联动作元数据（插画、程序化受力图、教练提示）并可进入动作详情；视频仍在记录详情播放。
3. 教练回复保留模型原文的段落、编号列表和换行，长回复可读。
4. 训练历史每一行可以看到来源计划与版本（如“周训练力量一 · v2”）；自由训练不显示
   计划来源。
5. 用户可以恢复已归档的计划，也可以在二次确认后删除计划；删除计划不影响已完成的
   训练历史。
6. 带练中录像启动失败时，用户能看到自动消失的失败提示与具体原因；按钮禁用时能理解
   原因（如“正在开启相机”）。
7. 计划详情能看到该计划的执行统计：完成次数与近若干次的有效容量趋势；没有历史时显示
   空态引导。
8. 版本历史每一项直接展示相对上一版的变更说明（如“移除 引体向上；杠铃深蹲 4→5
   组”），无需长按或二次进入。
9. 每个动作的肌群受力图由程序根据主/次肌群确定性渲染；训练完成复盘可生成包含正背面
   受力图、统计与动作明细的分享图片，经系统分享面板分享。

## 产品规则

### 训练记录回顾

- 列表按自然日分组，组头显示“M月d日 周X”；组内按时间倒序。
- 筛选粒度为年、年月、年月日三级，未选择时显示全部；筛选条件生成日期区间下推到
  查询，不在内存全量过滤。
- 分页按固定页大小（约 50 条）滚动加载；筛选变化后从第一页重新加载。
- 左滑删除、详情跳转与既有编辑语义不变。

### 训练记录与动作元数据

- 每条 `WorkoutEntry` 应通过可空 `exerciseID` 关联 `ExerciseDefinition`；聊天写入与
  详情保存继续走既有 resolve/create 边界，不得只靠展示层临时猜名。
- 列表优先用 `exerciseID`，其次按规范名匹配已有动作；命中时显示动作插画、规范名与
  主要肌群。解析不到动作时回退训练图标；列表不再显示黑底播放按钮。
- 打开训练记录分页时，对当前页仅有名称、缺少 `exerciseID` 的旧记录做确定性回填：
  只绑定已存在的动作，不因回填创建未知动作（missing-is-nil）。
- 记录详情展示「关联动作」：插画、程序化肌群受力图、主要肌群与教练提示摘要，并
  可导航到动作详情；改名保存时若规范名变化则重新解析并写回 `exerciseID`。
- 视频入口保留在记录详情页，附件数据不变。

### 教练回复排版

- 修复流式 Markdown 渲染：完整解析模式下按块结构重建段落间距、编号/无序列表前缀，
  保留代码块与链接语义。
- 数据层继续原样累积模型文本增量，不得为排版修改或补写模型原文。
- 修复需要有可复现的确定性单元测试（多段落、编号列表、无序列表）。

### 训练历史与计划管理

- 开始带练时 Session 记录来源计划 ID 与计划名快照；历史行显示“计划名 · vN”。
  旧数据按模板家族 ID 反查兜底；查不到或无计划来源时不显示。
- 归档计划详情提供“恢复计划”，恢复后回到活跃列表，模板版本与历史不变。
- 计划详情提供系统 destructive 语义的“删除计划”，需二次确认；删除移除计划、全部
  模板版本与模板动作，但保留已产生的 Session、逐组事实与训练记录。
- 删除与恢复由 `TrainingPlanStore` 统一实现，GUI 与 Agent Tool 共用同一规则。

### 版本变更说明

- 新版本创建时确定性对比前后模板动作：新增/移除动作、顺序变化、组数/次数/重量/间歇
  变化，生成变更摘要与逐条明细，与版本一起持久化。
- GUI 编辑与 Agent 修改计划共用同一 diff 规则；v1 显示“初始版本”。
- 版本历史行直接展示相对上一版的变更说明（优先完整明细，否则摘要）。旧版本数据无
  摘要时按相邻版本现算展示。

### 带练录像反馈

- 录像准备、权限、启动、写入各失败路径都必须映射为用户可理解的中文原因与恢复建议
  （权限被拒引导去系统设置；会话中断建议重试）。
- 失败以自动消失的顶部提示（toast）呈现，不再只依赖易被忽略的行内文字。
- “录制本组”按钮禁用期间显示禁用原因；相机失败不阻断组事实保存（继承 PRD 014）。

### 程序化受力图

- 肌群受力图由程序渲染：正/背面分卡人体底图加逐块肌肉矢量路径，按动作的主/次肌群
  点亮，主肌群深、次肌群浅；正反面标注与引线肌群名使受力区域可辨（规则见
  [ADR 0044](../adr/0044-programmatic-muscle-map-and-training-share-poster.md)）。
- 动作已保存的自由文本肌群经确定性映射表转换为规范肌群；映射不到的肌群保持不点亮，
  不猜测补齐。
- 多动作叠加（如整次训练）时按各动作有效组数累加强度，再归一为高亮深浅分档。
- 动作详情与列表的通用肌群图改用程序化渲染；`muscleMap` 类图片不再提供 AI 按需生成，
  已存在的生成/上传肌群图仍可查看与删除。
- 动作插画（`actionIllustration`）继续遵循 ADR 0035：内置素材优先、可上传、可显式
  AI 生成；生成请求使用统一的风格约束模板，保持插画风格一致。

### 训练分享

- 训练完成复盘页提供“分享”入口，本地渲染分享图片：日期、计划名（如有）、左正背面
  受力图与右统计、动作与逐组明细、Soma 标识。
- 分享图不包含用户照片、视频帧、位置、备注、头像或训练天数；渲染完全在本机完成，
  仅经用户在系统分享面板中的显式选择离开设备。

## 数据与隐私

- 新增本地 SwiftData 字段：Session 的来源计划 ID 与计划名快照；模板版本的变更摘要
  与明细。均为可选字段，旧数据保持为空并按兜底规则展示。
- 肌群规范枚举、中文映射表与人体/肌肉矢量路径为包内只读静态资源；矢量路径移植自
  MIT 许可的开源项目并保留来源声明，不进入个人媒体、备份或导出。
- 受力图是通用肌群参与示意，不代表个人生理测量，不冒充医疗或体测结论。
- 分享图片本地渲染，不新增远程数据流；本需求不改变任何 Agent Tool 协议与远程边界。

## 明确不在范围

- 服务器端分享链接、社区或社交能力；分享只产出本地图片。
- 肌肉疲劳度、恢复时间或训练负荷建模；强度深浅只反映本次选中范围内的动作组数。
- 男/女多套人体模型与逐块肌肉交互选择；首版使用一套中性正背面模型。
- 用 AI 重绘既有内置动作插画；风格统一只约束新的生成请求。
- 训练记录编辑、合并与去重逻辑的任何改变。
- 新增或修改 Agent Tool（删除计划已有 `delete_training_program`）。

## 验收

- 训练记录按天分组；选择年、年月、年月日分别得到正确子集；滚动触发分页加载且删除、
  详情不受影响；无结果时显示空态。
- 含视频的记录行显示动作插画而非播放按钮；无法解析动作时显示回退图标。
- 构造多段落与编号列表的助手回复，UI 保留段落与列表断行；新增渲染单元测试通过。
- 从计划开始并完成一次带练后，训练历史行显示“计划名 · vN”；自由训练行不显示。
- 归档计划可恢复；删除计划需二次确认，删除后计划消失而相关训练历史仍可回看。
- 编辑计划产生新版本后，版本历史直接显示相对上一版的变更说明；diff 单元测试通过。
- 模拟器拒绝相机权限后手动录制，出现含原因的失败提示且训练可继续；真机补充录像
  启动失败场景的手工验收。
- 计划详情显示该计划的完成次数与容量趋势；无历史时显示空态。
- 任选两个映射肌群不同的动作，受力图点亮区域不同且主/次深浅可区分；正反面标注与
  点亮肌群标签可辨；映射不到的肌群不点亮；映射与强度叠加单元测试通过。
- 完成复盘可生成并分享图片，图片包含左受力图与右统计，不含照片、视频帧或位置。
- `make verify` 通过。
