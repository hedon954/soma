# PRD 038：历史会话标题长按编辑

- 状态：已实施，待真机触感与 VoiceOver 验收
- 日期：2026-08-22
- 修订自：[PRD 037](037-generated-editable-session-titles-and-single-row-composer-context.md) 的历史抽屉标题编辑入口
- 后续修订：暂无
- 上游依据：维护者要求移除会话行省略号，复用既有左滑删除，并由长按标题直接进入编辑

## 背景

PRD 037 首次加入可见省略号菜单，承载重命名、恢复自动标题和删除。但删除已经有原生左滑入口，
省略号重复暴露删除并增加了每行视觉噪声。标题本身就是编辑对象，更适合作为长按手势目标。

## 用户结果

1. 历史会话行不再显示省略号，标题获得更多横向空间。
2. 轻点会话行仍切换会话；长按标题直接弹出原有系统重命名框。
3. 删除仍只使用尾随左滑 destructive action，不增加第二个可见删除入口。
4. 手动标题的「恢复自动标题」进入同一个重命名框，不丢失 PRD 037 的标题优先级能力。

## 产品规则

- 长按只绑定标题文字，不把整行变成容易误触的编辑热区；最短识别时间为系统常见的半秒。
- 长按成功时不触发轻点切换；普通轻点仍保持原有选择语义。
- 重命名框继续限制非空与最多 40 个字符；保存失败继续显示可恢复错误。
- `manual` 标题的编辑框提供「恢复自动标题」；自动或兜底标题不显示该动作。
- VoiceOver 保留「重命名对话」自定义操作，并在会话行提示可长按标题重命名。
- 不改变标题生成请求、来源优先级、`updatedAt`、备份、数据模型或隐私边界；这些继续遵守
  PRD 037 与 ADR 0088。

## 验收

- 历史抽屉所有会话行均不显示省略号。
- 轻点非当前会话能切换；长按标题出现预填当前标题的重命名框，且不会先切换会话。
- 手动标题长按后可恢复自动标题；左滑删除仍可用并保持原有确认与在途 Job 门禁。
- VoiceOver 可发现重命名动作；长标题、大字号、浅色和深色下行布局不溢出。
- `make check`、`make verify` 通过。
