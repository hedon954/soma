- 上游依据：[PRD 000](../../../prd/000-origin-through-0.0.11.md)（聊天写入必须可审查；课程编排与聊天共用验证边界）

## 背景

训练计划编辑器要用户自己起名、选开始日，再把已有课程一天天排进周期。还没有课程时，编辑器只能提示先去建课程。难的是决定练几天、哪几天休息、用哪几堂课。这些事实已经部分留在课程、最近训练和当前健身房里，不该再做成另一张表。

## 用户结果

还没有进行中的计划时，「新建训练计划」右边有「教练来排」。左边仍打开现在的编辑器。

点击「教练来排」切到教练，并立刻发送一条由 App 写死的用户消息：

> 帮我排一份训练计划。先看我已有的课程和最近训练，只问会改变这轮安排的问题；确认后再给计划草稿，先不要保存。

没有 API Key 时走现有的发送前引导。这条消息和其他发送一样暂存，恢复后按 FIFO 补偿，不丢。

教练先用本机已有的课程、最近训练和当前健身房。只问会改变这轮周期、而且记录里还没有的事实，一次一到三个问题，并用现有的 `ask_user_questions` 展示。例如最近几周大多每周三次，就问这轮是否仍按每周三次，而不是重问目标、器械和伤痛。事实已经够，就不再追问。

每个问题都有可点的选项，并标明单选或多选。点选项只切换选中，不马上发送。单选同时只留一项，再点同一项会取消。多选可以同时留下多项。每题下方都有一个输入框，用户可以写选项里没有的话。整张提问底部有一次发送：至少一题选了选项或写了字才能发出。没选也没写的题不进入这句回答，也不替用户补上。发出后提问收起，回答进入下一轮教练；这一轮仍然不给计划草稿。

计划草稿可以直接带动作和逐组参数，或引用已有课程、计划；无需先创建课程。用户没提供的参数保持空白。

草稿出现在教练里，是本地固定卡片，不是模型编排的界面。卡片写出计划名、开始日，以及每一天是休息还是哪一堂课。「查看并修改」打开现在的计划编辑器，字段已经填好。用户改完点保存，才写入计划。关掉编辑器不保存。保存规则与手建相同：至少包含一个有效动作；若当时已有另一份进行中的计划，保存时把它归档。卡片在已有进行中计划时写明这一点。

提问失败、草稿校验失败或用户停止生成时，不出现可保存的计划。已经保存的课程保持原样。

## 产品规则

- 只有空的计划区显示「教练来排」。已有进行中计划时，仍从详情里的编辑入口修改。
- 点击即发送。不把这句话放进输入框等用户再点一次发送。
- 起草中的提问必须带单选或多选，并且每题都显示自填输入框。选项不绑定直接执行的工具。其他场合的提问仍是点按一项立即发送。
- 提问结束本轮，本轮不给出草稿。
- 不按常见分化、周一起始或固定天数补齐用户没说的安排。开始日没说就用今天。
- 草稿不改课程里的重量、组数和间歇。
- 打开教练不主动起草计划，也不预测今天该练什么。
- 同一轮可以重新给出草稿；卡片显示这一轮最后一次校验通过的草稿。两次给出不产生两份计划。
- 周期最长 14 天，与编辑器上限相同。

## 数据与隐私

不新增 SwiftData 字段，不把计划草稿存进服务器。点击发送的内容与平时给教练发一句话相同：这条固定消息，以及教练本就会附上的本机上下文。触发条件是用户点「教练来排」。失败时没有计划落盘；已成功写入的课程不撤销。

## 明确不在范围

- 不从已有计划的详情或编辑页发起替换。
- 课程引用不改源处方；直接动作可在草稿里填写参数。
- 不把「教练来排」放进教练输入区的快捷按钮。
- 不新做一套计划编辑界面。

## 验收

空计划区同时有「新建训练计划」和「教练来排」；已有计划时不显示后者。点击后教练出现上述用户消息并开始本轮；无 Key 时消息仍在，且不调用模型。

只缺一项会改变周期的事实时，本轮只有提问、没有计划。提问里每题都能单选或多选，每题都有输入框；只点选项不会发出。单选不能同时留下两项。多选可以留下多项，再点一次取消。只写字、只选选项、又选又写，都出现在同一条用户消息里；全空不能发送。事实足够时给出草稿卡片，数据库里仍没有新计划。卡片打开的编辑器带上草稿；不保存就离开，计划区仍为空。保存后有一份进行中计划，槽位与编辑器一致。草稿引用的内容不存在、全是休息、超过 14 天或缺少名称时，不出现卡片。缺少单选或多选标记、或把选项绑成直接执行的起草提问，不展示，并退回工具错误。

浅色和深色下两个按钮都能读清，触达不小于 44 pt。执行 `make check`、`make verify`。
