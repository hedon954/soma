# ADR 0139：教练页时间线是消息与无回合记录的投影

- 状态：已采纳，已实现
- 日期：2026-09-29
- 版本：0.0.26
- 维护者：Soma maintainers
- 上游依据：[PRD 070](../prd/070-coach-timeline.md)
- 部分替代：[ADR 0000](../../../adr/0000-origin-through-0.0.11.md)（仅教练列表的数据来源；聊天空创建路径、气泡与记录卡仍有效）
- 后续替代：暂无
- 下游落地：[验收](../../../acceptance.md)

## 背景

`CoachMessage` 是一次说话或一次回复，不是这一天全部身体事实的清单。带练写入的
`WorkoutEntry` 带有 `sourceWorkoutSessionID`，通常没有 `sourceTurnID`，所以按消息查询的教练页看不到它。

## 决策

教练列表的取数改为时间线投影：当前已加载消息，加上当前会话业务日中 `sourceTurnID == nil` 的
训练、饮食和身体记录，按 `occurredAt` 排序。同一次带练合并为一个列表项，项内仍用现有
`ChatRecordEditorCard`。消息项仍用现有 `CoachBubble`，滚动身份仍是消息 id。

投影不写回 `CoachMessage`，不进入 Agent 上下文。记录仍是唯一事实；卡只按业务 id 读取。

已加载窗口还有更早消息时，早于窗口内最早一条消息的记录不进入当前页。

## 未选择的方案

- 为带练补一条假的用户消息和教练回复。那会让模型把没说过的话当成上下文。
- 把 Agent 的 Trace、Job 和工具步骤提升成这条时间线。那些仍折叠在回复内部。
- 为时间线另做一套卡片外观。现有记录卡已经能审查这些记录。

## 结果

### 正向影响

- 当天的带练和事后才打开的教练页使用同一条时间。
- 统计、编辑和删除仍然只碰到记录本身。

### 成本与限制

- 比当前分页窗口更早的记录要等用户加载更早消息后才出现。
- 没有业务 id 的旧记录无法挂上现有记录卡，时间线会跳过它们。

## 验证

- `CoachTimelineTests` 覆盖排序、回合内记录不重复、带练合并，以及更早分页窗口。
- `make check` 通过。
