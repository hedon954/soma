## 背景

训练中的倒计时、休息、下一组和录像启停具有确定顺序。如果每一步都等待大模型，网络、延迟、
Token 和不可复现行为会直接打断训练。另一方面，要求用户每组重新回聊天确认会重新引入传统
录入摩擦。

用户明确启动计划后，“完成这一组”已经是用户直接确认的结构化事实，不需要模型再次解释。

## 决策

1. `GuidedWorkoutCoordinator` 由 App 生命周期持有，读取不可变 Session 计划快照。
2. 状态机固定为准备、动作说明、组前倒计时、执行、确认、休息、下一组和完成。
3. 用户确认完成、跳过、替换或修改实际值时，运行时直接保存 Session 草稿。
4. 这是 ADR 0002 的受控例外：聊天仍是非结构化训练和计划创建入口，带练只记录用户在已启动
   Session 中明确确认的执行事实。
5. 网络、远程 Agent 或 AI 建议失败不得阻止倒计时、休息、逐组保存和完成训练。
6. 每个动作的自动录像目标由 `firstSetIsWarmup` 确定：
   - `false`：第 1 组；
   - `true`：第 2 组。
7. 自动录像必须在本次 Session 开始时显式开启；之后对每个动作自动执行，直到暂停或取消。
8. 目标组倒计时后开始录制，用户确认完成时停止。每个动作默认只保留一段，可重录或删除。
9. 麦克风默认关闭，视频默认保存在 App 沙盒，不自动写入相册或发送远程模型。
10. 相机不可用、中断、后台、磁盘不足和热压力只降级录像，不改变训练状态机。
11. 训练结束先生成本地确定性总结。用户主动请求时，Agent 查询 Session 和所选媒体生成复盘，
    不重复创建训练事实。

## 未选择的方案

- 每组调用大模型决定下一步：增加网络依赖且无法稳定恢复。
- 通过视觉自动猜测任意动作开始和结束：第一版准确性不足。
- 全局永久开启自动录像：不符合显式同意和可预期相机行为。
- 所有动作固定录第 1 组：会经常只得到热身组。
- 相机失败时终止训练：录像不是训练事实的必要条件。

## 结果

### 正向影响

- 训练在断网和模型故障下仍可完成。
- 用户确认的逐组事实即时落盘，恢复点清晰。
- 每动作一段工作组视频降低遗漏和素材过多。
- 训练事实、原视频与 AI 反馈拥有不同生命周期。

### 成本与限制

- 带练成为聊天外的专用执行界面，但不新增顶层信息架构。
- App 进入后台后相机必须停止；返回时由状态机提示是否重录。
- 第一版不解决旁人入镜、场馆规则或任意动作实时纠错，由用户决定是否录像。

## 验证

- 状态机对暂停、恢复、跳过、替换、提前结束和 App 重建保持确定结果。
- 每次组确认都落盘；未确认组不会在异常退出后变成完成。
- 断网和 Provider 失败时仍能完成 Session。
- `firstSetIsWarmup` 两种路径准确选择第 1 或第 2 组。
- 暂停或取消后不再启动后续动作摄像头。
- 相机权限拒绝、中断、后台、磁盘不足和热压力不损坏训练数据。
- 录像进入导出评估、备份、恢复、清除和媒体引用回收。
