# ADR 0026：受限归档紧邻上一轮的健身房照片

- 状态：已接受
- 日期：2026-07-31
- 维护者：Soma maintainers
- 部分替代：[ADR 0024](0024-session-context-projection-and-compaction.md) 的历史媒体只读边界

## 背景

用户常先发送健身房照片，Agent 识别器械后再询问场馆名称。名称在下一 Turn 补充时，
`update_gym` 只收到当前 Turn 的空媒体数组，导致器械进入 `GymProfile`，照片却只留在
`CoachMessage`。把全部历史媒体交给所有 Tool 又会让旧照片误写入新记录。

## 决策

- 当前 Turn 的图片始终优先归入本次 `update_gym`。
- 当前 Turn 没有图片时，只有以下条件满足才解析紧邻上一轮图片：
  - Tool 是 `update_gym`；
  - 上一轮属于同一 Session；
  - 上一轮是紧邻当前 Turn 的用户 Exchange；
  - 上一轮确实包含图片；
  - 模型在 Tool Call 中明确传入 `media_source=recent_gym_turn`。
- App 在发给模型的紧邻历史 user message 中明确标注上述可引用值；模型只传语义引用，不接收
  或传回本机沙盒路径。App 再从同一 Session 的投影中确定性解析实际媒体位置。
- 不跨过中间 Turn 查找图片，不读取其他 Session，也不把历史媒体交给训练、饮食、身体等
  其他 Tool。
- Tool 明确要求 `recent_gym_turn` 但没有找到图片时失败并要求重新附加，不静默创建无图档案。
- `GymMedia` 保存全部去重后的照片；首图作为封面。
- 详情页缩略图只负责打开统一媒体查看浮层；删除入口位于浮层内，并采用“解绑”语义：从
  业务档案移除引用，聊天原件与系统相册不删除。

## 未选择的方案

- 把最近十轮全部媒体传给每次 Tool 写入：归属不明确且扩大误写范围。
- 把紧邻上一轮图片自动传给任何 `update_gym`：Tool 意图不等于媒体归属，可能把无关图片
  误绑到健身房。
- 让模型传本机媒体路径：扩大隐私暴露，也允许模型编造或引用越界路径。
- 删除业务照片时直接删除沙盒文件：同一文件可能仍被聊天或其他记录引用，会造成断图。

## 结果

### 正向影响

- “先发图、再补名称”能得到完整的健身房档案。
- 跨轮归档范围可测试，不会回退为任意历史媒体复制。
- 单张删除不会破坏聊天审查证据。

### 成本与限制

- 若用户隔了其他对话才补充名称，必须重新附加照片。
- 当前 `GymMedia` 只保存图片；视频仍作为聊天媒体和 Agent 分析证据。
- 业务记录解绑不会立即回收共享沙盒文件，文件生命周期继续由全局数据清理负责。

## 验证

- 单元测试覆盖模型显式选择后的跨 Loop 归档、未选择时不归档、禁止跨过中间 Turn、当前图片
  优先，以及显式引用缺图失败；请求测试确认紧邻历史消息包含可用引用值。
- 健身房删除封面后自动选择剩余最新照片，并同步器械缩略图。
- 训练、饮食、身体记录逐项解绑后，剩余媒体和旧兼容字段保持一致。
- 模拟器手工检查缩略图打开全屏查看、左右切换、图片缩放、二次确认和删除后的相邻项选择。
