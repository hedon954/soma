## 背景

用户会在后续消息中补充另一张照片或纠正 Agent 的识别。例如先发送一张午餐照片，随后补图
并说明“不是鱼肉”。模型会再次调用 `record_meal`；当前实现无条件插入，于是同一餐出现两条
记录，两张图也被拆散。训练、身体和健身房同样可能遇到多视角补充或纠错。

ADR 0016 的幂等回执只能阻止同一 Turn 的相同 Tool Call 重放，无法识别跨 Turn、参数已经
修正但现实事件仍然相同的情况。

## 决策

- 训练、饮食和身体记录增加可空 `sourceTurnID` 与 `sourceSessionID`，保存聊天来源。
- `query_user_data` 返回每条业务记录的稳定 ID。Agent 纠错时优先调用
  `update_workout`、`update_meal` 或 `update_body`，由本地按 ID 精确修改并合并当前
  Turn 的新媒体。
- 提供受限的 `delete_record`：只支持训练、饮食和身体记录，且本地必须再次验证用户当前
  消息存在明确删除意图。删除业务记录不级联删除聊天原文或共享媒体。
- 每次业务写入先执行确定性候选匹配，再决定新增或更新。
- 匹配必须综合多个维度，不能只比较标题或时间：
  - 来源 Turn/Session；
  - 时间距离；
  - 记录类型与餐次/动作等核心类别；
  - 规范化文字相似度；
  - 组次、重量、热量、宏量营养、体重等结构化数值；
  - 用户是否表达“不是、改成、补充、刚才”等纠错/补充语义；
  - 媒体是否重合或作为邻近补图出现。
- 同一 `sourceTurnID` 永远更新原记录。该无条件规则已由 [ADR 0077](../../0.0.7/adr/0077-same-turn-identity-merge-and-additive-inline-review.md)
  收窄：必须同时匹配动作或餐次身份；不同动作各自成条。
- 跨 Turn 只有唯一候选达到高阈值时才合并；歧义时新增，避免误吞两次真实事件。
- 合并媒体时按 `kind + path` 有序去重并追加，不复制文件。
- 纠错命中时，新提供的非空事实覆盖旧 AI 估算；没有新证据的字段继续保留，不能用 `nil`
  擦除已有用户事实。
- 非纠错的重复命中只补齐缺失事实，并保留更早的事件时间。
- 健身房继续按规范化名称更新；媒体、器械也按稳定名称或路径去重。
- 外部健康数据仍优先使用外部 ID 去重，不参与聊天语义合并。

## 旧数据修复

- 启动时只自动合并非常明显的旧重复：
  - 时间接近；
  - 同类型；
  - 核心标题/动作高度相似；
  - 关键数值一致或互补。
- 合并后保留更早记录 ID 和时间，追加去重媒体，再删除冗余记录。
- 低置信候选不自动处理，避免不可逆地合并真实独立事件。

## 未选择的方案

- 只按一分钟时间窗去重：会吞掉真实连续记录。
- 只按标题去重：模型措辞变化会漏判，同名餐食也可能是两次进食。
- 让模型凭语义猜数据库 ID：模型只能使用查询工具实际返回的 ID，本地还要验证类型与存在性。
- 永远新增再让用户手工删除：破坏审查体验，也使趋势短期重复计数。

## 结果

- 多图和后续纠错聚合到同一现实记录。
- 记录合并仍由本地可测试规则决定，不依赖最终自然语言。
- 多维阈值宁可保留歧义重复，也不静默合并证据不足的独立事件。
