# ADR 0041：训练计划与带练使用一级训练 Tab

- 状态：已采纳
- 日期：2026-08-04
- 维护者：Soma maintainers
- 部分替代：
  - [ADR 0002](0002-chat-write-path-review-gui.md) 的仅“教练 / 进展”顶层结构
  - [ADR 0030](0030-deterministic-guided-workout-and-session-recording.md) 的“不新增顶层信息架构”范围
  - [ADR 0036](0036-gui-training-program-authoring.md) 的“进展 → 训练计划”入口与“不新增训练 Tab”判断
- 后续替代：暂无
- 上游依据：[PRD 016](../prd/016-training-primary-tab.md)

## 背景

计划带练已同时承担继续 Session、开始训练、新建/编辑计划与执行历史等高频任务。把它作为“进展”的
一个记录索引行，需要先进入趋势页再导航，执行路径与用户“现在开始练”的意图不匹配。

## 决策

将现有 `TrainingProgramLibraryView` 原样迁移为底部一级“训练”Tab，位于教练和进展之间；页面按进行中
Session、计划库与执行历史组织。`InsightsView` 移除重复训练计划入口，继续承担记录审查与趋势。

这是入口迁移，不改变训练计划、Session、录像、聊天 Tool、数据空间、备份或本地优先边界。

## 未选择的方案

- 在教练输入框附近长期放置计划库：会挤占聊天主任务，也不适合浏览、编辑和回看多个计划。
- 仅在进展页顶部强化计划卡：仍需先进入不以执行为目标的页面。
- 新建一套“今日训练”数据模型：会与不可变模板和 Session 事实分叉。

## 结果

计划与带练成为可发现的高频入口，聊天仍可低摩擦启动计划，进展页的信息目的更单一。模拟器验证 Tab
顺序、计划迁移与继续 Session；真机验证底部导航、开始/恢复带练和横竖带练返回后的 Tab 状态。
