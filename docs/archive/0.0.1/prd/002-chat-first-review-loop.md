## 产品收敛

核心交互从“用户选择类型并填写表单”调整为“用户直接告诉教练发生了什么”。图片、视频、文字和语音进入同一个对话，AI 自动判断意图、提取字段、调用记录能力并更新统计。

产品因此只保留两个顶层界面：

- **教练**：沟通、上传媒体、系统语音输入、当前健身房快捷切换；
- **进展**：回看记录、纠正数据、查看趋势。

“少即是多”不等于隐藏事实。创建动作由聊天完成，但 AI 生成的事实必须有明确的审查出口。

## 教练页要求

1. 文字、照片、视频和 iOS 系统语音输入共享同一个发送入口。
2. 健身房切换是训练建议的高频上下文，因此放在输入框上方的紧凑控件；完整管理仍位于设置。
3. 数据空间切换属于低频开发/演示能力，只放在高级设置，不能占用聊天页顶部或造成误触。
4. 对话文本支持 iOS 原生划句选择与复制，而不只是整条消息复制。
5. 用户离开聊天页后，只要 App 进程仍存活，当前解析应继续执行。
6. 用户可以看到正在分析、加载 Skill、执行工具或生成回复等实时状态。

## 审查与 CRUD

### 最近记录

进展页必须提供训练、饮食和身体记录的最近列表入口，而不是只有聚合统计。

### 记录详情

- 训练：动作、日期、组次、重量、间歇、时长、评分、负荷判断、反馈、原始文字、图片或视频。
- 饮食：餐次、食物、热量、宏量营养、说明和食物图片。
- 身体：体重、体脂、腰围、说明、AI 观察和体态图片。
- 健身房：全部环境/器械图片、AI 环境总结和器械列表。

详情页进入即编辑；有修改时出现保存键。禁止把“编辑”再藏进操作菜单。

### 删除

列表使用 iOS 惯用的左滑删除。删除动作为红色垃圾桶图标，不额外重复显示“删除”文字。

### 数据真实性

- 用户没有说出的字段保持为空，不能用常见值补齐。
- 例如用户只说“俯卧撑 12×4”，可以记录 4 组、每组 12 次和自重，但不能自动写入 60 秒间歇。
- UI 对空值不展示伪占位数据；编辑时每个字段始终保留名称，不能只依赖输入前的 placeholder。
- 器械识别的置信度百分比不对用户展示。它不等于器械质量，也不能帮助日常审查。

## 统计要求

### 连续性

- 视觉结构与 GitHub contribution graph 对齐；
- 显示月份、星期与强度图例；
- 每个方格对应自然日，不能因时区或小时边界错位。

### 体重趋势

- 支持周、双周、月、季四种粒度；
- 支持左右拖动历史窗口；
- 只有存在可比较的完整前周期时才展示环比。

### 训练容量趋势

- 与体重趋势同级展示；
- 由记录实时计算，而不是维护一份可能失真的手工汇总；
- 单条训练容量为 `组数 × 次数 × 重量`；
- 缺少任一必要字段或自重无外部负重时，不伪造容量；
- 同样支持周、双周、月、季和横向拖动。

## 演示与个人数据

App 内置虚构图片和结构化演示数据，以展示完整闭环。演示与个人数据使用彼此隔离的数据空间；切换不会复制、合并或删除数据。正常用户不需要频繁操作这一能力，因此入口位于高级设置。

## 被替代的设计

- 被替代：训练/饮食/身体分别手动新增。
- 被替代：首页五栏式功能导航。
- 被替代：聊天页左上角演示/个人切换。
- 被替代：器械列表右侧的置信度百分比。
- 被替代：详情页中的“更多操作 → 编辑”链路。
- 被替代：缺失训练字段自动套用默认间歇或时长。
