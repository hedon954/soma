# PRD 055：动作分类与餐次明细

- 状态：已采纳
- 日期：2026-09-05
- 修订自：[PRD 000](../../../prd/000-origin-through-0.0.11.md) 的动作库浏览与日摄入明细
- 下游落地：[ADR 0118](../adr/0118-exercise-facets-and-meal-colors.md)
- 后续修订：[PRD 057](../../0.0.22/prd/057-coach-focus-progress-rings-and-library-clarity.md) 去掉受力肌群轴，动作模式改为类型，搜索改到右侧；摄入／消耗／宏量明细不再重复卡面已有汇总

## 背景

动作库只有名称搜索，难以按训练意图缩小范围；摄入明细缺少餐次，且所有条目同色，难以区分。

## 用户结果

- 动作库左侧常驻多级列表，点击部位及下级主要肌群、动作模式或受力肌群，右侧立即显示结果；顶部名称搜索与当前分类取交集。
- 返回动作库保留筛选和搜索；空结果可重置，缺少资料的动作仍能通过「未标注」找到。
- 点开当日摄入，每条餐食前显示早餐、午餐、下午点心、晚餐或加餐，色标与数值使用该餐次固定配色。

## 产品规则

- 身体部位取主要肌群，一个动作可以属于多个部位；部位下级列主要肌群，独立的受力肌群分支包含主要与辅助。
- 动作模式与精确肌群名称来自当前动作定义，保留自定义标签；不修改原数据、不把辅助肌群提升为主要。
- 一次选择一个分类路径并立即生效，不弹出筛选表单；左右列表独立滚动。已归档动作继续单独分组。当前页面保留分类与搜索，不跨启动持久化。
- 早餐橙、午餐绿、下午点心青、晚餐紫、加餐珊瑚色；始终同时提供文字，不能只靠颜色识别。
- 未知餐次写「餐次未记录」，未知热量写「未估算」，真实零仍显示 0 kcal。明细只列分项，不重复卡面
  已有的摄入／消耗／宏量汇总。
- 周月年仍按已结束有效日显示日期明细，不把按日聚合伪装成一餐。

## 数据与隐私

只派生现有本地记录，无持久字段、迁移、外部请求或新的用户资料；测试使用虚构数据。

## 明确不在范围

器械、难度和训练类型的自动猜测、全网动作目录、记录重新分类或回填。

## 验收

分类路径、主要与辅助身份、多部位、未标注、自定义名称和重置有确定性测试；双主题、长文本、键盘、滚动与安全区模拟器渲染验证。餐次投影与配色对比度测试通过，提交前运行 `make verify`。
