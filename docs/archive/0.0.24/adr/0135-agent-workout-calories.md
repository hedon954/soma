# ADR 0135：训练工具优先采用用户提供的热量

- 状态：已采纳
- 日期：2026-09-12
- 版本：0.0.24
- 上游依据：[PRD 000](../../../prd/000-origin-through-0.0.11.md) 的可编辑训练热量
- 部分替代：[ADR 0000](../../../adr/0000-origin-through-0.0.11.md) 的训练工具热量写入规则，MET 公式保持不变
- 下游落地：[BUG 0065](../../../bugs/0065-agent-workout-calories-ignored.md)、[验收](../../../acceptance.md)

## 背景

现有训练热量已支持用户在界面编辑，但聊天工具尚未接入同一能力，用户提供的热量被公式结果覆盖。

## 决策

`create_workout.workouts[]` 和 `update_workout` 支持可选整数 `calories`：用户在文字或图片中
明确提供时，模型原样传入并保存；未提供时，模型省略参数，由现有 MET 公式计算。
修改时省略也按现有公式重算；缺少计算依据仍为空。

复用 `WorkoutEntry.estimatedCalories` 和现有 `calorieOverride`，不新增持久字段或迁移。
创建回执使用实际采用的值，提供热量时不再回复被覆盖的 MET 数值。
批量调用的幂等签名包含各条 `calories`，省略、零和不同数值互不混淆。

这是当前 schema 4 的可选参数扩展，旧调用省略该字段的行为保持一致。App 与 Server 同步声明，
远程执行需要包含此扩展的服务端版本。固定提示词、字段说明和内置训练 Skill 共用同一规则。

## 结果

用户给出的热量能直接创建和修改记录，缺省输入继续使用确定性计算。数据结构与现有编辑能力不变。

## 验证

创建／修改各自有值、无值的完整工具写入回归，以及零、缺体重、幂等签名和远程 Schema 校验。
执行 `make check`、`make verify`。
