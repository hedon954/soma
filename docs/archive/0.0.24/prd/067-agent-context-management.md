# PRD 067：会话上下文与跨轮连续性

- 状态：已采纳，已实现
- 日期：2026-09-12
- 版本：0.0.24
- 修订自：[PRD 000](../../../prd/000-origin-through-0.0.11.md)（Agent 历史窗口与压缩）
- 下游落地：[ADR 0137](../adr/0137-agent-context-management.md)

## 用户结果

连续交谈最多保留最近 30 个完整来回，历史文本估算超过 30,000 tokens 或轮数超过 30 时，
仅将实际移出的内容压缩。恰好达到门槛不压缩；最新单轮不切半。门槛是应用历史预算，
不假定所有模型容量为 256k，也不等于含媒体、System 和当前输入的请求上限。

历史中的相对日期绑定原消息；新一轮拥有新的时间和执行状态。排队与重试保留发送语境及
已成功的写入。用户更改配置从下一轮生效，恢复不能混用新旧 Prompt。

空会话直接开始；压缩不可用时采用有界确定性摘要并保留来源。上下文或请求体超限需要
明确的恢复提示，不重新执行成功工具。原聊天及媒体留在设备，摘要不是业务事实来源。

## 隐私与范围

仅向用户配置的模型提供完成当前任务所需的上下文；历史媒体按明确回指选择。持久化使用
现有 Job 与摘要容器，禁止保存私有 thinking、额外日志或密钥。不新增 UI 或自动恢复屏障例外。

## 验收

按 [实施方案](../../../../.codex/plans/2026-09-12-agent-context-management.md) 第 11 节验证轮数/token
边界、跨日、排队、配置更新、恢复、摘要失效、媒体保留和缓存观测；执行 make verify。
缓存收益需要实际供应商数据，测试通过不能代替命中率或回答质量验收。
