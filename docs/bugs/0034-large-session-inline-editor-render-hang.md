# BUG 0034：大会话内联编辑器导致卡死退出

- 状态：已修复，待真机连续交互复验
- 发现日期：2026-08-25
- 影响范围：教练历史会话切换、包含较多菜品的最新饮食结果卡
- 上游依据：无
- 下游落地：暂无

## 症状

数据较少的 Session 可以正常切换；进入一个包含较多结构化饮食明细的 Session 时，点击已经生效，
但教练页长时间无响应，动画和触摸一起停住，随后 App 可能被系统终止。模拟器里的普通长文本夹具
不能稳定复现，真机真实结构化卡片可以稳定触发。

## 根因

故障 Session 的消息数量和正文都很小，数据库读取不是瓶颈。最后一条 AI 回复引用了一份十项饮食
记录，因为它是最新回复，`InlineMealCards` 立即进入可编辑形态。每个菜品行会同时创建菜名、热量、
份量和四项营养值的原生 `TextField`；`ViewThatFits` 还会构建多套候选布局。一次会话切换因此在
主线程集中创建、测量和布局几十个 TextKit 输入控件，放大 AttributeGraph 和键盘输入系统成本，
最终表现为主线程长时间卡死，而不是 Session 点击或 SwiftData 全库查询失败。

## 修复

- 内联数值默认使用同样排版的轻量文本按钮，只有用户点中的单个值才创建 `TextField` 并取得焦点。
- 聊天菜品行不再用 `ViewThatFits` 双候选布局；饮食评价用行数限制代替 PreferenceKey 测高。
- 菜品未变时自动保存不再清空升糖评价；隐藏的进展 Tab 延后到可见时再重算快照。
- 失焦或提交后立即释放该输入控件；完整草稿、保存、删除和缺失值语义保持不变。
- 撤销未验证的 UIKit 会话手势覆盖层，继续使用已经通过回归的原生按钮、长按重命名和侧滑删除。
- Agent 原始 stream 继续由私有 reader actor 读取；触及 SwiftData/Observation 的异步投影回调保持
  `@MainActor`，不以性能为由破坏 BUG 0024 的并发安全边界。

## 回归门禁

- 自动化测试或静态检查：长流 UI 夹具新增十项虚构饮食卡；切入该 Session 后必须完成渲染，未点
  编辑时 `meal-inline-value-editor` 数量必须为 0，同时保留会话点击、长按重命名和切回长流会话。
- `make check` 同时要求 stream reader 不整体绑定 MainActor、投影回调显式标注 `@MainActor` 且为
  async，防止性能优化再次绕开 SwiftData actor 边界。
- 手工验收：真机覆盖安装后直接打开故障 Session，连续执行历史抽屉开关、小/大会话往返、长按
  重命名、点按任一营养值编辑和四 Tab 切换；进程不得退出，触摸不得出现秒级冻结。
- 仍无法自动化的风险：真机 TextKit、键盘与 120 Hz 动画的最终手感仍需在真实数据上确认。

## 验证

- 真机数据库只读统计确认故障 Session 只有 12 条消息，异常负载集中在最新十项饮食内联卡，不是
  消息总量或正文大小。
- Simulator 定向 UI 回归通过：大会话约一秒内切换完成，默认原生字段编辑器为 0，长按重命名和
  切回长流会话均成功。
- `make check` 通过。
- Team `6C6NQVDA4M` 覆盖安装并直接启动到原故障 Session；新进程连续观察十秒仍存活。点击、编辑
  和跨 Session 的最终真机交互确认仍待完成。
