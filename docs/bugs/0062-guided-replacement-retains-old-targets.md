# BUG 0062：带练替换动作沿用旧目标

- 状态：定向回归中，完整门禁与交互待验收
- 日期：2026-09-10
- 上游依据：[训练领域协议](../engineering/training-domain-model.md)
- 下游落地：[验收](../acceptance.md)

## 症状

替换动作后只显示了新名称，组数、重量、次数、时长和间歇仍属于旧动作。

## 根因

协调器只更新动作 ID、名称和快照中的身份，没有重建待练的组与左右侧目标。
动作列表直接提交选择，也没有最近实际记录预览和确认边界。

## 修复

- 选择目标动作后读取它最近一次实际训练，排除当前会话；按动作定义投影次数/时长和侧别。
- 各组分别回填。左右重量不同仍分别保留；左右目标不一致或缺一侧时，无法共用的目标留空，
  展示原始摘要供用户确认。组间歇只回填一致的实际间歇，不猜测缺失值。
- 无历史时从空目标开始。确认页可以改组数和各组参数；返回或取消不写训练和动作定义。
- 确认后事务替换当前尚未开始的组及侧目标，同步会话与动作快照、当前指针及计时修订。
  与计划开始共用运行时组展开规则，不修改计划模板。
- 已开始、已完成或已有实际数据/录像的当前动作拒绝替换；其他已完成动作保持不变。

## 回归门禁

`GuidedExerciseReplacementTests` 首条测试在旧实现中实际失败：预期两组时长，得到三组旧次数目标。
覆盖最近记录排除当前会话、空历史、缺失值、异构左右组、确认修改、未开始边界和已完成证据保护。

交互验收：选择 → 最近记录与来源 → 修改或取消 → 确认 → 带练展示新目标，浅深主题分别检查。
不新增持久字段或数据迁移。
