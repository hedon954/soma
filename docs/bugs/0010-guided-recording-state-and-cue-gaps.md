## 症状

1. 开启默认每动作一段后，第 1 个目标组显示相机，但录像失败并提示“无法录制”。
2. 未开启自动录像时，每组没有手动录像入口；开启后非目标组仍持续调用和展示相机。
3. 紧凑小窗上下有黑边，占用动作示意空间。
4. 语音只说“准备第 1 组”，没有 3/2/1、正式开始、后续组、休息和完成。
5. 计划结束缺少有意义的本地反馈；历史 Session 不能左滑删除。

维护者提供的真机截图只用于本地诊断，不进入仓库、测试夹具或外部 Issue。

## 根因

1. `AutoRecordingPolicy` 同时被当成用户偏好与当前录像状态；完成组时通过 `shouldRecord` 重新推断
   是否需要停止，无法表达手动录像、重试或每组录像。
2. `WorkoutCameraService.startRecording` 在调用 `AVCaptureMovieFileOutput.startRecording` 后立即
   返回并标记 `.recording`，没有等待系统 `didStartRecordingTo`，请求成功被误当作实际写入成功。
3. 开始页为“校准”提前 `prepare` 相机；带练页又按策略而不是真实录像状态显示小窗。
4. 共享 Preview Layer 固定 `.resizeAspect`，紧凑窗口比例不一致时产生 letterbox 黑边。
5. 语音是零散副作用，没有阶段事件、倒计时去重和过期队列清理。
6. Session 总结只有单行字符串，UUID 关联模型没有统一删除级联。

## 修复

- 分离自动录像策略、启动中和真实录像 Set；自动与手动入口共用实际活动状态。
- 等待 `didStartRecordingTo` 后才显示取景器和红点，完成或失败统一由录制 Delegate 收敛。
- 删除开始前相机校准；没有实际录像时不启动相机、不挂载预览。
- Set 保存独立录像路径；紧凑小窗裁切填满，放大态保持完整画幅。
- 增加可去重语音事件，覆盖准备、倒计时、开始、休息、下一动作与完成。
- 增强本地训练总结；历史行增加原生尾随左滑删除并通过 Store 清理关联模型和私有媒体。

## 回归门禁

- Coordinator 测试覆盖三种自动策略、手动录像、启动失败与按 Set 保存。
- Cue 测试覆盖第一组和后续组的完整序列及倒计时去重。
- Camera 测试要求 `.recording` 只能由系统启动回调产生。
- Store 测试覆盖删除 Session 后 Performance、Set、Analysis 和媒体路径不残留。
- 布局快照覆盖无录像不显示相机、录像中紧凑小窗无黑边和完成复盘。
- `make verify` 通过；真实相机与语音继续由维护者真机复验。

## 真机复验

1. 自动录像关闭进入训练，确认系统绿色相机指示不出现；任意组点击“录制本组”后才出现。
2. 分别选择“每个动作录一组”和“每一组都录”，完成两动作多组训练并逐段播放保存视频。
3. 触发首组自动录像，确认红点只在真实开始后出现；拒绝权限时错误可见且训练可继续。
4. 紧凑小窗无上下黑边；放大、收起和横竖屏切换不打断当前文件。
5. 第一组、第二组、休息结束、换动作和训练完成均能听到对应语音，且没有迟到串音。
6. 完成后看到训练时长、组数、容量、录像和动作明细；历史左滑删除后记录和私有视频消失。
