# BUG 0063：模型明确拒绝视频后缺少可用画面路径

- 状态：完整本地门禁通过，真机待验收
- 日期：2026-09-10
- 上游依据：[PRD 063](../prd/063-video-compatibility-and-actionable-errors.md)、[ADR 0131](../adr/0131-explicit-video-rejection-frame-fallback.md)
- 部分替代：[BUG 0054](0054-full-video-playback-and-dictation-regressions.md)（明确视频拒绝时始终阻断的范围）
- 下游落地：[验收](../acceptance.md)

## 症状

仅接受图片的模型明确拒绝视频类型后，消息失败，用户无法继续利用该视频的可见画面。

## 根因

原完整视频契约将所有不支持行为直接阻断。兼容路径需要独立于瞬态重试，且必须同时覆盖
原始请求、历史媒体位置、远程输入和持久恢复，才能避免丢证据或重复执行。

## 修复

按 ADR 0131，在当前模型请求尚未输出且明确拒绝视频时，单次切换为有界画面。
单视频目标 8–24 张，多个视频总共最多 24 张、每个至少 8 张，均匀覆盖整段并附时间。
保留照片、原视频及原消息位置，显示画面数量并说明连续运动无法由静态抽样完整判断。
备用画面无效时明确失败；既不降为纯文本，也不重跑此前完成的工具。
App checkpoint 与服务器事件保留模式，恢复后继续画面请求。

## 回归门禁

`VideoFrameFallbackTests` 旧实现首条回归实际失败；修复后覆盖请求替换、明确拒绝判定、
短长视频预算、合成视频尺寸与全时段覆盖、原文件不变、部分输出禁止重发、损坏与取消、模式恢复。
Server 测试另验清单引用/字节预算、模型拒绝、已有工具结果、工作进程重启以及图片再次失败。
数量和时点测试不能证明动作分析准确率；真实动作质量和真机系统媒体链路单独验收。
