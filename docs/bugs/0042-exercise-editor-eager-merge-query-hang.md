# BUG 0042：动作编辑页提前物化合并候选导致卡死

- 状态：已修复并通过真机交互验收
- 发现日期：2026-08-27
- 影响范围：动作详情、动作内容编辑、动作管理
- 上游依据：无
- 下游落地：暂无

## 症状

从动作详情菜单点击“编辑动作”后，页面长时间无法出现或失去交互。动作库条目越多，问题越
明显；500 条虚构动作的自动化场景会让旧实现超过 60 秒仍无法恢复。

## 根因

内容编辑页在初始化时同步查询最多 2000 条活动动作和最近一次合并记录，并在同一个 `Form`
中为 `Picker` 物化全部合并候选。改名、肌群和动作说明在用户点击保存前本不需要这些数据，
低频管理查询却阻塞了高频编辑路径。

## 修复

- 内容编辑页移除动作目录与合并记录查询，打开时只从当前动作填充编辑草稿。
- 改名继续只在“保存修改”时走规范化名称查重；`canonicalNameKey` 的数据库唯一约束保持不变。
- 合并、归档与撤销合并迁移到详情菜单中的独立“管理动作”页面，只有用户主动进入时才读取。

## 回归门禁

- 自动化测试：500 条虚构动作下打开“编辑动作”，2 秒内出现编辑页且名称输入框可交互。
- 手工验收：真机从动作详情打开编辑页，修改为未重复名称后保存；重复名称显示已有动作错误。
- 仍无法自动化的风险：不同规模个人动作库在旧设备上的绝对首开耗时仍需持续观察。
