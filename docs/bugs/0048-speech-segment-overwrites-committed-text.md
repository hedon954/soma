# BUG 0048：语音停顿后覆盖已提交文字

- 后续修订：[BUG 0054](0054-full-video-playback-and-dictation-regressions.md)（完整视频与当前草稿追加规则）

- 状态：第二轮真机回归失败，第三轮修复中
- 发现日期：2026-09-02
- 影响范围：教练输入框连续听写、停顿后继续与停止后重启
- 上游依据：维护者复现描述
- 下游落地：[PRD 052](../prd/052-coach-training-and-lifecycle-reliability.md)

## 症状

听写过程中停顿后再次说话，新识别结果会覆盖停顿前已经显示的文字，而不是在标点后继续追加。

## 根因

输入框直接绑定识别器当前 transcript；系统在新 request 或 partial 修订时会从片段起点重新给结果，
旧实现无法区分已提交前缀和仍可修订的当前片段。

第二轮真机回归发现系统并不保证每次停顿都会先回调 `isFinal`：部分情况下下一段
partial 会从空源重新开始。只在 final 时提交仍会让新 partial 覆盖上一段。另外，用户手动
停止后立即再次开始时，输入框可能尚未来得及把服务中的最后片段合入新基线。

第三轮真机回归进一步确认，静默阶段仍可能收到同一段音频的文本修订，例如补标点或把 partial
短暂回退。旧状态机只比较文字是否变化，误把这种修订当作用户继续说话并重置静默计时；下一段
真正语音到达时，上一段仍在可替换区，因此再次表现为覆盖。

## 修复

- 语音服务分离输入基线、`committedSegments` 与 `currentPartial`。
- final/停顿提交当前片段并补缺失标点；新识别 request 只替换 current partial。
- 手动停止提交当前片段，再次开始从输入框现有内容追加；重复回调不重复文本。
- 每次 non-final partial 后启动可取消的 0.85 秒静默计时；期间没有新结果时主动提交旧 partial、
  补标点并轮换识别 request，使下一段只能追加到不可变前缀。
- 对计时触发前已经到达、且相隔至少 0.85 秒并与当前 partial 不具前缀关系的新 partial，仍先
  提交旧片段；普通增量和回退修订只替换当前片段。
- 使用 `SFTranscriptionSegment` 的结束时间维护独立声学活动 revision；只有声学时间真正前进
  才重置静默计时，同一音频的补标点或回退不再延后提交。没有新声学证据的短 partial 也不能
  缩短已经显示的当前片段。
- 停止时同步合入最终 transcript；再次开始前再次收口旧 transcript，再建立新的输入基线。

## 回归门禁

- 自动化：partial 变短、两次停顿、停止重启、中英混合和重复 final 回调。
- 手工：Release 真机中文听写包含两次明显停顿，全文只增不丢。

## 验证

第三轮确定性测试补充“同一声学结束时间的文本修订不得移动静默边界”和“短 partial 不得让
可见文字倒退”；`CoachComposerStateTests` 14 项通过。真实 `SFSpeechRecognizer` 中文两次
停顿仍需新构建真机复验。
