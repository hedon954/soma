# BUG 0060：听写替换编辑器导致变高且不能改字

- 状态：修复中，定向回归与视觉验收分开记录
- 日期：2026-09-10
- 上游依据：[ADR 0121](../adr/0121-live-dictation-preview.md)
- 下游落地：[验收](../acceptance.md)

## 症状

听写态用 `Text` 替换输入控件，并在最小 44 pt 外叠加纵向 padding，空态也变高。

## 根因

普通输入又以字符数切换单行与多行 TextField，既不代表真实排版宽度，也会丢失焦点。
为绕开旧控件把上一帧预览回写的问题，状态层直接拒绝所有听写中的手动编辑。

## 修复

- 点击麦克风开始或停止；同一个原生编辑器持续显示文字并允许修改，由用户自行发送。
- 编辑器按实际宽度测量，最少 44 pt，最多五行；占位符仅一行，超长正文在框内滚动。
- 仅原生编辑事件回写草稿；程序更新不得冒充用户输入。保留选择与中文输入法标记文本。
- 用户改后的全文成为当前草稿，丢弃旧猜测并切换识别 generation；迟到结果不能复原旧字。
  识别会话重启期间的音频衔接必须单独在真机检验，单元测试不能证明这段体验无间隙。
- 不恢复历史草稿，不上传音频，不自动发送。

## 回归门禁

- `SpeechInputSessionTests.testEditingLivePreviewKeepsUserTextAndRejectsOldRecognition` 在修复前
  实际失败：修改被拒绝，迟到 final 又写入错误字；修复后需检查改字、续说及停止。
- `CoachDraftEditorTests` 检查短中文、实际窄宽换行、末尾回车、五行滚动、选择保持、
  程序更新不回写以及中文 marked text 不被覆盖。
- iPhone 尺寸浅深主题检查空态、键盘、长文与可访问性字号。真机中文听写不以模拟器替代；
  用户取消听写验收时，保持该项未验证并继续其他工作。
