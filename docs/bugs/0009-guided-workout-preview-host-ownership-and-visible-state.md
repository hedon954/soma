# BUG 0009：带练共享预览层被旧 Host 抢回并静默黑屏

- 状态：已修复；待维护者真机复验
- 发现日期：2026-08-03
- 影响范围：计划带练紧凑/放大相机切换、相机错误反馈与竖屏动作信息
- 修订自：[BUG 0008](0008-guided-workout-realtime-camera-projection.md) 的首次共享预览层修复
- 后续修订：暂无
- 关联需求：[PRD 013](../prd/013-guided-workout-experience-and-capture.md)
- 关联决策：[ADR 0038](../adr/0038-focused-guided-workout-and-capture-geometry.md)

## 症状

1. 紧凑态能看到相机，点击完整取景后放大态变为纯黑；收起后紧凑态也失去画面。
2. 黑屏时仍显示“正在录制”和红点，没有说明预览画面是否真正生效。
3. 竖屏放大取景占满首屏，只剩巨大“5 次”，用户无法同时确认动作名称和本组目标。

维护者提供的真机截图只用于本地诊断和视觉对照，不进入仓库、测试夹具或外部 Issue。

## 根因

1. 紧凑和放大容器虽然共享同一 `AVCaptureVideoPreviewLayer`，但旧 SwiftUI 分支在新 Host 安装
   预览层后仍可能收到迟到的 `updateUIView`。旧容器会把预览层重新抢回，随后
   `dismantleUIView` 又将其移除，因此新旧两处都黑屏。
2. UI 只根据录像状态展示“正在录制”，没有读取 `AVCaptureVideoPreviewLayer.isPreviewing`，把
   “文件输出已启动”错误等同于“用户已经看到取景画面”。
3. 竖屏相机严格按全宽 `9:16` 展开，没有为动作名称、目标、组进度和主按钮保留首屏空间；目标
   又使用展示型大字号，信息层级失衡。

## 修复

- 每个 `CameraPreviewView` 使用稳定 Host ID。新 Host 接管后，旧 Host 的迟到更新只能更新自己
  仍持有的层，不能重新挂载已属于其他 Host 的共享层；旧 Host 清理也只能移除自己拥有的层。
- Host 切换时只重建轻量预览连接，不停止 `AVCaptureSession`、`MovieFileOutput` 或当前录像；预览
  绑定继续复用唯一 Capture Session 和 Preview Layer。
- 使用系统 `isPreviewing` 作为真实可见状态：切换期间显示“正在连接相机画面”，两秒后仍未开始
  渲染则显示明确的非阻塞错误；权限、运行时和录像错误同样投影到取景表面。
- 竖屏取景高度不超过可用高度的 52%，下方固定显示动作名称、具体重量/次数、组进度、提示和
  完成按钮；目标改用普通标题字号，不再用巨大单一次数占据页面。

## 回归门禁

- 预览 Host 测试模拟“紧凑安装 → 放大接管 → 旧紧凑迟到更新 → 旧紧凑销毁”，确认共享层仍在
  放大 Host。
- 相机表面状态测试覆盖录像中尚未渲染、预览超时、权限/录像错误和正常可见状态。
- 布局测试约束竖屏相机高度，并渲染包含动作名、具体目标和错误反馈的真机尺寸快照。
- `make verify` 覆盖静态门禁、构建和模拟器测试；真实相机渲染仍由维护者真机复验。

## 真机复验

1. 紧凑态看到画面后连续执行“完整取景 → 收起 → 再次完整取景”，三处都应立即恢复同一画面，
   录像红点和文件不中断。
2. 遮断相机权限或触发系统相机中断，确认取景表面显示具体原因和“训练可以继续”，不再静默黑屏。
3. 竖屏放大后首屏同时看见取景、动作名称、具体目标、组进度与完成按钮；横屏仍保持左侧大相机、
   右侧窄控制栏。
4. 完成目标组后打开保存视频，确认切换前后录像连续，画幅、方向和镜像与预览一致。
