# BUG 0014：带练动作完成后没有形成训练记录

- 状态：已修复；历史个人数据首轮补投影待维护者真机观察
- 发现日期：2026-08-12
- 影响范围：训练记录、计划执行聚合、容量趋势、导出备份与删除
- 上游依据：无
- 下游落地：
  - [PRD 026](../prd/026-guided-workout-record-projection-camera-failures-and-session-entry.md)
  - [ADR 0060](../adr/0060-guided-performance-workout-entry-projection.md)

## 症状

计划带练完成动作后，逐组事实只出现在计划执行和动作详情的 Session 兼容视图中，进展页“训练
记录”没有对应 `WorkoutEntry`。用户无法按普通训练记录编辑、删除或导出该动作；若直接补写记录，
现有趋势又会同时累计记录和 Session Set。

## 根因

ADR 0029 把计划快照、Performance 和 Set 正确分层，但实现没有把终态 Performance 投影到统一
业务记录。趋势与动作历史因此各自临时合并两套模型，缺少稳定来源 ID、幂等回填和去重规则。

## 修复

- 终态动作至少有一个完成组时，按完成组顺序创建/更新一条带来源 ID 的 `WorkoutEntry`；跳过组
  不伪造，缺失字段保持 `nil`。
- 历史 Session 在本机幂等回填；统计与动作历史优先使用投影记录，旧数据才回退原始 Set。
- 备份/导出保存来源 ID；删除 Session 同步删除关联训练记录和既有执行图。
- 单独删除投影训练记录会保存抑制标记，后续回填不会违背用户删除意图。

## 回归门禁

- 自动化测试：完成后跳过、全跳过、重复回填、趋势去重、备份往返和 Session 级联删除。
- 手工验收：训练记录先出现动作记录，整次确认结束后训练 Tab 再出现一次计划执行。
- 仍无法自动化的风险：大量旧个人数据的首轮补投影耗时需在真机观察。

## 验证

- `make verify` 通过。
- 单元测试使用虚构动作覆盖：完成组后跳过剩余组会在 Session 完成前生成一条来源记录；未知实际值
  保持 `nil`；全跳过不建空记录；重复回填不重复；用户删除后抑制回填与普通统计回退。
- 趋势测试证明投影记录与原始 Set 只累计一次，旧记录去重修复不会合并掉带来源记录；Session
  删除同步删除来源训练记录、逐组事实、分析和虚构媒体。
- 加密备份往返保留来源 ID 与投影抑制标记；开放训练导出保留来源 ID。
