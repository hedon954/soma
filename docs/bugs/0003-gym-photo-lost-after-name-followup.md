# Bug 0003：补充健身房名称后照片没有进入档案

- 状态：已修复，待真机媒体验收
- 发现日期：2026-07-31
- 影响范围：先发送健身房照片、下一轮再补充场馆名称的创建流程

## 症状

Tool Card 显示健身房和器械已更新，但健身房详情没有照片。Agent 还可能错误解释为“照片只
保留在聊天，不会嵌入档案”。

## 根因

`ConversationProcessingService` 会把历史图片重新提供给模型用于推理，但执行 Tool 时只把
当前 Turn 的 `mediaAttachments` 传给 `ConversationRecorder`。Agent 第一轮看图、第二轮获得
名称后才调用 `update_gym`，此时当前媒体为空。ADR 0024 的历史媒体只读门禁阻止了任意跨轮
复制，却没有为紧邻的命名确认保留受限归档路径。

## 修复

- 新增 `AgentToolMediaAttribution`，只允许 `update_gym` 解析同一 Session 紧邻上一轮图片。
- App 在发给模型的紧邻历史消息中明确提供 `media_source=recent_gym_turn` 语义引用；模型
  选择该来源后，App 再从 Session 上下文投影解析媒体位置，不暴露本机路径。
- Tool 明确引用上一轮但找不到图片时失败，不再静默创建无图档案。
- Tool 结果包含实际保存照片数量。
- 关联边界由 [ADR 0026](../archive/0.0.1/adr/0026-bounded-gym-media-attribution.md) 固化。

## 回归门禁

- 自动化测试：请求包含模型可用的媒体引用；模型选择后紧邻图片能归档，未选择时不归档；
  隔过一个 Turn 后不能回捞；当前图片优先。
- 手工验收：真机先发两张虚构健身房照片，再只回复名称，详情中应出现两张照片。

## 验证

- 新增跨 Turn 归属和单张解绑单元测试。
- 已通过模拟器编译和测试；真实相册照片仍需真机手工确认。
