## 一、我们的目标是什么

进展页不是数字陈列柜，要让用户方便地回答三个问题：

1. **那天发生了什么？** 昨天吃了多少、消耗多少、练了什么，能回看和纠错。
2. **这段时间是否有变化？** 训练是否持续、同一动作是否进步、饮食和体重怎样变化。
3. **下一步值得关注什么？** 根据已有记录指出值得检查的项目，不凭空给恢复分或减重期限。

重点面向 Soma 已有的力量训练、减脂与增肌减脂用户，不扩张成睡眠、跑步、社交的全功能平台。

### 当前问题与优先级

| 优先级 | 问题 / 受影响目标 | 已核实证据 | 判断边界与设计动作 |
| --- | --- | --- | --- |
| P0 | 看不到历史消耗，无法复盘昨天 | 用户反馈；`HealthEnergyReader.today()` 与今日能量投影 | 能力缺口，高确定性；提供按日期读取和日详情 |
| P0 | 页面时间含义不一致 | 顶部近 30 天范围、今日能量、周训练统计并存 | 信息结构问题，高确定性；统一当前时间范围 |
| P1 | 点图后不能顺畅追查原因 | `MonthlyProgressTrendCard` 的选中日期只更新局部数值 | 交互断点，高确定性；图表 → 日期 → 原记录 |
| P1 | 所有指标都被塞进近 30 天折线 | 固定训练容量 / 摄入 / 体重三选一，离散记录使用平滑曲线 | 表达问题，高确定性；分别使用柱图、实测点与趋势线 |
| P1 | 缺值使合计不可读，或容易被误认为真实零值 | 用户反馈及现有可空能量合计 | 数值语义问题；已记录小计为 0，缺测状态不丢失 |

以上是用户反馈和代码核验，不是全量用户发生率，也不是本轮真机性能审计；卡顿仍需独立验证。

### 用户习惯：支持哪些情境

个人追踪研究同时观察到记录、查看、行动、中断与恢复，而不是人人每天完整打卡。
[Epstein 等，2015，作者公开论文](https://depstein.net/assets/pubs/depstein_ubi15.pdf)。
因此下表是结合竞品和本次反馈形成的 **Soma 设计假设**，不是已测量的使用频率：

| 使用时机 | 要解决的事 | 最短路径 |
| --- | --- | --- |
| 刚吃完 / 刚练完 | 确认有没有记对 | 今日 → 记录 → 编辑 |
| 第二天 / 想起某一天 | 查昨天、补查遗漏、分享当天训练 | 日期 → 日详情 → 记录 / 分享 |
| 再次练同一个动作 | 对比上次重量、次数或时长 | 训练 → 动作 → 相邻两次表现 |
| 一周结束 | 看练了几天、哪些肌群、平均吃了多少 | 本周 → 上周；不必逐日累加 |
| 一个月或更久 | 看体重 / 腰围、动作表现有没有持续变化 | 月 / 年 → 身体或动作趋势 |
| 停记一段时间后回来 | 找回历史，继续记录 | 保留历史与空档，不把漏记当作失败 |

## 三、我们的设计结论是什么

### 1. 一个时间范围，三个领域，不再增加孤立图表

保留“进展”这一根页面。顶部提供 **日 / 周 / 月 / 年**、明确日期、上一期 / 下一期、日历和“回到本期”。
首次进入默认本周；之后保留选择和滚动位置。停在过去时不能悄悄跳回今天；选本期时随日期更新。

按用户选定稿，首页固定为 **饮食与能量主图 → 训练摘要 → 身体摘要**；三个领域均可点击进入详情。
训练与身体使用紧凑摘要和小图，不把三张大图堆在首页；本轮不增加随目标变化的自动重排。
不再增加一排领域 Tab 与时间 Tab 相互叠加，也不在首页展开全部公式、全部记录和所有指标。
首页不写重复解释操作的句子；数据口径用短标签表达，计算说明放详情。保留图例、覆盖状态和实际操作入口。

- 首页全部板块服从顶部同一范围，不能顶部选本月、能量仍显示今天。
- 点柱 / 数据点，在图下显示选中日期的数值及“查看当天”；不突然改变整个图的范围。
- “查看当天”进入日详情，统一展示当日能量、训练、饮食、身体记录；继续点击可编辑原记录。
- 日详情支持前一天 / 后一天和日历。返回恢复之前的月图、选中点和滚动位置。
- 训练日详情复用现有动作记录列表及按日分享，不做第二套统计。

### 2. 记录什么、展示什么

| 领域 | 保留 / 使用的事实 | 首页主信息 | 领域详情 |
| --- | --- | --- | --- |
| 训练 | 日期、动作、实际组与左右 effort、重量、次数 / 时长、间歇；来源、执行记录关联 | 已记录训练天数、完成组数、组数柱图 | 肌群主要 / 辅助组数、容量、训练时长；同一动作的重量 × 次数或持续时间、原始记录 |
| 饮食与能量 | 餐次、热量、蛋白质 / 碳水 / 脂肪；设备静息 / 活动能量、来源与更新时间 | 已记录摄入、预估总消耗及其历史对照 | 蛋白质与其他营养素、每日明细、记录差值、消耗依据与覆盖情况 |
| 身体 | 日期、体重、腰围、可选体脂与照片、来源 | 最近一次有日期的测量、期间变化、体重图 | 腰围 / 体脂独立切换、原始测量、可选照片对照 |

继续聊天记录、详情纠错，不要求用户每天填写新表单。没有记录的非主指标收起，但提供清楚入口。
照片只留在受控详情，不自动进入图表、分享或调研素材。

训练天数不能把同一天的多个动作算成多次训练。左右 effort 不等于两倍逻辑组数；组数不冒称
“有效增肌组数”。全身容量只回答完成了多少外部负荷，不能据此宣布力量提高；自重训练保留组次
与时长，不能因为外部重量为 0 就显示“没有训练”。肌群图保留主要 / 辅助身份，不推导恢复分。

### 3. 时间周期与图表粒度

| 查看范围 | 图表粒度 | 主要用途 | 汇总规则 |
| --- | --- | --- | --- |
| 日 | 当天记录 / 餐次；有实际分时数据才显示小时图 | 查昨天、核对、编辑、分享 | 当日已记录合计；身体显示实际测量，不凑趋势 |
| 周 | 自然周，默认周一至周日；每日一柱 / 实测点 | 训练安排与饮食周复盘 | 训练天数 / 组数合计；饮食日均注明有记录天数 |
| 月 | 自然月；每日柱 / 点，肌群按周对照 | 月内变化与漏记定位 | 不把“9 月”写成滚动近 30 天 |
| 年 | 自然年；每月汇总，可进入月份 | 长期变化 | 训练累计；饮食按有效天数加权日均；身体月内测量均值并保留样本数 |

领域详情的日期选择器再提供“全部 / 自定义”，历史不限制在 30 天。年图点月、月图点日，逐层深入。
多次身体测量保留原始点；长期聚合点注明“均值”，不冒充那一天的实际体重。只有一个点时不画变化线。
当前未结束的周 / 月只与上一周期相同已过天数比较，或明确选择已结束周期；未来日期不画零柱。
**图表的查看周期，不是活动系数算法的观察窗口。** 切换日 / 年不能改变同一天的计算结果。

### 4. 三类图分别怎么画

- **训练：离散柱图。** 默认完成组数；容量为可切换指标，不用平滑曲线连接休息日。
  肌群用横向条形图读主要 / 辅助分布，受力图辅助定位。动作表现单独看真实训练日期，不把不同动作硬连成一条线。
- **能量：摄入柱 + 预估总消耗虚线。** 同一 kcal 轴，明确图例，不叠加成一个“总量”。
  点某天同时看摄入、消耗来源和记录差值；不以红绿灯把某一天判为好坏，也不与 kg 共用双轴。
- **身体：实测点 + 趋势。** 原始点始终可见，不把补点当测量；缺测不填 0、不连长空档。
  首版使用原始点和明确的周期均值，平滑趋势待采样与算法验证后加入。体重、腰围、体脂不混轴。

沿用 Soma 浅 / 深双主题和语义色；用实虚线、图例与文字共同区分系列。触达不少于 44pt，
图表拖动不是唯一入口，日历和可读列表也能完成同样任务。页面保持单一纵向滚动，不嵌套记录滚动区。

### 5. 消耗必须有历史，但不能叫“真实消耗”

历史每天都应能查到摄入、可获得的消耗与依据。全天估算使用该日及之前可用的资料和活动证据，
不能把今天的体重、系数直接覆盖所有历史。旧数据补算标注“补算”；新同步或编辑引起的重算可追溯。
全天估算与设备截至当前的能量分开，今天的部分摄入不能直接称为已经形成的全天热量缺口。
详细估算边界继续由 [PRD 053](../archive/0.0.19/prd/053-adaptive-energy-estimation-and-progress.md) 约束。

- 记录小计没有值时显示 **已记录 0**；部分热量未知时先加已知部分，详情说明未计入条目。
- “没有记录”与“实际为 0”保留区别。空白饮食日不当零摄入参与生理校准，缺体重也不画 0kg。
- 周 / 月饮食优先显示“有记录日均，n 天”；今天仍在记录时单独注明，不默认为完整日。
- 差值叫“记录差值 / 相对全天预估”，不叫真实缺口；没有估算所需资料时显示“待补资料”，不是 0 消耗。
- Apple 健康活动能量与其中已包含的 Soma 训练不能重复相加；本地原始事实、设备估算、公式派生分别可查。

### 6. 先做什么、不做什么

**第一步：历史与可解释图表。** 统一日期控制、按日能量读取、三个领域、点图查记录、缺值与均值口径。
动态消耗按 PRD 053 单独验证，不以重设计为由直接套一个未经验证的活动系数。

**第二步：更容易比较。** 关注同一动作、相邻周期比较、身体测量对照；再验证是否需要可固定的重点指标。

**本轮不做：** 睡眠 / HRV / 恢复综合分、自动减重日期预测、排行榜、任意搭建仪表盘、把周训练次数换算成固定活动系数。
这些不是当前数据或用户需要已经支持的结论。

## 证据边界

官方资料支持功能模式，不证明市场使用频率。Strong 文档较旧，Keep 只核实公开能力介绍；
本轮没有登录这些产品进行完整交互审计。默认本周、三个板块、两步查日记录是 Soma 的设计提议，
后续需通过任务走查验证。没有新增健康上传、账号、分析服务，也没有采集真实用户健康记录。
