# Soma 上下文管理优化方案

- 日期：2026-09-12
- 状态：方案已整理；30 轮 / 30k 门槛为维护者已确定目标，其余为建议设计与实施次序
- 交付范围：方案文档；未修改运行时代码，也未验证模型效果或缓存收益
- 当前基线：0.0.23 工作区，包含其他任务尚未提交的提问工具与热量改动
- 现行依据：[PRD 000](../../docs/prd/000-origin-through-0.0.11.md)、[ADR 0000](../../docs/adr/0000-origin-through-0.0.11.md)、[ADR 0120](../../docs/adr/0120-focused-shortcut-prompt.md)、[Prompt 来源目录](../../docs/engineering/prompt-source-catalog.md)

## 1. 目标与已确定边界

优化后的上下文应同时满足：保留多轮表达的细节，区分历史与当前事实，在模型请求间尽量复用
相同前缀，并在压缩、修改配置和恢复执行时维持业务时间、权限与工具副作用的一致性。

| 项目 | 本方案边界 |
| --- | --- |
| 完整历史窗口 | 最近最多 30 个用户来回，不是 30 条消息或 30 次模型调用 |
| 压缩触发 | 完整历史超过 30 个来回，或历史文本估算超过 30,000 tokens，任一个成立 |
| 边界值 | 恰好 30 轮、恰好 30k 且没有其他越界条件时不压缩；超出后才移出完整轮次 |
| 模型容量 | 允许未知；不维护全量容量表，不以所有模型均支持 256k 为前提 |
| 压缩位置 | 常规压缩发生在新 Turn 的 Loop 开始前，不在工具调用之间任意重写上下文 |
| 事实来源 | 业务当前态来自本地数据库与确定性工具；历史和摘要提供背景与引用 |
| 权限 | 当前明确授权决定本轮动作；历史授权、摘要和 Skill 不能扩大工具权限 |
| 本地与远程 | 复用设备生成的同一上下文计划与版本化模型输入 |

30k 定义为**历史消息中实际发送的文本估算**。当前实现只有历史问答和卡片修订；后续若保留
原生工具回执、Turn 上下文和历史 Skill 文本，这些也计入历史文本预算。固定 System、API
工具定义、压缩基线摘要、当前输入与多模态 token 不包含在这一门槛内，需单独计量。
因此 30k 不等于整个请求的硬上限，也不能保证任意供应商都接受请求。

最新完整来回不切半轮；若单轮已经超过 30k，保留该轮并标记超预算，由独立的大输入处理
路径处理。不能压缩旧历史后假装当前大输入已经变小。原始聊天和媒体始终保留在设备。

## 2. 当前实现与主要缺口

以下为静态代码审查发现，不代表已通过真实模型复现。落实时先添加对应回归测试。

| 当前路径 | 发现与影响 | 对应改进 |
| --- | --- | --- |
| [ConversationContextProjection](../../Soma/Services/Conversation/ConversationContextProjection.swift) | 最近 10 个来回、约 6000 历史文本 tokens；短对话较早丢失原文 | 统一 30 / 30k 窗口 |
| [ConversationCompactionMiddleware](../../Soma/Services/Conversation/ConversationCompactionMiddleware.swift) | 摘要仅按十轮边界取材，与 token 裁剪脱节；不足十轮也可能有被裁掉而未摘要的内容 | 同一 ContextPlan 决定保留与压缩集合 |
| [ConversationTurnLocalRunner.prepareAgentHistory](../../Soma/Services/Conversation/ConversationTurnLocalRunner.swift) | Exchange 的 date / turnID 未传入 AgentConversationExchange | 时间及身份贯穿消息转换和摘要 |
| [AgentModelInputBuilder](../../Soma/Services/Conversation/AgentModelInput.swift) | 当前 user 变成历史后重新包装；跨轮不保留完整工具序列；媒体标识依赖窗口下标 | 在一个上下文段内复用规范化消息 |
| [ConversationProcessingService.submitPersisted](../../Soma/Services/Conversation/ConversationProcessingService.swift) | 业务摘要在发送时冻结，执行时历史又重新读取；排队后可能混用不同时点状态 | 发送语境与执行状态分开 |
| [AIServiceAgentPreparation](../../Soma/Services/Conversation/AIServiceAgentPreparation.swift) | 恢复时重新读取当前 System / Skill；检查点主要保存工具名与调用结果 | 冻结实际配置版本和初始消息 |
| [AIService.clearHistoricalImageParts](../../Soma/Services/Conversation/AIService+ReActLoop.swift) | 第二步修改早期图片消息；用数组末项推定当前 user，追加工具结果后可能误清本轮图片 | 用 Turn / message / media 身份管理保留范围 |
| [AgentCrossTurnFactSummary](../../Soma/Services/Conversation/AgentCrossTurnFactSummary.swift) | 固定十轮外 digest 与滚动摘要可能覆盖重复；摘要来源缺少精确时间 | 统一来源范围，避免多份摘要争夺事实解释 |
| 摘要持久化 | 只用 coveredTurnIDs 判断增量；历史修订后可能复用旧摘要；确定性兜底没有总长度限制 | 摘要有来源版本、覆盖范围和硬预算 |
| [本地用量](../../Soma/Services/Conversation/AIServiceAgentStreaming.swift) / [远程 Provider](../../Server/src/provider.ts) | 本地已有 cached_prompt_tokens、TTFT；远程仅保留输入输出总量 | 补齐分段与缓存观测 |

现有优点应保留：AgentModelInputBuilder 为统一入口、原生 assistant/tool 协议、固定 Schema、
确定性业务写入、选择性历史媒体、持久检查点、业务时间与等待时间分离。

## 3. 统一上下文计划

在 Services 层引入 ContextPlan 的概念；先作为可测试值类型，再决定哪些部分确需持久化。
不要另建与现有 Builder 并行的 Prompt 拼接框架。

```text
会话消息 + 本地业务状态 + 本轮授权配置
                    ↓
             ContextPlanBuilder
                    ↓
   保留 Turn / 摘要来源 / 状态快照 / 媒体选择 / 配置版本
                    ↓
          AgentModelInputBuilder
                    ↓
       Local Provider / Remote Provider
```

ContextPlan 应输出：

- 当前 Turn 的身份、发送时间、时区和业务日期。
- 按顺序保留的历史消息及其来源版本。
- 已移出窗口、需要进入摘要的 Turn 集合。
- 摘要的覆盖边界、生成版本和有效性。
- 当前业务快照的 observedAt、数据 revision 和适用范围。
- 明确选择的媒体身份、输入模式和作用 Turn。
- Prompt / Skill / 工具 / 模型配置快照的指纹。
- 历史文本估算、其他输入分项、窗口重建原因。

投影、压缩、媒体选择、本地与远程提交必须消费同一结果。读取历史时应按完整 Turn 查询
并获取对应助手结果；现有“最多读取 80 条消息”不等同于保证读取 30 个完整来回，重试、
暂存和额外消息可能占用额度。不得为扩大窗口改成无界读取所有 Trace 或媒体。

## 4. 时间、状态与历史事实

### 4.1 时间属于具体 Turn

每轮持久保留 turnID、sentAt、timeZone、effectiveBusinessDate、defaultOccurredAt；
loopStartedAt 单独表示开始执行的时点。用户相对日期绑定原消息，延迟执行和重试不得移动它。
已有字段优先复用；旧数据无法恢复的时区或业务日期标记未知，不能静默以当前设置补成历史事实。

```text
Turn 1: sentAt=2026-09-12 23:50 +08:00
用户：今天练了腿。

Turn 2: sentAt=2026-09-13 08:00 +08:00
用户：今天还能练腿吗？
```

第一条“今天”仍为 9 月 12 日。第二条“今天”为 9 月 13 日。旧时间是历史证据，并不需要删除。
如果在 9 月 14 日重试 Turn 2，其业务时间依然不变；实时问题另行获取执行时状态。

### 4.2 发送语境与执行快照分开

| 数据 | 固定或刷新规则 |
| --- | --- |
| 原始用户输入、发送时的业务日期与时区 | 发送时冻结 |
| 用户选择的快捷按钮、授权范围与 Skill 配置 | 发送时冻结实际配置内容；紧急撤权另行检查 |
| 首次执行前的业务记录与计划当前态 | 在前序 FIFO 工作完成后读取并记录 observedAt / revision |
| 本 Loop 已完成的写入 | 以成功工具回执及本地业务事实为准 |
| 当前位置和天气 | 标注观测时点、来源与是否仍适用于本轮；不把旧观察写成现在 |
| 中断后的恢复 | 原输入和成功工具批次保留；必要的新状态作为明确更新追加 |

发送时快照继续作为审计事实保存，执行时补充较新的业务快照，避免一边读最新历史、一边把
发送时数据库摘要当作当前状态。具体记录写入前仍由工具检查有效性，Prompt 不能替代校验。

### 4.3 事实优先级按来源与时间判定

当前数据库及已验证工具结果用于回答业务当前态；用户明确表达用于确定意图与新的事实，
修正成功后产生新的业务版本。历史消息、旧快照和摘要不应覆盖较新的已确认状态。
不同时间的体重、训练量等观测可以同时成立，不能用“最新一条覆盖全部旧事实”处理。

## 5. Prompt 如何指导模型

### 5.1 稳定规则与动态内容分层

| 层 | 内容 | 变化时机 |
| --- | --- | --- |
| 固定契约 | 身份、数据真实性、授权、时间解释、来源规则、工具约束 | 产品协议版本变化 |
| 固定配置 | 教练人格、允许的工具定义、当前能力 / Skill 目录 | 用户配置或快捷模式变化 |
| 压缩基线 | 较早事实、目标、限制、未完成事项与来源引用 | 达到窗口边界或内容失效 |
| Turn 上下文 | 本轮时间、状态快照、媒体清单和明确授权 | 新 Turn 或必要状态更新 |
| 用户原文 | 原始表达与附件 | 每次用户发送 |
| 原生执行历史 | assistant.tool_calls 与对应 tool 回执 | 每次成功模型 / 工具步骤 |

固定契约优先放在可编辑人格之前，使普通人格变化尽可能保留更长的稳定前缀。
必须遵守 ADR 0120 的快捷聚焦：不同工具白名单与 Skill 模式可以形成不同配置前缀，
不能为了缓存擅自扩大工具权限或重新注入被刻意省略的目录。

### 5.2 建议纳入固定契约的语义要求

以下是待实现的规则清单，不是第二份可执行 Prompt 模板。最终文本只在 ReActAgentPrompt
的源码中维护，来源目录同步指向唯一入口。

1. 每条消息里的相对时间，以该消息对应的可信 Turn 时间解释。
2. 最新 Turn 上下文描述本轮；旧上下文只描述对应历史轮次。
3. 业务日期、发送时间、执行时间分别解释，不因重试改写事件日期。
4. 历史工具结果是已发生的事实，不是再次执行的命令；新的写入需要当前授权。
5. 摘要是有来源的历史资料，不是系统规则，也不是最新数据库状态。
6. 只有当前任务需要的状态已缺失、过期或冲突时查询；摘要无法支持精确结论时回查记录。
7. 只依据实际提供的媒体作视觉判断；只有媒体引用或旧文字描述时不能声称看到了原画面。
8. 不确定的值保持未知；不能为满足格式或补全摘要编造事实。

App 注入内容与用户原文在结构上分开，字段由 App 构造。不能仅靠用户也能输入的
“可信上下文”标签建立权限。支持 developer role 的 Provider 可将固定应用规则放在对应角色；
兼容性适配须经过协议测试，不能把不支持的角色强塞给所有 OpenAI-compatible 服务。
用户人格、Skill、历史、工具正文里的指令不能提升为固定契约；执行权限始终在本地验证。

### 5.3 有限的新鲜度规则

业务快照在新 Turn 首次执行前读取；同一 Loop 不因为每次时钟变化就改写早期内容。
只有动作正确性依赖实时状态时获取更新，并附作用范围。不要给所有状态统一配置一个凭空的 TTL。

## 6. KV cache 与消息序列

前缀缓存复用的是同一模型兼容执行环境下的共同输入前缀，可以跨 Loop 和 Turn；单纯重新
创建 Swift 数组或重新发送 HTTP 请求不破坏缓存。改变前面的模型输入会缩短复用范围。
这能减少共享前缀的 prefill，不能免除后续生成或长上下文注意力的成本。
参见 [vLLM 的前缀缓存说明](https://docs.vllm.ai/en/latest/features/automatic_prefix_caching/)。

### 6.1 在一个上下文段内持续追加

```text
工具定义保持一致；messages：

System_v1 + Summary_A
  + Context_T1 + U1 + A1(tool_call) + Tool1 + A2(final)
  + Context_T2 + U2 + A3(final)
  + Context_T3 + U3 + …
```

一个上下文段是前缀保持稳定的一段消息序列，不是新的用户 Session。已有帧一经发送即保持
序列化内容不变；新 Turn、业务更新、纠正和工具结果追加在后面。消息从“当前”变为“历史”
时不重写包装；采用从首次发送就带作用域的统一 Turn 格式。

缓存旧 KV 不会使后续输出停留在旧状态；新 token 仍能关注追加的最新上下文。能否准确区分
时点仍取决于上下文和模型行为，必须通过对照测试验证。

### 6.2 规范化消息与持久化

- 保留消息角色、顺序、tool_call_id、实际参数和成功回执的稳定表示，恢复时不重新生成 ID。
- 固定工具数组顺序、Schema 表达、字段排序、日期格式及媒体身份；工具参数只规范化一次。
- 不每轮在开头插入当前时间、请求 UUID、随机排序的目录或新数据库摘要。
- 用户手动纠正以新纠正事件追加；旧消息在数据源被编辑 / 删除时，派生上下文必须失效重建。
- 本地优先复用现有 Job、Event 与 checkpoint；只持久化恢复必需的信息。新增持久字段或
  注册模型前须另写 ADR、同步数据库文档，不能把设计值类型直接宣称为已支持迁移的存储结构。
- 现有信封历史只支持 system/user/assistant。跨 Turn 保留原生工具序列需要显式升级信封、
  iOS / Server 验证器及兼容策略；业务当前态仍只在设备，不能改成服务器对话记录决定业务事实。

先稳定普通问答与 Turn 元信息，再在新协议下保留必要的原生工具帧。不把全部长 Trace、
日志或模型私有 thinking 搬进未来请求。已保留的 tool call 与回执必须成组，不能留下悬空调用。

### 6.3 配置变化是合法的缓存边界

Prompt、人格、Skill 正文、工具定义、模型及影响输入的参数组成配置指纹。Loop 固定实际
配置快照；用户更改普通配置后，从新 Turn 使用新版本。重试优先恢复原快照及检查点。
必须立即生效的撤权由执行层拦截，不为保留缓存延后；协议不兼容时明确重建上下文。

已有用户 Session 可以继续存在：

```text
配置改变前：System_v1 + Summary_A + 历史帧 + Context_T3 + U3
配置改变后：System_v2 + 兼容摘要 / 历史帧 + Context_T4 + U4
```

Provider 特有的 cache key、显式缓存断点、保留时间只在确认支持时启用，放在适配层。
未知兼容服务仍发送标准请求。相同前缀不保证命中：缓存粒度、消息边界、存活时间、路由和
隔离范围都可能影响结果。缓存 key 也不能代替输入一致性。
参见 [OpenAI 的历史保留、工具稳定性与缓存边界说明](https://developers.openai.com/api/docs/guides/prompt-caching)。

### 6.4 媒体保留有明确身份与成本

维持当前“本轮媒体优先、历史只按明确回指选择”的隐私和输入边界。媒体应以稳定
turnID / messageID / mediaID 关联；不要使用滚动窗口下标作为持久身份。
图片模式、尺寸与视频模式在一个 Loop 内保持一致；明确能力拒绝才沿现有路径回退。

需要区分：保留图片有利于后续工具步骤继续看图与复用前缀，但每轮重新传送未被引用的旧图
会扩大数据流和成本。因此应在首次选择时控制数量；下一 Turn 不需要旧图时允许建立新的
上下文段，不能为了缓存默认扩大历史媒体发送范围。不要在第二步无条件改写早期图片消息。

## 7. 压缩策略与缓存取舍

### 7.1 同一选择结果决定保留与移出

1. 收集可用于当前请求的有序历史，排除本轮和不应作为已完成事实的未来 / 暂存输入。
2. 从最近到最早保留完整 Turn，直到下一轮会超过 30 轮或 30k 历史文本预算。
3. 输出 retainedTurnIDs 与 evictedTurnIDs，压缩只处理真正移出的已完成内容。
4. 对未完成或失败但已有成功写入的 Turn，保留检查点 / 成功事实，不把失败概括成“未发生”。
5. 原文窗口、历史媒体选择和早期 digest 消费同一结果，不再各写一份十轮规则。

常规压缩仍发生在新 Loop 之前。Loop 内原生工具调用可能继续增长；本次阈值调整不新增
隐式 Loop 内压缩或自动重试。已知请求预算不足应在模型步骤前解释失败，具体恢复策略需单独验证。

### 7.2 摘要只保留可回查的必要信息

保留明确目标、限制、用户事实、决定、未解决事项、成功写入的记录引用及来源 Turn / 时间。
区分用户陈述、AI 建议和实际写入；“建议训练”不能压成“已经训练”。对相对日期保留原时区
及基准，确定时转换为绝对日期；无法确定时保留原表达和时间来源。

统一较早历史的摘要覆盖，避免旧 digest 与模型摘要重复注入同一事实。摘要记录源版本 / 指纹，
历史修改、业务纠正、删除或窗口重新纳入原文时检查是否失效。纠正记录应采用新状态，
业务删除不意味着用户历史从未发生，但摘要不能继续把被删记录当作可操作的当前记录。

沿用小模型 → 标准模型 → 确定性摘要回退。压缩器自己的输入分批、有预算，输出及确定性
兜底有硬上限，不能无界累积。最新必要事实放不下时保留来源并按需回查，不能宣称全文无损。
没有有效摘要且关键被移出内容不能安全保留时，应明确失败，不能静默缺失后继续业务写入。

### 7.3 扩大旧窗口后的摘要处理

从旧十轮窗口升级时，存量摘要可能覆盖新三十轮原文。覆盖集合重新进入原文窗口后，清除
过期派生摘要，或仅从仍在窗口外的原文重建。保留全部原始消息与已完成写入，不做业务数据重建。

### 7.4 严格最近三十轮与批量压缩无法同时最大化

默认执行本次已确定的严格 30 / 30k 保留规则。长 Session 超过门槛后，每轮可能都会移出
旧内容并更新摘要，前缀会再次变化；不能宣称扩大门槛后长会话始终保持追加或永远高命中。

批量压缩到更小窗口可以延长下一段稳定增长期，但会提前失去部分最近三十轮的原文。
这属于后续可选决策，本方案不默认压到 20 轮、15k 或应用模型容量百分比。
先测量严格 30 / 30k 的效果，再决定是否值得改变“最近三十轮原文保留”的产品含义。

## 8. 模型容量未知与错误恢复

30 / 30k 是固定应用策略。可靠的模型容量信息以后可作为额外限制，但不是实施前提。
不根据模型名猜容量，不把一次成功请求的长度当成模型上限。服务端 usage 存在时可用于
校准文字估算；多模态计量单独处理，缺失值标记 unavailable，不能当作 0。

区分 context token 超限、请求体字节过大、模型能力不支持、输出限制及网络错误。
现有 [provider-failure.ts](../../Server/src/provider-failure.ts) 将 413 与 context 超限合并，
需要先拆分类别才能考虑自适应恢复。大视频触发 413 时不能用压缩文字伪装为修复。

维持现有人工恢复屏障：失败展示后由用户重试。若后续引入“接收阶段明确拒绝且无输出时，
压缩一次并重试失败模型步骤”，需要新增协议决策与回归，不能重新执行成功工具或无限重试。

## 11. 验收矩阵

| 场景 | 必须成立 |
| --- | --- |
| 空历史、1 轮、30 个短来回 | 原文保留，不提前调用压缩器 |
| 31 个已完成短来回 | 最新 30 个在原文，最早一个进入摘要 |
| 2–3 个超长来回 | 不足 30 轮仍按 token 预算移出；被移出内容有摘要覆盖 |
| 恰好 30k、略超 30k | 边界稳定，完整轮次不被截断 |
| 最新单轮超过 30k | 单轮不被切半；明确超预算处理，不声称总请求已受控 |
| 同一窗口重复准备 | 不重新调用压缩器，不重复注入覆盖内容 |
| 旧十轮摘要升级 | 不与新三十轮原文重复；摘要重建不改业务记录 |
| 23:50 与次日 08:00 两个“今天” | 分别绑定各自消息的本地日期 |
| 延迟两天后重试 | 原业务日期和成功写入保持；新增实时状态另行标注 |
| 连续发送两条，第一条稍后才落库 | 第二条首次执行快照能反映已完成的前序写入 |
| 用户改业务日期、时区、人格或 Skill | 作用范围和版本生效点明确，恢复不混用配置 |
| 历史授权与恶意工具文本 | 不扩大本轮权限、不覆盖固定契约 |
| 手动纠正 / 删除已摘要记录 | 当前事实与摘要引用一致，不能复活已删除记录 |
| 本轮图片后先调用工具再回答 | 第二步仍能访问正确图片，不按数组末项误清 |
| 历史图片未被重新提供 | 模型不能声称本轮看过原画面 |
| 重启与远程重投递 | 工具调用配对，成功副作用不重复 |
| 未变配置的连续文本 Turn | 没有压缩时输入帧只追加，可复用前缀增长 |
| System / 工具 / 媒体模式发生变化 | 有明确重建原因，接受必要缓存损失 |
| 不支持缓存、缺 usage 的 Provider | 业务行为正确，指标为未知，不报虚假命中 |
| token 超限与大请求体 413 | 分类不同，不盲目压缩或无限重试 |
