# ask_user_questions 实施计划

范围：固定提问工具、逐题按钮、自定义回答、普通发送和确定性操作两条承接路径。用户发送新消息后收起旧提问。

1. 定义受控问题与按钮协议，绑定已有工具并验证完整参数；提问成功即结束本轮，避免无意义模型续跑。
2. 复用现有 Job 的确定性 payload、MutationReceipt、Trace/Event 和结果卡；点击才产生用户消息与写入授权。
3. 提问存于既有工具结果，历史仍有语义；当前 Session 新用户 Turn 使旧按钮失效，防重复和迟到显示。
4. 原生双主题组件，每个选项按钮独占一行，选项下方提供可选输入；普通选项与自由输入按普通消息执行。
5. 本机／Server 协议与停止规则一致，补确定性、恢复、权限与 UI 回归；执行 make check、make verify 和模拟器视觉验收。

不修改已有 kcal 修复。失败保持可重试；不引入新数据库字段、远程数据流或任意代码执行。
