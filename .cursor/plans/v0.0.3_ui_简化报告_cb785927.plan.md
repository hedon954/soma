# v0.0.3 UI 简化报告与实施计划

## 审计结论（TL;DR）

对 `Soma/Views`（约 14,400 行、24 文件）逐屏审计后，"GUI 太重"的根源不是功能太多，而是三个系统性问题：

1. **平铺代替分层**：详情页把"看 / 改 / AI / 媒体 / 历史 / 管理"全部平铺在一屏（动作详情 7 个 Section、训练记录编辑约 12 个固定字段、计划详情 6 大区块）。
2. **低频功能占据主路径**：AI 优化、录像选项、远程执行切换、版本历史等低频能力与核心 CTA 并列。
3. **视觉语言碎片化**：`DesignSystem` 采用率低（Views 里 264 处硬编码 `.font`、圆角出现 13 种数值），带练流自成一套绿色视觉。

**简化总策略：渐进披露。** 默认只读/只显核心，编辑和低频操作显式进入；不删除任何 PRD 授权的能力，只改变入口层级。

## 五大区域的重点发现

### 1. 教练（聊天）— 最大问题：Composer 叠层 + Agent 过程卡

- Composer 可同时纵向叠 4–5 层：动作候选 chip、"上次训练"快填、健身房胶囊、远程执行切换、附件预览。
- **P0**：「本次仅本机/可后台继续」切换下沉到设置默认策略或长按发送菜单（违反"低频开关不占聊天主界面"）。
- **P0**：Skill/Tool 过程卡默认折叠为一条状态，只留最终回复 + 轻量"已记录"；「教练方法」徽章删除（Agent 实现细节）。
- **P0**：Composer 上下文条约定优先级，同时只显示一层。
- P1：空态引导缩短为一句 + 1–2 个示例；重试按钮降权；`LiveAgentResponse` 死代码删除。
- 注意：Session 抽屉目前无可见入口（仅左缘滑动），建议补一个低调入口——这是可用性缺口，不是减负项。

### 2. 训练 — 最大问题：计划详情堆叠 + 带练执行同屏过载 + 处方表单过重

- **P0** 计划详情：训练统计（Chart+5 条历史）、版本历史、AI「优化本次训练」默认折叠/进菜单；「编辑/归档/删除」收入 `⋯` 菜单；首屏只留动作列表 + 开始训练。
- **P0** 带练执行（`GuidedCompactSetView`）：同屏 8 类元素淹没了主 CTA。录制入口和教练提示默认隐藏，跳过收入菜单，进度轨简化为"第 2/4 组"文字。
- **P0** 准备训练 Sheet：录像选项默认折叠（默认关闭），语音提示移到设置（已是 `@AppStorage`）。
- **P1** 处方编辑：默认只暴露组数+次数，重量/间歇/热身收入"更多"；创建计划时隐藏"训练目标/安排提示"；去掉"使用上次"的重复入口。
- P1：Performance 复盘的证据/局限/建议改为默认只读，点编辑再出 TextEditor。

### 3. 进展 — 最大问题：首屏 6 区块 + 训练记录编辑表单

- **P0** 训练记录编辑（`WorkoutRecordEditor`）：默认只展媒体+基本信息+训练数据；「热量估算」（MET/计算时长/推算开关）和「AI 解析」折叠；300pt 肌群图默认收起。
- **P0** 进展首屏：6 区块收敛到 3–4 个。「AI 当前上下文」降为单行/toolbar 入口；「最近 7 天」三指标与趋势卡重复，合并；「最近记录」5 行索引减到 2–3 行；热力图可默认折叠。
- P1：训练历史行内 6 类指标减到主指标一组；年/月/日三级筛选菜单扁平化为"全部+按月"。
- P2：分享 Sheet 同一动作三处入口去重；足迹长文默认 3–4 行折叠。

### 4. 设置 — 最大问题：AI 配置密度 + 说明性文案过重

- **P0** AI 服务页：渐进披露为"平台 → API Key → 模型"三步；Base URL（预置平台自动填）、小模型档、图片生成模型折叠进"高级"；「保存并获取」与「刷新」合并。
- **P0** 服务分组对齐 PRD 004：「任务进度与通知」「后台持续处理」移出"服务"，下沉到"更多"。
- **P1** 身体信息：默认展示性别/身高/参考体重三个核心字段，其余折叠；「热量估算」只读说明节删除或改一行 footnote。
- P1：隐私页只留位置开关+一句 footer；健康页 Keep/COROS 折叠为"其他设备"；远程页数据边界默认折叠。
- P2：高级设置 Skills 8 行收进二级页；「高级设置/开发者设置」文案统一；删除 `SettingsView.swift` 中未挂接的 `gymSection`/`personalSection`/`dataSpaceSection` 死代码。

### 5. 动作库 — 最大问题：详情页 7 Section 平铺 + "进入即编辑"变成满屏输入框

- **P0** 动作详情重构为"只读首屏 + 二级编辑"：首屏 = 示意图一张 + 名称 + 教练提示（折叠）+ 紧凑肌群图 + 最近训练；AI 生成图/说明、上传、外部链接表单、版本恢复、合并/归档全部下沉到菜单或子页。
- P1：肌群图默认单面、高度 ~180（`MuscleMapView` 已有 `showsBothSides`/`height` API，调用方未用紧凑模式）；历史列表只显示最近 3–5 条。
- P2：列表行缩略图与副文案降密度（PRD 010 要求列表有示意图，保留但缩小）。

## 横切项：设计系统收口（P2，随重构顺带做）

- 补充 Form/列表密度规范到 `DesignSystem.swift`（行缩略图尺寸、统一圆角 token、次要操作菜单约定）。
- 重构涉及的文件（`ExerciseViews`、`GuidedWorkout*`、`TrainingProgramEditorViews`）顺带替换硬编码样式为 `AppTheme` token；不做全仓一次性样式大迁移。

## 明确不动的核心能力（红线）

- 聊天发送链路：文本/附件/语音/健身房切换（≥2 时）/附件预览。
- 所有记录的 CRUD 能力（折叠不等于删除，字段仍可编辑）。
- missing-is-nil：不为"表单变简单"加必填或默认值。
- API Key 配置、HealthKit 导入、导出/备份/清除、位置授权、远程明确授权披露。
- 带练状态机行为（确认/休息/暂停/跳过/替换语义不变，只动呈现层级）。
- 高级设置中已正确下沉的演示切换、提示词、Skills、执行日志——不回迁。

## 决议

**全部 P0/P1/P2 改进点已采纳**（2026-08-05），v0.0.3 按下列顺序实施。
