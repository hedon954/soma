# 训练时长误算防护

## 根因

这条「杠铃深蹲 4×8、间歇 90 秒」的正确推算（现有 [`WorkoutCalorieCalculator.estimatedResistanceDuration`](Soma/Services/ConversationRecorder.swift)）是：

`(4×8×4 + 3×90) / 60 ≈ 6.6 分钟`

界面上的 **48 分钟** 正好等于错误公式：

`4 × 8 × 90 / 60 = 48`

即把「间歇秒」当成了「每次动作耗时」。Agent 把该值写进了 `durationMinutes`（实际训练时长）；热量估算又**优先使用实际时长**，于是「计算时长」也被带成 48，看起来整条记录都离谱。

产品规则（[ADR 0006](docs/adr/0006-data-truth-and-derived-metrics.md) / PRD 004）已明确：推算时长只进热量、不回填实际时长。本地推算代码本身是对的；缺的是对 Agent 误写的拦截与对旧数据的纠正。

## 修复

### 1. 识别并丢弃错误时长

在 [`WorkoutCalorieCalculator`](Soma/Services/ConversationRecorder.swift)（或同文件旁的小 helper）增加确定性检测：

- 输入：`durationMinutes`、`sets`、`reps`、`restSeconds`
- 若 `durationMinutes == round(sets * reps * restSeconds / 60)`（且与正确推算明显不符），视为误写，按 **未提供实际时长** 处理

`record_workout` / `update_workout` 写入前：

- `durationMinutes` 命中误写 → 存 `nil`（missing-is-nil）
- 热量改走组次+间歇推算，`calorieDurationEstimated = true`

### 2. 旧记录打开/保存时纠正

在训练详情保存路径（[`RecordDetailViews`](Soma/Views/RecordDetailViews.swift)）与 merge/update 路径：若已存时长命中同一误写模式，清空实际时长并按推算重算热量字段，避免用户只看不改也一直显示 48。

可选：详情页加载时若检测到误写，编辑态自动清空「训练时长」并刷新热量区（不偷偷改磁盘直到用户保存或进入详情时一次性纠正——选用 **打开详情/更新时自动纠正并 save**，因为这是明确脏数据而非用户真实事实）。

### 3. 测试与提示

- 单测：`4/8/90` 推算 ≈ 6.6；`durationMinutes: 48` 被识别为误写并忽略；热量用推算时长。
- 收紧 [`ReActAgent`](Soma/Services/ReActAgent.swift) 热量 Skill 说明：禁止 `组×次×间歇/60`，正确式为 `组×次×4秒 + (组-1)×间歇`。

## 验证

- 相关单元测试通过
- `make check`；有代码变更后 `make verify`
- 手工：打开该深蹲详情，训练时长应为空或合理值，计算时长约 6–7 分钟且标记为推算
