# Soma UI 设计系统

## 层级和 Token

| 角色 | 深色 | 浅色 | 用途 |
| --- | --- | --- | --- |
| page | `#000000` | `#FFFFFF` | 页面、安全区、导航、TabBar |
| card | `#191919` | `#F7F7F7` | 分组卡和主要信息卡 |
| inset | `#232323` | `#EFEFEF` | 卡内逻辑组、输入、用户消息 |
| separator | `#303030` | `#DCDCDC` | 0.5 pt 分隔线与低对比边界 |
| accent | `#FFFFFF` | `#000000` | 导航、选择、主操作 |
| on accent | `#000000` | `#FFFFFF` | 主控件反色前景 |
| training category / load | `#FF922B` | `#C65000` | 训练类别图标、容量与负荷 |
| meal / success | `#24D77A` | `#00854A` | 饮食图标与明确成功 |
| body | `#66B8F0` | `#0072C6` | 身体数据图标 |
| trend | `#B58CFF` | `#753DB8` | 趋势图标 |
| consistency | `#31C9D1` | `#00838B` | 训练频率与连续性 |
| recovery | `#6FD47A` | `#27803B` | 恢复指标与积极状态 |
| vital | `#FF6B5B` | `#B43F34` | 心率等生命体征与明确异常 |
| warning | `#F2C94C` | `#835A00` | 提醒与可恢复风险 |
| destructive | system red | system red | 删除和失败 |

业务 View 只使用 `AppTheme` 语义成员，不重新硬编码色值或用任意 opacity 混出近似表面。

## 色彩规则

- 黑白承担主视觉。普通导航、主按钮、标题和卡片不使用彩色品牌色。
- 一张普通信息卡默认最多出现一种非中性色，优先只落在小图标、轨迹、进度或状态点。
- 暗色用户消息使用 inset 灰色气泡，不能重复铺白色大块。
- 浅色纯白只用于页面；列表和设置分组必须使用浅灰 card，并以组间距保持可辨识层级。
- 正常字号文字对承载表面至少 4.5:1；图标和边界至少 3:1。
- 浅色语义色适度提高明度与饱和度，抵消纯白背景的灰雾感，同时继续满足 4.5:1；暗色语义色固定不随浅色
  校准改变。
- 浅色语义图标保持清晰实色，不使用阴影、柔光或模糊；暗色语义色固定不变。
- 训练、饮食、身体、趋势、提醒、成功和破坏性状态保持独立语义。
- 业务类别图标使用对应语义色和必要的柔和语义底，不能因为主交互为黑白就统一染黑。
- 业务入口统一使用 `AppSemanticRole` 与 `SemanticIconBadge`；同一列表中的训练、饮食、身体、趋势
  图标必须一眼可分，不允许用一排黑色 SF Symbol 代替语义层级。
- 颜色分三层：`AppSemanticRole` 表示记录类别，`AppMetricRole` 表示测量指标，`AppStatusRole`
  只表示具有确定阈值的状态。指标色优先于所属记录类别，因此训练不自动等于橙色。
- 图表的数据线、点、柱、面积和热力格跟随指标语义：频率/连续性使用 consistency，容量/负荷使用
  trainingLoad，恢复使用 recovery，表现使用 performance，身体测量使用 body，生命体征使用 vital。
  坐标轴、网格和分隔线保持中性，数据标记不得回退到黑白 `accent`。
- 同一曲线只有在阈值、区间或异常点具有确定业务含义时才使用状态色分段；不得为了视觉丰富而使用
  彩虹线。标题图标必须与指标含义直接对应，不能用同一个泛化训练图标覆盖所有指标。
- 所有肌群受力图的有效区域使用 training：主要/高强度使用接近实色的训练橙，辅助/低强度使用
  约半透明训练橙；未映射区域保持中性灰，标签与引导线跟随训练橙，不使用 accent 黑白着色。

## 尺寸

- 页面左右 16 pt。
- 独立区块 20 pt，同组卡 12 pt，卡内 20 pt，紧凑编辑卡可用 14 pt。
- 设置分组间距 18 pt；根分区标题与卡片外沿对齐。
- 主卡圆角 18 pt；输入、内嵌块和控件 12 pt。
- 反馈等大输入表面使用 inset 背景和 1 pt separator 边界，纯白浅色下不能只靠阴影辨认。
- 可见按钮允许紧凑，但点击目标最小 44×44 pt。
- 历史缩略图约 48×54 pt，使用真实媒体和 aspect-fill。
- 深色靠色阶和细线分层；浅色靠表面色阶和分隔线分层，不能用厚边框、阴影或模糊光效。

## 字体

- Tab 根标题使用 inline navigation title，居中，不用 large title。
- 聊天正文与用户消息：Dynamic Type Subheadline Light。
- 普通列表正文：Subheadline Regular。
- 章节标题和显式强调：Headline 或 Title3 Medium。
- 时间、位置与说明：Caption/secondary。
- 数值：monospaced digits。
- 强调只比 Light 正文提高到 Medium；不要使用大面积 Bold/Semibold 或连续粗体制造层级。
- 不用固定高度截断中文正文、错误恢复或可编辑内容。

## 聊天与导航

- 未选中根 Tab 使用 outline SF Symbol；选中项可使用 fill 版本和中性系统选中底。
- Composer 只保留加号、文本、麦克风和发送；不显示独立相机按钮。
- 三个 Skill 快捷按钮使用紧凑边框/浅灰胶囊，44 pt 触达。
- 每条消息显示日期与时间；跨年再显示年份。
- AI 回复只由 `CoachResponseView` 呈现受控 Markdown：标题、段落、分隔线和列表。
- AI 回复不设置重复头像或装饰列，正文从消息区左边界开始。

## 组件选择

- 主信息使用 `AppCard`；卡内数据使用 `AppTheme.insetBackground`。
- 分组设置和历史列表优先保留 Form/List 原生行为，再映射 card、separator 和 spacing。
- 图标使用 SF Symbols 或仓库真实素材；不使用 emoji、文本符号、手绘 SVG 或截图替代控件。
- 设计稿只用于文档与视觉 QA，不作为运行时贴图。
